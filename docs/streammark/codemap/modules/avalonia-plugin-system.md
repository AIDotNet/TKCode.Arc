# Avalonia 插件体系与服务解析

`IMarkdownPlugin` 在 `Configure(MarkdownPluginBuilder)` 里一次性登记语法（白名单组件、Markdig 扩展、映射）、渲染（块组件视图 / 行内组件 / 围栏视图 / 公式 / 高亮 / 图表）与交互（代码块头部操作）；宿主把插件塞进 `MarkdownServices`，附加属性 `MarkdownServices.ServicesProperty` 把这份服务集合下发给整棵可视子树，首次访问时汇总成不可变的 `PluginRegistry`，注册表同时给出文档解析要用的 `Profile`。

**不负责：** 白名单标签的实际解析与 `ComponentSpec` 白名单表 / `MarkdigMapper` 的节点映射（`core-parsing-and-model`，`src/TKCode.Arc.StreamMark/Core/Parsing/MarkdownProfile.cs:MarkdownProfileBuilder.AddComponent`、`src/TKCode.Arc.StreamMark/Core/Parsing/HtmlComponentExtension.cs`）；块视图基类、`BlockViewFactory` 的分派分支与 `RenderContext` 的语义（`avalonia-text-rendering`，`src/TKCode.Arc.StreamMark/Avalonia/Rendering/BlockViewFactory.cs:Create`）；RaTeX / TextMate / Mermaid 三个具体实现（`avalonia-extensions`，`src/TKCode.Arc.StreamMark.RaTeX/RaTeXPlugin.cs`）；`Md.*` 主题资源与样式快照（`theme-and-styles`、`src/TKCode.Arc.StreamMark/Avalonia/Rendering/MarkdownStyle.cs`）；图片取数 / 解码 / 缓存（`avalonia-images`，`src/TKCode.Arc.StreamMark/Avalonia/Images/ImagePipeline.cs`，这里只持有 `MarkdownServices.Images` 引用）。

## State it owns
- `MarkdownServices._registry`（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/MarkdownServices.cs:17`）：`Registry => _registry ??= new PluginRegistry(this)`（:78）。注册表**只构建一次**，之后插件列表、`Math`、`Highlighter`、`Diagrams` 的任何后续改动都不生效（`MarkdownServices` 的属性都是 `init`，正确做法是换一个新实例）。首次访问的时机决定一切：`MarkdownView.CreateContext`（`src/TKCode.Arc.StreamMark/Avalonia/MarkdownView.cs:170`）与 `MarkdownView.OnSourceChanged` 里的 `GetServices(this).Profile`（:105）都会顺手把注册表建出来。
- `PluginRegistry`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:13`）：`_blockComponents` / `_inlineComponents` / `_fenceViews` 是构造期从 builder 接过来的字典（builder 随后被丢弃），`Diagrams` / `BlockActions` 是 `ImmutableArray`，`Profile` 是 `builder.Profile.Build()` 的产物（:32）。因此注册**只发生在构造阶段**，运行期没有任何增删入口；视图层拿到的是同一批工厂委托与同一个 `MarkdownProfile` 实例（`ReferenceEquals(fence, oldFence)` 就是靠这个身份判断复用，`src/TKCode.Arc.StreamMark/Avalonia/Rendering/BlockViewFactory.cs:51`）。
- `MarkdownServices.Default`（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/MarkdownServices.cs:15`）是附加属性的默认值，即进程级单例：没设 `Services` 的所有视图共用它（以及它的首次访问即固化的注册表）；`ImagePipeline` 同理有 `s_defaultImages`（:31、:40）。
- `BlockStateStore` 的作用域是**每个文档视图一份**，不是每块一份：`MarkdownView._state`（`src/TKCode.Arc.StreamMark/Avalonia/MarkdownView.cs:36`，输入属性变化时 `_state.Clear()`，:115）、`TranscriptPanel.EntryState.State`（`src/TKCode.Arc.StreamMark/Avalonia/Transcript/TranscriptPanel.cs:39`）。`RenderContext` 收下它，缺省时自建一个空实例（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/RenderContext.cs:17`），并在 `With` / `WithHtml` 中透传（:53、:61）。
- 键是 `(顶层块 key, 状态名)`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/BlockStateStore.cs:10`）：key 是块在原始源码中的起始偏移，源码只追加因此跨重解析稳定；状态名是字符串，已存在的有 `code.wrap`（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/CodeBlockView.cs:26`）、`code.state`（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/CodeBlockState.cs:52`）、`diagram.code`（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/DiagramBlockView.cs:43`）、`"collapsible.open:" + 组件名`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/BuiltInComponentsPlugin.cs:62`）。约定只在界面线程访问（`BlockStateStore.cs:6`）。

## Contracts it exposes
- **`IMarkdownPlugin`**：`Name`（仅标识，注册表内不去重、不按名查找）+ `Configure(MarkdownPluginBuilder)`；`Configure` 在构造 `PluginRegistry` 时被同步调用一次，只允许**登记委托与工厂**，不要在里面做 IO 或反射（NativeAOT，`docs/streammark/architecture.md:57`）。
- **`MarkdownPluginBuilder` 各方法的语义**：`AddBlockComponent(name, factory, registerTag)` 把 `name` 映射为块视图工厂，默认同时把标签加进白名单（同名重复登记直接覆盖，`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:68`）；工厂只负责 **new**，内容一律通过 `BlockView.Update` 下发，同名组件的新模型复用同一视图；`AddInlineComponent(name, renderer, kind, registerTag)` 默认按自闭合组件登记；`AddFenceView(language, factory, whileStreaming)` 按 `CodeBlock.Language` 精确匹配（大小写不敏感）；`AddBlockAction(descriptor)` 是追加列表，无去重。
- **`IInlineComponentRenderer`** 的四个方法都带默认实现，插件按需覆写：`CreateRun`（自闭合组件 → `DrawableTextRun`，`null` 表示不显示）、`GetStyle`（成对组件内部文字的 `InlineComponentStyle`，`null` 表示继承）、`ToPlainText`（复制到剪贴板时替代文本）、`IsClickable`（决定悬停手型与 `TextSegmentView.ComponentClickedEvent`，`src/TKCode.Arc.StreamMark/Avalonia/Rendering/TextSegmentView.cs:566`、`:576`）。
- **`IMathRenderer` / `ISyntaxHighlighter` / `IDiagramRenderer`**：分别经 `UseMath` / `UseHighlighter` / `AddDiagramRenderer` 登记。`Layout` 必须线程安全（渲染层可能后台预排版）、失败返回 `null` 并给出 error（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/IMathRenderer.cs:7`）；`ISyntaxHighlighter` 来自 Core，按语言 `CreateSession` + `GetThemeColors`（`src/TKCode.Arc.StreamMark/Core/Highlighting/ISyntaxHighlighter.cs:30`）；`IDiagramRenderer.CanRender` 按语言认领、`RenderAsync` 可在后台线程跑、失败回退源码（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/IDiagramRenderer.cs:10`）。
- **`MarkdownServices.ServicesProperty`**：`inherits: true`，设置在窗口 / 会话视图 / 任意祖先上；`MarkdownView` 与 `TranscriptPanel` 都在静态构造里挂了 `Changed` 处理器，只做“作废当前 `RenderContext` 并请求下一帧”（`src/TKCode.Arc.StreamMark/Avalonia/MarkdownView.cs:44`、`src/TKCode.Arc.StreamMark/Avalonia/Transcript/TranscriptPanel.cs:95`）。
- **`Profile` 的用法约定**：文档要用服务的方言创建。推荐 `services.CreateDocument()` / `CreateStream(...)` / `CreateEntry(text)` / `CreateDeferredEntry(text)`（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/MarkdownServices.cs:CreateDocument` 等），手动写法是把 `services.Profile` 传给 `new StreamingDocument(...)`（`null` 即回落 `MarkdownProfile.Default`）、`new MarkdownStream(profile: ...)`、`MarkdownEntry.FromText(text, profile)`。`MarkdownView.Markdown` 的自建文档由控件用当前服务的方言创建，服务变化时 `MarkdownView.OnServicesChanged` 按新方言重建（`DocumentId` 不变，视图 / 块状态 / 选区重建）。插件都不改语法时 `Profile` 就是 `MarkdownProfile.Default`（`MarkdownProfileBuilder.Build` 的 `IsUnchanged` 分支），所以方言可以按引用比较：宿主自己的文档方言不同时，`MarkdownServices.CheckProfile` 在视图新建渲染上下文时（`MarkdownView.CreateContext`、`TranscriptPanel.ContextFor`）每个文档报告一次 `PluginDiagnosticKind.ProfileMismatch`（`Diagnostic` 事件 + `Trace.TraceWarning`）。
- **兼容写法**：`Math` / `Highlighter` / `Diagrams` 三个属性等价于“注册一个只提供该能力的插件”，`PluginRegistry` 构造里 `Math = builder.Math ?? services.Math`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:25`）；`Diagrams` 则是 `[.. services.Diagrams, .. builder.Diagrams]`（:27），两者的优先级方向相反。

## How to extend
- **To add 一个插件**：① 实现 `IMarkdownPlugin`，在 `Configure` 里一次性登记（参照 `RaTeXPlugin`，`src/TKCode.Arc.StreamMark.RaTeX/RaTeXPlugin.cs:6`）；② 挂进 `new MarkdownServices { Plugins = [new MyPlugin(), ...] }` 并经 `MarkdownServices.SetServices(viewOrAncestor, services)` 下发（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/MarkdownServices.cs:85`）；③ 用 `services.Profile` 创建文档——`MarkdownEntry.FromText(text, services.Profile)` / `new StreamingDocument(services.Profile)` / `new MarkdownStream(profile: services.Profile)`（`tools/streammark/Gallery/Program.cs:85`、`:89`）。漏掉 ③ 的症状：插件注册的组件标签根本不会被解析（`Profile` 变了但文档用的是 `MarkdownProfile.Default`），标签按普通 HTML / 文本落到 `HtmlBlock` / 段落里，`TryGetBlockComponent` 永远不会被调用（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:35` 的注释即为此）。
- **To add 行内 / 块级组件视图**：① 实现 `IInlineComponentRenderer`（只覆写需要的方法）或提供一个 `Func<ComponentBlock, BlockView>` 工厂；② `builder.AddInlineComponent(name, renderer, kind)` / `builder.AddBlockComponent(name, factory)`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:66`、`:77`）；自定义视图类继承 `StackBlockView` 或 `BlockView` 并在 `OnUpdate` 里**按阅读顺序**消耗片段号（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/BlockView.cs:43`）；③ 若视图要在回收后保留状态，把状态写进 `context.State`（键用 `(TopKey, 状态名)`，参照 `CollapsibleBlockView.OnUpdate` 的 `context.State.Get(topKey, StateName, defaultOpen)`，`src/TKCode.Arc.StreamMark/Avalonia/Plugins/BuiltInComponentsPlugin.cs:81`）。漏掉 ③ 的症状：视图被虚拟化回收后展开 / 换行 / 图表视图选择全部回到默认值。
- **To add 代码围栏视图与块操作**：① `builder.AddFenceView("diff", code => new DiffView(), whileStreaming: false)`，视图需自己消费片段号（`segment++`）并实现 `MeasureOverride`（测试替身见 `tests/TKCode.Arc.StreamMark.Tests/Avalonia/Plugins/PluginSystemTests.cs:78`）；② 头部按钮用 `builder.AddBlockAction(new BlockActionDescriptor(id, label, MarkdownIcons.X, block => block is CodeBlock { Language: "cs" }, ctx => Task.CompletedTask))`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:127`）；③ 需要围栏信息串（路径 / 行号）时在 `Execute` 里用 `Plugins.CodeFenceInfo.Parse`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:140`）。漏掉 ② 的症状：`AppliesTo` 恒为 false 时按钮不出现（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/CodeBlockView.cs:131`），而操作列表在**每次上下文变化时整体重建**（`UpdateActions`，:122），漏掉 `AppliesTo` 的过滤条件会让操作出现在所有代码块 / 表格上。

## Invariants and traps
- **块操作按目标分组** — `BlockActionDescriptor.Targets`（`Code` 默认 / `Table` / `Diagram`）在构建时分组，视图经 `PluginRegistry.ActionsFor(target)` 只拿自己那一组；按钮由 `Rendering/BlockActionBar.cs` 统一建拆，`CodeBlockView` / `DiagramBlockView` 在上下文变化或信息串变化时、`TableBlockView` 在上下文变化或首次更新时重建（表格的按钮随悬停显示，并与复制 / 全屏一起保持在单元格之上）。该类没有操作时 `Rebuild` 直接返回。
- **组件登记与 `WhileStreaming`** — 注册表把每个块组件存成 `BlockComponentRegistration(Factory, Text, WhileStreaming)`；`PluginRegistry.FindBlockComponent(component)` 在 `component.IsOpen && !WhileStreaming` 时返回 null（显示为 `ComponentContainerView`），`BlockViewFactory.Create` / `CanReuse`（比较新旧模型的登记是否同一个，闭合那一刻换视图）与 `BlockText`（`FindComponentText(component)`）都按它判断，保证视图与复制文本的片段一致。
- **组件复制文本** — `AddBlockComponent(name, factory, ComponentTextCollector text)` 登记的收集器存进 `PluginRegistry.FindComponentText`，`BlockText.Segments(block, registry)` 遇到该组件时改用它（`ComponentTextContext.AddText` / `AddInline` / `AddBlocks`）；同名 `AddBlockComponent` 是整体覆盖，不带文本时前一个登记者的收集器也随之失效。查找表是 `FrozenDictionary`（构建一次，热路径只读）。
- **注册只构建一次，失败也只失败一次** — `MarkdownServices.Registry` 在锁内构建（任意线程得到同一实例，保证 `Profile` 能按引用比较）；`PluginRegistry` 构造把每个 `Configure` 的异常包成 `PluginConfigurationException(PluginName)`，`MarkdownServices` 缓存这个异常，之后每次访问重新抛出同一个、不再重跑插件。
- **覆盖有记录** — `MarkdownPluginBuilder.Claim` 按 `math` / `highlighter` / `block:名` / `inline:名` / `fence:语言` 记下登记者（`IMarkdownPlugin.Name`），被后来者覆盖时写入 `PluginRegistry.Diagnostics`（`PluginDiagnosticKind.Replaced`）；兼容属性 `Math` / `Highlighter` 被插件覆盖同样记录。经 `builder.Profile` 直接改的语法层不记录。图表优先级（兼容写法在前）未改。
- **同名组件后登记者覆盖先登记者** — builder 用普通字典赋值（`BlockComponents[name] = factory`，`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:68`），内置插件排在最前（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:20`），所以宿主插件覆盖内置是**设计内行为**；`Profile.AddComponent` 同样是先 `RemoveAll` 同名再追加（`src/TKCode.Arc.StreamMark/Core/Parsing/MarkdownProfile.cs:79`），两处必须同时覆盖，否则出现“解析成组件但视图还是内置的”或反之。
- **内置组件总是启用且无法关闭** — `IEnumerable<IMarkdownPlugin> plugins = [BuiltInComponentsPlugin.Instance, .. services.Plugins]` 是硬编码拼接（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:20`），`details` / `think` / `citation` / `cite` 四个视图必然存在（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/BuiltInComponentsPlugin.cs:26`，均以 `registerTag: false` 登记，白名单标签来自 `ComponentSpec.BuiltIn`，`src/TKCode.Arc.StreamMark/Core/Parsing/ComponentSpec.cs:20`）；未注册视图的 `ComponentBlock` 回落到 `ComponentContainerView` 而不是报错（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/BlockViewFactory.cs:13`）。
- **插件注册只用委托与工厂，不用反射** — `MarkdownPluginBuilder` 的字段全是 `Func<...>` / `IInlineComponentRenderer` / 记录类型（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/IMarkdownPlugin.cs:35-41`），Core 侧 `MapBlock<T>` / `MapInline<T>` 也只做 `is TNode` 判定后调委托（`src/TKCode.Arc.StreamMark/Core/Parsing/MarkdownProfile.cs:87`）；库项目一律 `IsAotCompatible=true` 且裁剪警告视为错误（`docs/streammark/architecture.md:57`），所以插件里不要引入反射式注册 / 动态类型扫描。
- **注册表不可变，改动只在注册阶段** — 运行期没有任何 API 能往注册表里加东西；`Registry` 一旦被首次访问就固定（`src/TKCode.Arc.StreamMark/Avalonia/Extensions/MarkdownServices.cs:78`），此后修改 `Plugins` 列表内容不会生效（属性本身也是 `init`）。想在运行期换插件只能换一个新的 `MarkdownServices` 实例并重新 `SetServices`。
- **`MarkdownServices` 变化只重建自建文档** — `MarkdownView` 的 `Changed` 处理器是 `OnServicesChanged`：只有文本来自 `Markdown`（`_ownDocument` 非空）且新服务的 `Profile` 与文档的不是同一个实例时才重建并重新解析，然后作废上下文；`Document` / `Stream` 是宿主的，只报告不重建。`TranscriptPanel` 的条目全归宿主，同样只报告。
- **兼容属性排在所有插件之前，插件优先** — 公式与高亮是 `builder.Math ?? services.Math`，图表是 `Diagrams = [.. builder.Diagrams, .. services.Diagrams]` 且 `FindDiagramRenderer` 取第一个命中者（2026-11-08 起与公式 / 高亮同向；此前兼容写法的图表排在前面）。插件之间：组件 / 围栏视图 / 公式 / 高亮是后登记者覆盖，图表按登记顺序先命中者生效（`CanRender` 是谓词，无法判定重名）。
- **围栏视图默认只在代码块闭合后替换** — `FindFenceView` 要求 `!code.IsOpen || registration.WhileStreaming`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/PluginRegistry.cs:63`），流式中途是普通 `CodeBlockView`，闭合后 `DocumentPresenter.Restyle`（`src/TKCode.Arc.StreamMark/Avalonia/Rendering/DocumentPresenter.cs:83`）才会换成插件视图；`CanReuse` 用 `ReferenceEquals(fence, oldFence)` 判定，因此同语言注册被替换（新注册表）时旧视图会被换掉，而围栏视图与 `CodeBlockView` 之间来回切换也会导致视图重建。
- **`AddBlockComponent(registerTag: true)` 会与 Core 的内置标签表合并**，`ComponentTable` 用 `OrdinalIgnoreCase` 查找、`BlockNames` 取小写（`src/TKCode.Arc.StreamMark/Core/Parsing/ComponentSpec.cs:50`、`:58`），而 `MarkdigMapper` 把块级组件名统一 `ToLowerInvariant()` 后放进模型（`src/TKCode.Arc.StreamMark/Core/Parsing/MarkdigMapper.cs:188`）——注册 `"Callout"` 与注册 `"callout"` 等价，视图工厂字典同样是 `OrdinalIgnoreCase`。
- **`BlockStateStore` 只在界面线程访问、且随文档生命周期清空** — `MarkdownView.OnSourceChanged` 里 `_state.Clear()`（`src/TKCode.Arc.StreamMark/Avalonia/MarkdownView.cs:115`），因此换文档 / 重设 `Markdown` 会把折叠、换行、图表选择全部重置；`BlockStateStore.Set` 要求 `T : notnull`（`src/TKCode.Arc.StreamMark/Avalonia/Plugins/BlockStateStore.cs:15`），存可空类型（如 `CodeBlockState?`）会静默不写入。
