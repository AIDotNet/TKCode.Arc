## 何时使用

`DonutChart` 展示一个整体如何划分为几个部分。环形让人一眼看出划分的形态，旁边的图例给出每个部分的数值和占比，中心则显示总计，或指针所指部分的数值。它适合放在仪表板的卡片或面板中，此时问题是“这个数字由什么构成”，答案通常为两到六个部分。

- **营销概览中的访问来源**：Acme Analytics 显示本周 48,200 次访问来自哪些渠道（搜索、直接访问、社交、邮件）。图例让每个来源都清晰可读，较小的来源则合并到“其他”中，而不是变成细小的碎片。
- **财务页面中按类别统计的支出**：财务人员把本月支出按薪资、云主机、营销和软件来审阅。在图例中固定某个类别后，中心会保留它的数值，而财务人员仍可查看表格。
- **管理控制台中的存储用量**：工作区所有者查看哪些项目占用的存储最多。占比低于百分之几的部分会合并到“其他”，所有者也可以隐藏某个项目，看看其余部分的环如何变化。
- **支持仪表板中的工单状态分布**：待处理、等待中和已解决工单的占比，通过切换数据集在本月与本季度之间切换。扇区会移动到新位置，而不是重新绘制整个环。

## 何时不用

- **部分很多，或需要精确比较各部分**：使用 `BarChart`。十二个扇区很难比较，人眼读取长度比读取角度更准确。
- **单个数值与已知上限对比**：使用 `Gauge`，它以阈值显示某个读数在范围中的位置；若要表现人们关注其填充进度的配额，则使用 `UsageMeter`。
- **随时间的变化**：使用 `LineChart`。环形只表示某一时刻，把趋势画成一系列环会掩盖先后顺序。
- **以人数或网格格子计数的占比，例如席位或网格单元**：使用 `WaffleChart`，它每个百分点显示一格，读起来就是计数。
- **需要下钻的嵌套部分**：使用 `Treemap`，它保留层级结构，并按数值决定矩形大小。

## 用法

每个 `ChartPoint` 对应一个扇区。为每个数据点设置稳定的 `Key`，这样数据变化时扇区才能保持各自的身份。数值为零或负数的数据会被忽略。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AtomUICommunity/TKCode.Arc">
    <arc:DonutChart Label="按来源统计访问量"
                    Unit="次访问"
                    TotalLabel="总计"
                    OtherLabel="其他"
                    ItemsSource="{Binding Sources}" />
</UserControl>
```

`DonutChart` 派生自 Arc 图表家族的基类 `ChartBase`，因此 `Label`、`Unit`、`ValueFormat`、`EmptyLabel` 和 `ItemsSource` 的行为与其他图表一致。环形图额外提供环、同步的图例、中心读数以及分组规则。由于环是自绘的，每个弧形都是一个绘图对象，数据集变化时只是移动已有的弧形，而不是重新创建控件。

### 结构

1. **环**：各个弧形，相邻弧形之间留有 3 px 的间隙，四角为 4 px 圆角。环默认直径 208 px（`Diameter`），厚度 24 px（`RingThickness`）。在较窄的容器中，它会等比缩小以适应。
2. **中心读数**：环中央的三行短文字。静止时，顶行是总计标签（`TotalLabel`），中间一行是总计数值，底行是单位。指针悬停或固定某个扇区时，这几行改为显示该扇区的标签、数值以及它占总计的比例，例如“占总计的 60%”。标签行和单位行的高度固定（12 px 文字，行高 1.4），因此数值变化时不会移动。
3. **图例行**：每个可见扇区占一行，包括颜色色块、标签、数值和占比。当容器宽度至少为 460 px 时，图例位于环的旁边；否则位于环的下方。
4. **“其他”扇区**：合并的小部分。该行列出它包含的部分，其提示和播报也会列出这些部分。
5. **焦点环**：仅在键盘焦点时绘制，围绕图例行；若没有图例，则围绕环本身。

扇区颜色来自系列调色板，并在某个键第一次出现时按键分配，因此数据集变化时，某个类别会保留它的颜色。占比文字使用整数百分比；大于零但小于 1% 的占比显示为“<1%”。

### 尺寸与分组

`Diameter` 和 `RingThickness` 决定环的尺寸。占比低于 `GroupBelow`（占总量的比例，默认 0.04）的部分，以及超出 `MaxSegments`（默认 6，包含“其他”）的部分，会合并到“其他”扇区中。分组至少需要两个部分才会发生：单个小部分会保留在自身的扇区中，因为把单个部分合并进去只会让它无故隐藏。

```xml
<arc:DonutChart Label="存储空间"
                Diameter="160"
                RingThickness="18"
                GroupBelow="0.05"
                MaxSegments="5"
                ItemsSource="{Binding Storage}" />
```

在仪表板卡片中，小扇区只会增加噪音，此时应使用较大的 `GroupBelow`；在财务页面中，每个类别都必须可见，则应使用较小的值。只有在图例有空间时才提高 `MaxSegments`：每多一行，都会在环的旁边或下方多占一行的高度。

### 数据集

替换 `ItemsSource` 即可切换数据集。扇区保持原有顺序，并从当前角度移动到新的角度，因此扇区不会被重新挂载。新键的扇区会出现在它在顺序中的位置；离开的扇区会先收缩为零，然后移除。

```csharp
month.Click += (_, _) => chart.ItemsSource = s_month;
quarter.Click += (_, _) => chart.ItemsSource = s_quarter;
```

在各个数据集之间保持键不变（两个月份中都使用 `"search"`，而不是一个月用 `"Search"`、另一个月用 `"search-ads"`）。键变化后就是另一个扇区：它会失去颜色记录和隐藏状态。

### 图例与隐藏部分

图例默认可以隐藏和显示扇区。若只需要环本身，设置 `ShowLegend="False"`。`HiddenKeys` 列出被隐藏的键，且为双向绑定，因此视图模型可以保存它。被隐藏的扇区会收起，其余部分在环上重新分配，中心的总计只统计可见的扇区。最后一个可见扇区不能被隐藏，因此环不会意外变空。

<Demo name="RingOnly" />

```xml
<arc:DonutChart Label="按来源统计访问量"
                HiddenKeys="{Binding HiddenKeys}"
                ShowLegend="True"
                ItemsSource="{Binding Sources}" />
```

没有图例的环是一个独立的键盘停驻点：方向键依次朗读每个扇区。当空间紧张，且环本身已经表达了含义时使用它，例如卡片中旁边配有说明文字的存储量仪表。

### 固定扇区

设置 `LegendAction="Select"` 可固定扇区，而不是隐藏它。`ActiveKey` 保存被固定的键，且为双向绑定。无论哪种模式，点击环上的扇区也会将其固定。被固定的扇区会一直显示在中心读数中，直到它被取消固定，或另一个扇区被固定。`ActiveKeyChanged` 会在固定状态变化时触发，视图模型可以在其处理程序中读取 `ActiveKey`，也可以直接绑定它。

<Demo name="Select" />

```xml
<arc:DonutChart Label="按类别统计支出"
                LegendAction="Select"
                ValueFormat="$#,##0"
                ActiveKey="{Binding PinnedCategory}"
                ItemsSource="{Binding Spend}" />
```

### 绑定到视图模型

视图模型拥有数据、隐藏的键以及被固定的类别。图表负责显示它们，并把读者的选择写回。使用 CommunityToolkit.Mvvm 时：

```csharp
public partial class SpendViewModel : ObservableObject
{
    private static readonly IReadOnlyList<ChartPoint> s_october =
    [
        new ChartPoint("薪资", 9800) { Key = "salaries" },
        new ChartPoint("云主机", 4120) { Key = "cloud" },
        new ChartPoint("营销", 2250) { Key = "marketing" },
        new ChartPoint("软件", 1350) { Key = "software" },
        new ChartPoint("办公", 640) { Key = "office" },
        new ChartPoint("差旅", 380) { Key = "travel" }
    ];

    [ObservableProperty]
    private IReadOnlyList<ChartPoint> _spend = s_october;

    [ObservableProperty]
    private IReadOnlyList<string> _hiddenKeys = [];

    [ObservableProperty]
    private string? _pinnedCategory;
}
```

```xml
<arc:DonutChart Label="按类别统计支出"
                ItemsSource="{Binding Spend}"
                HiddenKeys="{Binding HiddenKeys}"
                ActiveKey="{Binding PinnedCategory}"
                LegendAction="Select"
                ValueFormat="$#,##0" />
```

- `HiddenKeys` 与 `ActiveKey` 都是双向的。图例的切换会把新列表写回，因此视图模型能看到每一次变化，包括用键盘做出的变化。
- 应替换 `HiddenKeys` 列表，而不是原地编辑它，因为图表会响应属性赋值。
- 重新加载时替换 `ItemsSource`。保持键稳定，这样扇区会移动而不是重新创建。
- `ValueFormat`（`$#,##0`）作用于图例、中心和播报。应在图表上一次设置，而不是在视图模型中格式化字符串。

### 示例：账单页上按类别统计的支出

财务人员打开本月的支出，在阅读下方表格之前先看出钱花在了哪里。环显示其构成，图例列出每个类别及其数值和占比，“其他”一行把两个小类别合并在一起，使它们不会挤占环的空间。办公与差旅合计仍低于 4% 的阈值，因此合并进“其他”，图例中该行会同时列出这两个类别。视图模型固定了云主机扇区（将 `PinnedCategory` 设为 `"cloud"`），因此中心显示的是它的数值和占比，而不是总计。图表宽 620 px，因此图例位于环的旁边，而不是下方。上面的视图模型提供了数据点，因此本页没有截图：仅靠标记，图表什么也画不出来。

```xml
<StackPanel Width="620" Spacing="16">
    <TextBlock Text="按类别统计支出，2026 年 10 月"
               FontSize="16"
               FontWeight="Medium"
               Foreground="{arc:ArcDesignTokenResource Foreground}" />
    <arc:DonutChart Label="按类别统计支出"
                    ValueFormat="$#,##0"
                    LegendAction="Select"
                    ActiveKey="{Binding PinnedCategory}"
                    ItemsSource="{Binding Spend}" />
</StackPanel>
```

### 文案规范

每个扇区都用它所代表的事物来命名，并由图表标题说明整体是什么。图例和中心读数会朗读扇区标签，因此简短的名词短语比完整句子更合适。

| 不要写 | 改为 |
|---|---|
| Visits | Visits by source |
| Other stuff | Other（图例行会列出其成员） |
| Search engines and paid ads | Search |
| 0.4% | <1%（图表对小占比会这样显示） |
| 48200 visits | 48,200 visits（`ValueFormat="N0"`） |
| Click a slice to see details | Click a segment to pin it |

`TotalLabel` 应保持为单个词，例如 Total、Visits 或 Spend，因为它是静止时中心那一行的标签。标签使用句首大写；读者需要的单位，例如 "visits" 或 "USD"，应写在 `Unit` 中，而不要在每个标签里重复。

### 最佳实践

**推荐**

- 使用两到六个扇区。每增加一个扇区，读者需要区分的弧形就更窄，而图例是比较它们的可靠方式。
- 为每个数据点设置不依赖标签的稳定 `Key`。如果重命名会改变键，扇区就会获得新颜色，并丢失隐藏状态。
- 在财务或运营页面上保持图例开启。图例是键盘操作的路径，也是唯一显示每个数值和占比的地方。
- 有意识地设置 `GroupBelow` 和 `MaxSegments`，使“其他”只包含小到无法辨认的部分。
- 通过 `ActiveKey` 固定页面所关注的扇区，使中心回答页面提出的问题。

**避免**

- 用环表示很长的列表，或用于精确比较。读者需要对各部分排序时，应使用 `BarChart`。
- 合计没有实际意义的数据，例如彼此重叠的类别。同一部分被计入两处，会使占比失真，总计也失去意义。
- 仅靠在视图模型中隐藏扇区来显示子集。如果被隐藏的部分根本不应计入总计，应改为在视图模型中过滤数据。
- 在狭窄的图例中使用过长的标签。标签会被省略号截断，完整名称则保留在提示和播报中。
- 在数据集之间更改键。这样扇区会先收起再重新展开，而不是移动到新的大小。

### 常见问题

**为什么环上缺少一个小扇区？** 它的占比低于 `GroupBelow`（默认 4%），或排名超出了 `MaxSegments`，因此被合并进了“其他”。将指针悬停在“其他”行上，或在图例中读取其名称，即可看到它的成员。单个小部分永远不会被合并进“其他”，因此既缺失又不在“其他”中的部分，其值必定为零或负数。

**固定某个扇区时，能否让总计一直显示在屏幕上？** 不能。中心会显示被固定的扇区、它的数值和占比，而不是总计。如果页面必须同时显示两者，应把总计以你自己的文字放在图表旁边，并绑定到你从视图模型中读取的同一个 `Total` 值。

**总计是否包含被隐藏的扇区？** 不包含。`Total` 只累加可见的扇区，因此隐藏“搜索”会降低总计，并重新计算各占比。每次切换后，播报都会读取新的总计。

**如何让图表忽略某个类别？** 将它从数据中移除，或将其值设为零或负数。数值为零或负数的数据会被忽略，永远不会绘制扇区。

**能否在窄卡片上更改环的尺寸？** 将 `Diameter` 设为所需的尺寸，环会自动缩小以适应较窄的容器。比图例断点更窄的卡片会把图例堆叠到环的下方。

### 图例操作

| 成员 | 含义 |
|---|---|
| `DonutLegendAction.Toggle` | 图例行显示或隐藏其扇区（默认） |
| `DonutLegendAction.Select` | 图例行将其扇区固定为 `ActiveKey`；再次点击则取消固定 |

## 无障碍

- `Label` 为图表命名。每一行图例都是一个切换按钮，其名称包含数值、占比；对于“其他”，还包含其所含的各个部分。隐藏的行在名称之后读作“已隐藏”。
- 图例是键盘操作的路径。每一行都是一个停驻点，也是其对应扇区的切换按钮。
- 显示或隐藏某个扇区时，会以礼貌的方式播报新的总计，例如“搜索已隐藏。总计 50 次访问。”
- 没有图例时，环可以获得焦点，其名称会提示读者使用方向键读取每个扇区。
- 中心读数对辅助技术而言是原始元素；同样的读数会通过播报和隐藏的摘要传达给读者。
- 隐藏的数据表和摘要会列出每个可见部分及其数值和占比。
- 焦点环仅在键盘焦点时显示。

### 键盘

显示图例时，每一行图例都是一个停驻点。没有图例时，环是一个停驻点，方向键在它的各个扇区之间移动。

| 按键 | 操作 |
|---|---|
| 图例：`Down` / `Right` | 移到下一行；最后一行回绕到第一行 |
| 图例：`Up` / `Left` | 移到上一行；第一行回绕到最后一行 |
| 图例：`Home` / `End` | 移到第一行或最后一行 |
| 图例：`Enter` / `Space` | 显示或隐藏该扇区；在 `Select` 模式下则固定或取消固定 |
| 图例：`Escape` | 取消固定的扇区（仅在已固定时） |
| 环（无图例）：`Right` / `Down`、`Left` / `Up` | 预览下一个或上一个可见扇区，到达两端时回绕 |
| 环（无图例）：`Home` / `End` | 预览第一个或最后一个可见扇区 |
| 环（无图例）：`Enter` / `Space` | 固定或取消固定被预览的扇区 |
| 环（无图例）：`Escape` | 清除预览并取消固定 |

键盘预览的扇区会显示在中心，因此读者听到和看到的是同一个数值。将焦点移出图表会清除预览。

## 动效

- 首次显示时，所有扇区同时从顶部扫出，每段的终点稍后跟上。
- 新数据集或隐藏某个扇区时，起始角与终止角会从扇区当前的角度开始变形，因此环保持其运动轨迹与顺序。弧形会以当前的速度移动到新位置。
- 激活的扇区沿中线向外移动并略微加粗，其余扇区变暗。指针在扇区之间的间隙处仍保持悬停状态。
- 中心读数滚动到激活的扇区；总计与各占比数字随新数值变化。
- 减弱动效时，扇区、外移效果与文字会立即显示为最终状态。关闭动效时的表现与减弱动效相同。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 首次显示 | 扇区从顶部扫出，每段终点稍后跟上 | 直接显示最终状态 | 直接显示最终状态 |
| 新数据集或隐藏扇区 | 弧形从当前角度变形，保持速度 | 直接显示最终状态 | 直接显示最终状态 |
| 激活的扇区 | 向外移动并加粗，其余扇区变暗 | 直接显示最终状态 | 直接显示最终状态 |
| 中心读数 | 像滚筒一样滚动到新读数 | 立即变化 | 立即变化 |

## 相关组件

- 部分很多或需要精确比较时，使用 `BarChart`。
- `WaffleChart` 用于以格子数量表示占比，每格代表一个百分点。
- 部分存在嵌套且需要下钻时，使用 `Treemap`。
- `Gauge` 用于单个数值与已知范围的对比。

| 组件 | 适用场景 |
|---|---|
| `BarChart` | 部分超过六个，或读者必须对它们排名 |
| `WaffleChart` | 占比最适合以格子数量来读取 |
| `Treemap` | 各部分嵌套在分组中，需要下钻 |
| `Gauge` | 一个数值需要对照范围和阈值来读取 |
| `UsageMeter` | 配额或限额是面板的重点 |
| `LineChart` | 问题是这种划分如何随时间变化 |
