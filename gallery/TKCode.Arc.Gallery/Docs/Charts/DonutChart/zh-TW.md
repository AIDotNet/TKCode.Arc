## 何時使用

`DonutChart` 呈現一個整體如何劃分為幾個部分。環圈讓人一眼看出劃分的形態，旁邊的圖例給出每個部分的數值和占比，中心則顯示總計，或指標所指部分的數值。它適合放在儀表板的卡片或面板中，此時問題是「這個數字由什麼組成」，答案通常為兩到六個部分。

- **行銷概覽中的造訪來源**：Acme Analytics 顯示本週 48,200 次造訪來自哪些管道（搜尋、直接造訪、社群、電子郵件）。圖例讓每個來源都清楚可讀，較小的來源則併入「其他」，而不是變成細碎的線段。
- **財務頁面中依類別統計的支出**：財務人員把本月支出依薪資、雲端主機、行銷和軟體來審閱。在圖例中固定某個類別後，中心會保留它的數值，而財務人員仍可查看下方的表格。
- **管理主控台中的儲存用量**：工作區擁有者查看哪些專案佔用最多儲存空間。占比低於百分之幾的部分會併入「其他」，擁有者也可以隱藏某個專案，看看其餘部分的環如何變化。
- **支援儀表板中的工單狀態分布**：待處理、等待中與已解決工單的占比，透過切換資料集在本月與本季之間切換。扇形會移動到新位置，而不是重新繪製整個環圈。

## 何時不用

- **部分很多，或需要精確比較各部分**：使用 `BarChart`。十二個扇形很難比較，人眼讀取長度比讀取角度更準確。
- **單一數值與已知上限比較**：使用 `Gauge`，它以門檻值顯示某個讀數在範圍中的位置；若要呈現人們關注其填滿進度的配額，則使用 `UsageMeter`。
- **隨時間的變化**：使用 `LineChart`。環圈只表示某一時刻，把趨勢畫成一系列環圈會掩蓋先後順序。
- **以人數或網格格子計數的占比，例如席位或網格儲存格**：使用 `WaffleChart`，它每個百分點顯示一格，讀起來就是計數。
- **需要下鑽的巢狀部分**：使用 `Treemap`，它保留階層結構，並依數值決定矩形大小。

## 用法

每個 `ChartPoint` 對應一個扇形。為每個資料點設定穩定的 `Key`，這樣資料變化時扇形才能保有各自的身分。數值為零或負數的資料會被忽略。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AtomUICommunity/TKCode.Arc">
    <arc:DonutChart Label="依來源統計造訪量"
                    Unit="次造訪"
                    TotalLabel="總計"
                    OtherLabel="其他"
                    ItemsSource="{Binding Sources}" />
</UserControl>
```

`DonutChart` 衍生自 Arc 圖表家族的基底類別 `ChartBase`，因此 `Label`、`Unit`、`ValueFormat`、`EmptyLabel` 和 `ItemsSource` 的行為與其他圖表一致。環圈圖額外提供環、同步的圖例、中心讀數以及分組規則。由於環是自繪的，每個弧形都是一個繪製物件，資料集變化時只是移動既有的弧形，而不是重新建立控制項。

### 結構

1. **環**：各個弧形，相鄰弧形之間留有 3 px 的間隙，四角為 4 px 圓角。環預設直徑 208 px（`Diameter`），粗細 24 px（`RingThickness`）。在較窄的容器中，它會等比縮小以適應。
2. **中心讀數**：環圈中央的三行短文字。靜止時，頂行是總計標籤（`TotalLabel`），中間一行是總計數值，底行是單位。指標懸停或固定某個扇形時，這幾行改為顯示該扇形的標籤、數值以及它占總計的比例，例如「占總計的 60%」。標籤行與單位行的高度固定（12 px 文字，行高 1.4），因此數值變化時不會移動。
3. **圖例列**：每個可見扇形佔一列，包括顏色色塊、標籤、數值與占比。當容器寬度至少為 460 px 時，圖例位於環圈旁邊；否則位於環圈下方。
4. **「其他」扇形**：併入的小部分。該列會列出它包含的部分，其提示和播報也會列出這些部分。
5. **焦點框**：僅在鍵盤焦點時繪製，圍繞圖例列；若沒有圖例，則圍繞環圈本身。

扇形顏色來自系列調色盤，並在某個鍵第一次出現時依鍵指派，因此資料集變化時，某個類別會保留它的顏色。占比文字使用整數百分比；大於零但小於 1% 的占比顯示為「<1%」。

### 尺寸與分組

`Diameter` 與 `RingThickness` 決定環圈的尺寸。占比低於 `GroupBelow`（占總量的比例，預設 0.04）的部分，以及超出 `MaxSegments`（預設 6，包含「其他」）的部分，會併入「其他」扇形。分組至少需要兩個部分才會發生：單一小部分會保留在自己的扇形中，因為把單一部分併入只會讓它無故隱藏。

```xml
<arc:DonutChart Label="儲存空間"
                Diameter="160"
                RingThickness="18"
                GroupBelow="0.05"
                MaxSegments="5"
                ItemsSource="{Binding Storage}" />
```

在儀表板卡片中，小扇形只會增加雜訊，此時應使用較大的 `GroupBelow`；在財務頁面中，每個類別都必須可見，則應使用較小的值。只有在圖例有空間時才提高 `MaxSegments`：每多一列，都會在環圈旁邊或下方多佔一列的高度。

### 資料集

替換 `ItemsSource` 即可切換資料集。扇形保持原有順序，並從目前的角度移動到新的角度，因此扇形不會被重新掛載。新鍵的扇形會出現在它在順序中的位置；離開的扇形會先收縮為零，然後移除。

```csharp
month.Click += (_, _) => chart.ItemsSource = s_month;
quarter.Click += (_, _) => chart.ItemsSource = s_quarter;
```

在各個資料集之間保持鍵不變（兩個月份中都使用 `"search"`，而不是一個月用 `"Search"`、另一個月用 `"search-ads"`）。鍵變更後就是另一個扇形：它會失去顏色紀錄與隱藏狀態。

### 圖例與隱藏部分

圖例預設可以隱藏與顯示扇形。若只需要環圈本身，請設定 `ShowLegend="False"`。`HiddenKeys` 列出被隱藏的鍵，且為雙向繫結，因此檢視模型可以保存它。被隱藏的扇形會收起，其餘部分在環圈上重新分配，中心的總計只統計可見的扇形。最後一個可見扇形不能被隱藏，因此環圈不會意外變空。

<Demo name="RingOnly" />

```xml
<arc:DonutChart Label="依來源統計造訪量"
                HiddenKeys="{Binding HiddenKeys}"
                ShowLegend="True"
                ItemsSource="{Binding Sources}" />
```

沒有圖例的環圈是一個獨立的鍵盤停駐點：方向鍵依序朗讀每個扇形。當空間緊湊，且環圈本身已經表達了含義時使用它，例如卡片中旁邊配有說明文字的儲存量儀表。

### 固定扇形

設定 `LegendAction="Select"` 可固定扇形，而不是隱藏它。`ActiveKey` 保存被固定的鍵，且為雙向繫結。無論哪種模式，點選環圈上的扇形也會將其固定。被固定的扇形會一直顯示在中心讀數中，直到它被取消固定，或另一個扇形被固定。`ActiveKeyChanged` 會在固定狀態變更時觸發，檢視模型可以在其處理常式中讀取 `ActiveKey`，也可以直接繫結它。

<Demo name="Select" />

```xml
<arc:DonutChart Label="依類別統計支出"
                LegendAction="Select"
                ValueFormat="$#,##0"
                ActiveKey="{Binding PinnedCategory}"
                ItemsSource="{Binding Spend}" />
```

### 繫結到檢視模型

檢視模型擁有資料、隱藏的鍵以及被固定的類別。圖表負責顯示它們，並把使用者的選擇寫回。使用 CommunityToolkit.Mvvm 時：

```csharp
public partial class SpendViewModel : ObservableObject
{
    private static readonly IReadOnlyList<ChartPoint> s_october =
    [
        new ChartPoint("薪資", 9800) { Key = "salaries" },
        new ChartPoint("雲端主機", 4120) { Key = "cloud" },
        new ChartPoint("行銷", 2250) { Key = "marketing" },
        new ChartPoint("軟體", 1350) { Key = "software" },
        new ChartPoint("辦公", 640) { Key = "office" },
        new ChartPoint("差旅", 380) { Key = "travel" }
    ];

    [ObservableProperty]
    private IReadOnlyList<ChartPoint> _spend = s_october;

    [ObservableProperty]
    private IReadOnlyList<string> _hiddenKeys = [];

    [ObservableProperty]
    private string? _pinnedCategory;
}
```

```xml
<arc:DonutChart Label="依類別統計支出"
                ItemsSource="{Binding Spend}"
                HiddenKeys="{Binding HiddenKeys}"
                ActiveKey="{Binding PinnedCategory}"
                LegendAction="Select"
                ValueFormat="$#,##0" />
```

- `HiddenKeys` 與 `ActiveKey` 都是雙向的。圖例的切換會把新清單寫回，因此檢視模型能看到每一次變更，包括用鍵盤做出的變更。
- 應替換 `HiddenKeys` 清單，而不是原地編輯它，因為圖表會回應屬性指派。
- 重新載入時替換 `ItemsSource`。保持鍵穩定，這樣扇形會移動而不是重新建立。
- `ValueFormat`（`$#,##0`）作用於圖例、中心與播報。應在圖表上一次設定，而不是在檢視模型中格式化字串。

### 範例：帳單頁上依類別統計的支出

財務人員打開本月的支出，在閱讀下方表格之前先看出錢花在哪裡。環圈顯示其組成，圖例列出每個類別及其數值和占比，「其他」一列把兩個小類別合併在一起，使它們不會擠佔環圈的空間。辦公與差旅合計仍低於 4% 的門檻，因此併入「其他」，圖例中該列會同時列出這兩個類別。檢視模型固定了雲端主機扇形（將 `PinnedCategory` 設為 `"cloud"`），因此中心顯示的是它的數值和占比，而不是總計。圖表寬 620 px，因此圖例位於環圈旁邊，而不是下方。上面的檢視模型提供了資料點，因此本頁沒有截圖：單靠標記，圖表什麼也畫不出來。

```xml
<StackPanel Width="620" Spacing="16">
    <TextBlock Text="依類別統計支出，2026 年 10 月"
               FontSize="16"
               FontWeight="Medium"
               Foreground="{arc:ArcDesignTokenResource Foreground}" />
    <arc:DonutChart Label="依類別統計支出"
                    ValueFormat="$#,##0"
                    LegendAction="Select"
                    ActiveKey="{Binding PinnedCategory}"
                    ItemsSource="{Binding Spend}" />
</StackPanel>
```

### 文案規範

每個扇形都以它所代表的事物來命名，並由圖表標題說明整體是什麼。圖例和中心讀數會朗讀扇形標籤，因此簡短的名詞片語比完整句子更合適。

| 不要寫 | 改為 |
|---|---|
| Visits | Visits by source |
| Other stuff | Other（圖例列會列出其成員） |
| Search engines and paid ads | Search |
| 0.4% | <1%（圖表對小占比會這樣顯示） |
| 48200 visits | 48,200 visits（`ValueFormat="N0"`） |
| Click a slice to see details | Click a segment to pin it |

`TotalLabel` 應保持為單一詞，例如 Total、Visits 或 Spend，因為它是靜止時中心那一行的標籤。標籤使用句首大寫；使用者需要的單位，例如 "visits" 或 "USD"，應寫在 `Unit` 中，而不要在每個標籤裡重複。

### 最佳做法

**建議**

- 使用兩到六個扇形。每增加一個扇形，使用者需要分辨的弧形就更窄，而圖例是比較它們的可靠方式。
- 為每個資料點設定不依賴標籤的穩定 `Key`。如果重新命名會改變鍵，扇形就會獲得新顏色，並失去隱藏狀態。
- 在財務或營運頁面上保持圖例開啟。圖例是鍵盤操作的路徑，也是唯一顯示每個數值與占比的地方。
- 有意識地設定 `GroupBelow` 與 `MaxSegments`，使「其他」只包含小到無法辨識的部分。
- 透過 `ActiveKey` 固定頁面所關注的扇形，使中心回答頁面提出的問題。

**避免**

- 用環圈表示很長的清單，或用於精確比較。使用者需要對各部分排名時，應使用 `BarChart`。
- 加總沒有實際意義的資料，例如彼此重疊的類別。同一部分被計入兩處，會使占比失真，總計也失去意義。
- 僅靠在檢視模型中隱藏扇形來顯示子集。如果被隱藏的部分根本不應計入總計，應改為在檢視模型中過濾資料。
- 在狹窄的圖例中使用過長的標籤。標籤會被省略號截斷，完整名稱則保留在提示和播報中。
- 在資料集之間更改鍵。這樣扇形會先收起再重新展開，而不是移動到新的大小。

### 常見問題

**為什麼環圈上缺少一個小扇形？** 它的占比低於 `GroupBelow`（預設 4%），或排名超出了 `MaxSegments`，因此被併入「其他」。將指標懸停在「其他」列上，或在圖例中讀取其名稱，即可看到它的成員。單一小部分永遠不會被併入「其他」，因此既缺失又不在「其他」中的部分，其值必定為零或負數。

**固定某個扇形時，能否讓總計一直顯示在畫面上？** 不能。中心會顯示被固定的扇形、它的數值和占比，而不是總計。如果頁面必須同時顯示兩者，應把總計以你自己的文字放在圖表旁邊，並繫結到你從檢視模型中讀取的同一個 `Total` 值。

**總計是否包含被隱藏的扇形？** 不包含。`Total` 只加總可見的扇形，因此隱藏「搜尋」會降低總計，並重新計算各占比。每次切換後，播報都會讀取新的總計。

**如何讓圖表忽略某個類別？** 將它從資料中移除，或將其值設為零或負數。數值為零或負數的資料會被忽略，永遠不會繪製扇形。

**能否在窄卡片上更改環圈的尺寸？** 將 `Diameter` 設為所需的尺寸，環圈會自動縮小以適應較窄的容器。比圖例斷點更窄的卡片會把圖例堆疊到環圈的下方。

## 無障礙

- `Label` 為圖表命名。每一列圖例都是一個切換按鈕，其名稱包含數值、占比；對於「其他」，還包含其所含的各個部分。隱藏的列在名稱之後讀作「已隱藏」。
- 圖例是鍵盤操作的路徑。每一列都是一個停駐點，也是其對應扇形的切換按鈕。
- 顯示或隱藏某個扇形時，會以禮貌的方式播報新的總計，例如「搜尋已隱藏。總計 50 次造訪。」
- 沒有圖例時，環圈可以取得焦點，其名稱會提示使用者使用方向鍵讀取每個扇形。
- 中心讀數對輔助技術而言是原始元素；同樣的讀數會透過播報和隱藏的摘要傳達給使用者。
- 隱藏的資料表和摘要會列出每個可見部分及其數值和占比。
- 焦點框僅在鍵盤焦點時顯示。

### 鍵盤

顯示圖例時，每一列圖例都是一個停駐點。沒有圖例時，環圈是一個停駐點，方向鍵在它的各個扇形之間移動。

| 按鍵 | 操作 |
|---|---|
| 圖例：`Down` / `Right` | 移到下一列；最後一列回繞到第一列 |
| 圖例：`Up` / `Left` | 移到上一列；第一列回繞到最後一列 |
| 圖例：`Home` / `End` | 移到第一列或最後一列 |
| 圖例：`Enter` / `Space` | 顯示或隱藏該扇形；在 `Select` 模式下則固定或取消固定 |
| 圖例：`Escape` | 取消固定的扇形（僅在已固定時） |
| 環圈（無圖例）：`Right` / `Down`、`Left` / `Up` | 預覽下一個或上一個可見扇形，到達兩端時回繞 |
| 環圈（無圖例）：`Home` / `End` | 預覽第一個或最後一個可見扇形 |
| 環圈（無圖例）：`Enter` / `Space` | 固定或取消固定被預覽的扇形 |
| 環圈（無圖例）：`Escape` | 清除預覽並取消固定 |

鍵盤預覽的扇形會顯示在中心，因此使用者聽到和看到的是同一個數值。將焦點移出圖表會清除預覽。

## 動態效果

- 首次顯示時，所有扇形同時從頂部掃出，每段的終點稍後跟上。
- 新資料集或隱藏某個扇形時，起始角與終止角會從扇形目前的角度開始變形，因此環圈保有其運動軌跡與順序。弧形會以目前的速度移動到新位置。
- 作用中的扇形沿中線向外移動並略為加粗，其餘扇形變暗。指標在扇形之間的間隙仍保持懸停狀態。
- 中心讀數滾動到作用中的扇形；總計與各占比數字隨新數值變化。
- 減少動態效果時，扇形、外移效果與文字會立即顯示為最終狀態。關閉動態效果時的表現與減少動態效果相同。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| 首次顯示 | 扇形從頂部掃出，每段終點稍後跟上 | 直接顯示最終狀態 | 直接顯示最終狀態 |
| 新資料集或隱藏扇形 | 弧形從目前角度變形，保持速度 | 直接顯示最終狀態 | 直接顯示最終狀態 |
| 作用中的扇形 | 向外移動並加粗，其餘扇形變暗 | 直接顯示最終狀態 | 直接顯示最終狀態 |
| 中心讀數 | 像滾筒一樣滾動到新讀數 | 立即變化 | 立即變化 |

## 相關元件

- 部分很多或需要精確比較時，使用 `BarChart`。
- `WaffleChart` 用於以格子數量表示占比，每格代表一個百分點。
- 部分存在巢狀結構且需要下鑽時，使用 `Treemap`。
- `Gauge` 用於單一數值與已知範圍的比較。

| 元件 | 適用情境 |
|---|---|
| `BarChart` | 部分超過六個，或使用者必須對它們排名 |
| `WaffleChart` | 占比最適合以格子數量來讀取 |
| `Treemap` | 各部分巢狀於分組中，需要下鑽 |
| `Gauge` | 一個數值需要對照範圍與門檻來讀取 |
| `UsageMeter` | 配額或限額是面板的重點 |
| `LineChart` | 問題是這種劃分如何隨時間變化 |
