## 何時使用

`DataFlow` 說明事件如何在資料平台中流動：從產生事件的產品與服務出發，經過事件串流和批次轉換，進入資料倉儲，再到建立在其上的即時檢視。它是一幅示意圖，而不是監控工具。它適合放在說明文件頁面、導覽畫面或空狀態中，讓讀者在任何真實資料存在之前就理解這條管線。

- **分析類產品的導覽畫面**：首次使用的畫面先展示事件來自哪裡（網頁應用程式、行動應用程式、帳單 Webhook），然後客戶再接入第一個來源。這張圖不需要設定精靈，就能回答「我的資料去了哪裡」。
- **資料平台說明文件**：描述擷取架構的頁面，例如一個 Kafka 主題向驗證作業和湖倉資料表供資料。說明文字與標籤應使用平台的真實元件名稱。
- **營運主控台中的空狀態**：管線頁面上的「尚無事件」面板。動畫告訴使用者管線已經接通並在等待流量，這是空白表格做不到的。
- **解釋過濾步驟**：在資料儲存之前丟棄一部分流量的隱私或品質規則。在轉換節點處淡出的紅色封包，不需要一張規則表就能展示規則移除了什麼。
- **版本說明與更新日誌頁面**：為新增管線階段（例如新的豐富化步驟）的功能配一張簡短的示意圖，放在描述它的文字旁邊。

## 何時不用

- **繪製真實資料量隨時間的變化**：使用圖表分類中的 `LineChart` 或 `BarChart`。`DataFlow` 中的計數器用來說故事，並不是測量值，插圖也不接受你的指標。
- **有目前位置的固定步驟序列**：使用 `Stepper`，適合設定精靈或使用者透過「下一步」和「上一步」推進的擷取作業。`DataFlow` 會自行循環，無法在步驟之間切換。
- **管線的即時狀態**：用 `Alert` 或 `Badge` 顯示每個作業的實際狀態，並用表格呈現延遲與失敗。循環的示意圖無法回報某個作業正在失敗。
- **同一頁面上有大量動畫插圖**：每個插圖在播放時都會逐影格重繪畫布，因此一個畫面上只保留一兩個正在執行，其餘使用減少動態效果的靜態畫面。
- **分支由使用者或資料決定的流程**：歷史紀錄使用 `Timeline`，流程關係使用說明文件中的流程圖。`DataFlow` 展示的是一條固定路線，外加一個過濾分支。

## 用法

插圖載入後即開始播放。圖表下方的說明文字隨故事推進而變化，播放按鈕可暫停播放。此控制項無需資料即可執行：它內建一個預設故事，講的是網頁應用程式、行動應用程式和 Webhook 向資料倉儲與儀表板供資料。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:DataFlow Label="事件管線" />
</UserControl>
```

`DataFlow` 衍生自 `Illustration`，而 `Illustration` 衍生自 Avalonia 的 `TemplatedControl`。因此它是一般的控制項：它有一個為輔助技術命名的 `Label`，可以取得焦點，可透過佈景主題設定樣式，也能放入任何版面配置。共用的插圖基底類別提供場景時鐘、循環腳本、說明文字、播放按鈕和減少動態效果的靜態畫面，因此控制項本身只需描述圖示及其數字。

### 結構

1. **來源**（左欄，`Sources`）：一到四張卡片，每張 150 × 52 場景單位，圓角 12 px，包含圖示、標題和一行詳細資訊。預設來源為網頁應用程式（頁面瀏覽）、行動裝置（點擊與工作階段）和 Webhook（合作夥伴事件）。來源在欄中平均分布，數量增加時間距隨之縮小。
2. **事件串流**（`Labels.Stream`、`Labels.StreamDetail`）：接收每個事件的佇列。卡片下方的計量條隨事件抵達而填滿，在轉換環節取走一批後清空。計量條上限為 24 個事件。
3. **吞吐量讀數**：事件串流卡片下方的每秒事件數，以半秒取樣平滑，並以 `Labels.EventsPerSecond` 格式化。
4. **轉換**（`Labels.Transform`、`Labels.TransformDetail`）：批次處理步驟，批次處理期間顯示忙碌圓環。被過濾的事件在此被移除。
5. **資料倉儲**（`Labels.Warehouse`、`Labels.WarehouseDetail`）：右側上方的分支。卡片下方的讀數統計已儲存的列數，並以 `Labels.Rows` 格式化。
6. **儀表板**（`Labels.Realtime`、`Labels.RealtimeDetail`）：右側下方的分支，其讀數統計推送到即時檢視的更新次數，並以 `Labels.Updates` 格式化。
7. **說明行**（`IsCaptionVisible`）：圖示下方的一行次要文字，使用小字級和次要文字顏色，隨每一步變化。
8. **播放按鈕**（`IsPlaybackButtonVisible`）：外框右下角的圓形按鈕，在靜態畫面中隱藏。
9. **外框**：帶 1 px 邊框（邊框色）和表面圓角的表面卡片，背景為點狀底紋。左右與上方的內距為 20 px，下方為 14 px。場景會依控制項所給定的寬度縮放，因此在窄欄中圖示仍能保持比例。

封包以強調色繪製。走過過濾路徑的封包會變為危險色並淡出；通往即時檢視的路線使用成功色。

### 吞吐量與過濾

`EventsPerSecond` 設定資料來源發出事件的速度。取值範圍為 1 到 60，預設 18，超出範圍的值會被限制在邊界內。`FilterRatio` 設定轉換環節移除的事件占比。取值範圍為 0 到 0.5，預設 0.14，因此預設情況下約每七個事件過濾掉一個。

```xml
<arc:DataFlow EventsPerSecond="8" FilterRatio="0.3" />
```

轉換環節每秒處理一批最多八個事件，因此每秒事件數高於 8 時，計量條會逐漸爬向其容量。此插圖說明的是管線的形態；它不模擬背壓、延遲或遺失事件，也不應用來估算容量。

### 來源與標籤

`Sources` 接受一到四個 `DataFlowSource` 值。每個值都有一個 `Title` 和一行選用的 `Detail`。空清單會回退為預設來源，超過四項的清單只取前四項。`Labels` 屬性接受一個 `DataFlowLabels` 物件，其中包含圖示中每一個可見的文字：節點標題與詳細資訊、讀數格式以及步驟說明文字。只設定需要的屬性即可，其餘保留英文預設值。

<Demo name="OwnSources" />

變更 `Sources` 或 `Labels` 會重建圖示，因此應在頁面載入時同時設定兩者，而不要在每次資料重新整理時設定。

### 播放與速度

`IsPlaying` 用來播放和暫停故事。它是雙向的：使用者按下播放按鈕或空白鍵時，控制項會寫入該值；應用程式也可以讀取或繫結它。`Speed` 縮放場景時鐘，取值範圍為 0.25 到 4。`Play()`、`Pause()` 和 `Restart()` 可在程式碼中執行相同的操作。`Restart()` 會重設計數器並回到第一步。

```xml
<arc:DataFlow Speed="2" IsPlaying="{Binding IsPipelineRunning}" />
```

```csharp
flow.Speed = 0.5;
flow.Restart();
```

當控制項移出畫面、被隱藏或從視覺樹中分離時，場景時鐘會暫停，因此捲動到可視範圍之外的索引標籤中的插圖，在重新可見之前不耗用任何資源。

### 跟隨故事進度

`Step` 與 `StepCount` 描述循環中的位置。故事共三步，每一步都會更新說明文字：

| 步驟 | 說明文字 | 醒目提示的內容 |
|---|---|---|
| 0 | 帶有來源數量的擷取說明文字 | 從來源到事件串流的連線 |
| 1 | 轉換說明文字：已驗證並豐富化，異常事件被過濾 | 通往轉換環節的連線 |
| 2 | 儲存說明文字：合格事件寫入資料倉儲並更新即時儀表板 | 通往資料倉儲與儀表板的連線 |

`StepChanged` 提供新的步驟及其說明文字。`RowsStored` 與 `EventsFiltered` 分別統計故事開始以來寫入資料倉儲的列數，以及被轉換環節移除的事件數。兩者皆為唯讀，由插圖自行維護。

```csharp
flow.StepChanged += (_, e) => status.Text = $"第 {e.Step + 1} 步，共 {flow.StepCount} 步：{e.Caption}";
```

### 減少動態效果

在減少動態效果（或關閉動態效果）下，插圖是其穩定狀態的靜態畫面：每條連線都會醒目提示，每條路線的中間停留一個封包以顯示行進方向，說明文字概括整個故事。播放按鈕隱藏，因為沒有可播放的內容。在不需要動態效果的頁面、列印品以及靜態匯出中使用此靜態畫面。

### 由資料驅動

`DataFlow` 不會讀取事件串流，它只繪製交給它的故事。在應用程式中，當來源和標籤來自設定時，從檢視模型繫結它們，並將播放狀態與之一併保存。下面的範例使用 CommunityToolkit.Mvvm，展示一個仍在設定中的分析產品的管線。

```csharp
public partial class PipelineSetupViewModel : ObservableObject
{
    [ObservableProperty]
    private bool _isPipelineRunning = true;

    [ObservableProperty]
    private double _speed = 1;

    public IReadOnlyList<DataFlowSource> Sources { get; } =
    [
        new("結帳", "訂單"),
        new("行動應用程式", "工作階段"),
        new("帳單 Webhook", "發票")
    ];

    public DataFlowLabels Labels { get; } = new()
    {
        Warehouse = "資料湖倉",
        WarehouseDetail = "parquet",
        Realtime = "警示",
        RealtimeDetail = "值班"
    };
}
```

```xml
<arc:DataFlow Sources="{Binding Sources}"
              Labels="{Binding Labels}"
              IsPlaying="{Binding IsPipelineRunning}"
              Speed="{Binding Speed}" />
```

每組設定只繫結一次 `Sources` 與 `Labels`。新的清單或標籤物件會重建圖示，因此不要在計時器中取代它們。用 `IsPlaying` 把故事與頁面狀態連動，例如在設定對話方塊開啟時暫停它。

### 文案規範

用與架構相同的名詞命名節點標題（事件佇列、資料湖倉、警示），詳細資訊行應簡短、小寫且具體（schema · enrich、parquet、on-call）。使用真實的來源名稱，而不是類型名稱：「結帳訂單」比「資料來源 1」更能說明問題。說明文字與標籤應與頁面其餘部分使用相同的時態。

| 不要寫 | 改為 |
|---|---|
| 資料來源 1 | 結帳 |
| 處理 | 驗證 |
| 資料庫 | 資料湖倉 |
| 即時 | 警示 |
| 事件在我們出色的管線中被處理 | 事件每秒驗證一次，並存入資料湖倉 |
| 已達到 18 events/s 的吞吐量 | 18 events/s |
| 你的資料正在流動 | 等待第一批事件 |

將標籤控制在約 16 個字元以內，使節點卡片維持單行；過長的標題會換行，卡片會顯得擁擠。不要在詳細資訊行中寫整句話。整個故事的描述請使用 `Summary`，並保持為一句話。

### 最佳做法

**建議**

- 在 `Labels` 中使用平台的真實元件名稱，因為讀者會把圖示與他們來自的架構頁面相互對照。通用的「處理」節點無法傳達任何資訊。
- 使用兩到三個來源。預設間距在兩個和三個來源時最寬鬆，四張卡片在窄寬度下幾乎沒有空間容納詳細資訊行。
- 在說明文件頁面上保持故事的預設速率。每秒 18 個事件的速率既能呈現活躍感，又不會分散讀者對正文的注意力。
- 當讀者所專注的頁面之外的插圖位於可視範圍之外時，用 `IsPlaying` 暫停故事；對於關閉了動態效果的使用者，讓靜態畫面取而代之。

**避免**

- 把計數器當作指標使用。`RowsStored` 與各項讀數統計的是插圖所講的故事，如果儀表板將它們顯示為真實資料量，回報的數字就不是來自你的系統。
- 在同一個畫面上放置多個正在播放的插圖。每個插圖都會逐影格重繪畫布，耗用的效能會疊加，也會爭奪注意力。
- 在計時器中或每次資料重新整理時變更 `Sources` 或 `Labels`。每次變更都會捨棄圖示並重新建立，故事永遠無法播放完成。
- 在標籤中寫一句話。卡片很小，長文字會換行並擠滿外框。
- 依賴圖示來判斷狀態。它展示的是管線的形態，而不是某個作業是否健康，因此故障應使用 `Alert` 或表格回報。

### 常見問題

**如何重新命名說明文字中的三個步驟？** 設定 `Labels` 的 `TransformStep` 與 `StoreStep` 屬性，整個故事則設定 `Summary`。第一步的說明文字由 `Ingest` 產生，它接收來源數量作為參數，因此若要修改措辭，請修改該函式。

**為什麼故事總是顯示相同的數字？** 插圖使用固定的隨機種子，因此每次執行的過程都相同。每次重新啟動時計數器都從相同的值開始，資料來源以帶有抖動但可重複的間隔發出事件。這讓說明文件的截圖與測試保持穩定。

**能否用我自己的計數來驅動讀數？** 不能。`RowsStored` 與 `EventsFiltered` 是唯讀的，讀數值由插圖自行維護。若要展示真實資料量，請使用 `LineChart` 或 `AnimatedCounter`，並填入指標儲存中的數字。

**不改程式碼，如何展示不同數量的來源？** 如上方檢視模型所示，將 `Sources` 繫結到設定中的集合。第四項之後的值會被忽略，空清單則會恢復為三個預設來源。

**長時間執行時，事件池會增長嗎？** 不會。封包來自一個固定的池並被重複使用，因此執行數小時的故事始終保持相同數量的封包物件。

## 無障礙

- `Label` 是插圖的無障礙名稱。請在其中為管線命名，例如「Acme Analytics 的事件管線」，因為圖示本身沒有讀者可以逐項瀏覽的文字。
- 插圖可取得焦點，取得焦點時外框周圍會顯示 2px 焦點環。
- 目前的說明文字會作為說明文字提供，因此焦點位於控制項上時，螢幕閱讀器會朗讀該步驟的描述。
- 說明文字的變化不會被播報。故事會循環播放，逐步播報會無止境地重複。
- 標籤與讀數就是圖示所顯示的文字。請讓它們脫離動畫也能被理解，因為看不到動畫的讀者仍能取得節點標題與說明文字。
- 在減少動態效果下，靜態畫面顯示穩定狀態及概要說明文字，在沒有任何動作的情況下傳達相同的資訊。

### 鍵盤

插圖可透過 Tab 鍵取得焦點。取得焦點後，以下按鍵可控制故事：

| 按鍵 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 將焦點移入或移出插圖 |
| `Space` 或 `Enter` | 播放或暫停故事 |
| `R` | 從第一步重新開始故事 |

## 動態效果

- 事件以小型封包的形式沿連線傳送。事件串流的計量條隨事件抵達而填滿，隨批次離開而清空，讀數同步遞增。
- 每一步都會點亮屬於該步驟的連線，其餘連線淡回原色。
- 被過濾的封包會變為紅色，並在離開轉換環節後不久淡出。
- 播放按鈕與說明文字以短暫的過渡變化，步驟的節點在啟用時會強調顯示。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| 事件沿連線傳送 | 每條路線上都有動畫封包 | 靜態畫面，每條路線上停留一個封包 | 靜態畫面 |
| 目前步驟的連線亮起 | 0.4 s 內淡入 | 以穩定狀態顯示（全部亮起） | 以穩定狀態顯示 |
| 被過濾的事件 | 變為紅色，並在轉換環節附近淡出 | 不顯示 | 不顯示 |
| 讀數（事件/s、列數、更新數） | 故事進行中遞增計數 | 顯示靜態畫面的數值 | 顯示靜態畫面的數值 |
| 播放按鈕 | 可見；切換播放狀態 | 隱藏 | 隱藏 |

## 相關元件

- `PaymentFlow`：單筆請求被核准或被拒絕的情境，外框與播放控制項相同。
- `MultiRegionFailover`：流量在區域之間切換的情境。
- `VectorSearch`：根據最相近的文件回答問題的情境。

| 元件 | 適用情境 |
|---|---|
| `LineChart` / `BarChart` | 你要繪製隨時間變化的真實測量值 |
| `Stepper` | 使用者透過「下一步」和「上一步」依序經過固定的序列 |
| `Timeline` | 你要依順序、帶時間地展示事件的歷史 |
| `Alert` | 你要以文字說明真實管線或作業的狀態 |
| `PaymentFlow` | 故事是一筆請求被核准或被拒絕 |
| `VectorSearch` | 故事是由最相近的文件回答的問題 |
