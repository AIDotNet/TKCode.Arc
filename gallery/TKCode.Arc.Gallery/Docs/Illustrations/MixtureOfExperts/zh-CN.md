## 何时使用

`MixtureOfExperts` 说明稀疏混合专家层如何处理文本：每个 token 先由路由器打分，再交给得分最高的一位或两位专家，最后由它们的输出重新组合。它回答读者第一次看到“480B 参数，30B 激活”这类描述时的疑问：哪些参数在运行，以及为什么对于任何一个 token 来说，大部分参数都保持静止。它是讲解插图，而不是监控工具：其中的分数、负载和参数量都是示意性的，因此要在周围的文字中说明这一点。

- **模型文档**：介绍稀疏模型及其激活参数量的页面。标题栏的读数和摘要句说明较小的那个数字从何而来。
- **课程与新人引导**：讲解路由的课程，读者可以在 top 1 与 top 2 之间切换，指向某个 token 查看它的门控分数，或指向某位专家查看它接收了哪些 token。
- **容量与负载均衡**：说明专家为何有容量限制，以及装不下的 token 会怎样的说明。被跳过的选择和负载均衡条让这一取舍一目了然。
- **推理平台的产品页面**：放在文字旁边的简短示意图，说明为什么同等规模的混合专家模型比稠密模型更便宜。
- **演讲与发布说明**：一张循环播放的卡片，不需要旁白，在四十秒内讲完整个故事。

## 何时不用

- **展示你自己模型的真实路由统计**：使用 `BarChart` 或 `DataGrid`，并填入实测的专家负载。卡片根据所给的分数规划自己的小故事，它并不是测量仪器。
- **选择哪个模型回答请求**：那是你产品中的模型路由器，属于另一个概念，处于另一个层级。此时应使用模型选择器或普通的 `Select`。
- **解释注意力或分词**：卡片按原样显示 token，不说明文本如何切分，也不说明哪些 token 关注哪些 token。这类内容应使用专门为此制作的示意图。
- **同一屏幕上有多张卡片**：每张卡片在播放时都会做动画。每个页面只保留一张，或用 `IsPlaying` 暂停其他卡片。
- **长序列**：故事在每个 token 上花费 2.2 秒。十五到二十个 token 就能讲清楚，一整段文字则会变成漫长的等待。

## 用法

卡片无需数据：它内置了一句包含十五个 token 和八位专家的虚构句子。卡片第一次大部分可见时开始播放，并循环：最后一个 token 之后，摘要停留 3.6 秒，然后路由重新开始。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:MixtureOfExperts MaxWidth="760" />
</UserControl>
```

`MixtureOfExperts` 派生自 `Explainer`，它是 Special 包中动画化 AI 讲解插图的基类，而 `Explainer` 派生自 Avalonia 的 `TemplatedControl`。基类提供故事时钟（`IsPlaying`、`Speed`、`IsLooping`、`Play()`、`Pause()`、`Restart()`）、进入可视区域即开始播放的行为、播放按钮以及礼貌的即时区域。本控件只负责描述这一层、规划路由并将其绘制出来。

### 结构

1. **标题栏**：在 top 1 与 top 2 之间切换的开关（`TopK`）、激活参数读数（来自 `Parameters` 的 "Active parameters 30B of 480B"）以及圆形播放按钮。
2. **输入**：正在被路由的 token，位于一个从左侧滑入的标签块中。当它的数据包离开、前往路由器后，标签块变暗。
3. **路由器**：一个圆角方框，为每位专家显示一条分数条和百分比。分数条的长度与分数本身成正比，而不是与最高分成正比，因此 50% 的分数恰好填满一半轨道。得分最高的几个选择分别使用第一、第二选择的颜色，其余保持弱化。
4. **门控线**：从路由器到每位专家各有一条线。被选中的线条以其选择的颜色亮起；指向已满专家的线条变成带虚线的警示线。
5. **专家方块**：一个图标、专家名称，以及它已接收 token 数量的计数器，底部沿着一条细的容量条。被选中的方块以其选择的颜色亮起；已满、跳过该 token 的专家方块会变为虚线，并显示警告标志。
6. **合并曲线与光点**：被选中专家的输出沿曲线汇合为一个光点，然后移动到输出端。
7. **输出**：该 token 的输出标签块，每位处理过该 token 的专家对应一个圆点。已直接穿过的 token 显示为虚线标签块，且没有圆点。
8. **序列**：每个 token 都是分隔线下方的一个标签块。尚未播放的 token 弱化显示，当前 token 带有圆环，已完成路由的 token 则是实心填充。
9. **页脚**：路由行（token、箭头，以及每个选择及其权重）和一句用文字说明它的提示。右侧是负载均衡读数，以及每位专家一段的负载条。

宽度小于 568 像素时，舞台改为从上到下排列：路由器变成一排竖向柱条，位于一行图标方块之上。宽度小于 640 像素时，负载均衡移到页脚文字下方；小于 480 像素时，内边距收紧，读数单独占一行，路由行也去掉 token 标签块。

### 演示过程

在速度为 1 时，每个 token 占用 2.2 秒：

| 时间 | 发生的事 |
|---|---|
| 0 s | 该 token 成为当前 token，其标签块滑入。路由器仍显示上一个 token 的弱化分数。页脚提示路由器正在为专家评分。 |
| 0.16 – 0.48 s | 一个带短拖尾的中性数据包移向路由器。 |
| 0.48 s | 路由器显示该 token 的分数；得分最高的几个选择采用各自的颜色，页脚显示路由。 |
| 0.76 – 1.14 s | 每个选择各自颜色的数据包移向对应专家（离开时抬升 `Routed`）。前往已满专家的数据包会在专家前停住。 |
| 1.14 s | 被选中的专家亮起，计数器滚动，容量条和负载均衡随之移动。 |
| 1.38 – 1.66 s | 输出沿合并曲线移动；长度不同的曲线同时到达。 |
| 1.66 – 1.84 s | 合并后的数据包移向输出端。 |
| 1.84 s | 输出标签块变为该 token，该 token 被标记为已路由。 |

最后一个 token 之后，摘要会说明一共路由了多少个 token，以及每个 token 只用了多少参数。

### 计算方式

卡片会一次规划整个序列，因此在播放之前就能检视任意 token。所有数字都来自各 token 的分数：

- **门控分数**被归一化为总和为 1。百分比是逐个取整的，因此一对数字的相加可能得到 101。
- **选择**是分数最高的 `TopK` 位专家。分数相同时，排在前面的专家优先。
- **权重**是所选分数除以它们的总和：44% 与 22% 的分数混合为 67 比 33。
- **容量**为 ⌈系数 × token 数 × k ÷ 专家数⌉ 个 token 每位专家。15 个 token 分配给 8 位专家时，top 2 为每位 4 个，top 1 为每位 2 个。
- **装载**按顺序进行。已满的被选专家会跳过该 token；它保留自己的权重，另一位专家不会被提升到 100%。若一个 token 的所有选择都已满，则它原样穿过。
- **负载均衡**为 (E − 最大负载 ÷ 平均负载) ÷ (E − 1)：所有专家负载相同时为 100%，一位专家接收全部 token 时为 0%。
- **激活参数**为共享参数 + k × 每位专家参数：按默认值，top 1 时为 6 + 12 = 18B，top 2 时为 6 + 24 = 30B。

使用默认数据时，15 个 token 在 top 2 下产生 28 次分配，因为有两个第二选择发现其专家已满，最终均衡度为 98%。top 1 时最后一个句号直接穿过。

### Top k 与容量

`TopK` 取值为 1 或 2，并且是双向的：标题栏的开关会写入它，应用也可以绑定它。修改它会重新规划每条路由，并从故事的同一位置继续，因此计数器、负载均衡和页脚原地变化，读数也滚动到新的数量。`CapacityFactor` 缩放容量；`double.PositiveInfinity` 则关闭容量限制，此时容量条相对于最繁忙的专家来填充。

```xml
<arc:MixtureOfExperts TopK="1" CapacityFactor="1.5" />
```

### 自定义专家与 token

`Experts` 接受 2 到 12 个 `MixtureOfExpertsExpert` 项，每项有一个 `Name`、一个可选的 `Handles` 句子（在检视该专家时显示），以及一个可选的 24×24 `Icon` 几何图形（未设置时以名称的首字母代替）。`Tokens` 接受 `MixtureOfExpertsTokenItem` 项，包含其 `Text`，以及可选的每位专家一个原始分数，放在 `Scores` 中。未提供分数的 token 会根据其文本获得稳定的示例分数：相同的文本总是以相同的方式路由。`Parameters` 接受以十亿为单位的总参数量、共享参数量和每位专家参数量。

<Demo name="CodeModel" />

```xml
<arc:MixtureOfExperts TopK="1" Parameters="96, 4, 7.5" CapacityFactor="1.25">
    <arc:MixtureOfExperts.Experts>
        <arc:MixtureOfExpertsExpert Name="Keywords" Handles="Reserved words such as if, for and return."
                                    Icon="{x:Static arc:ArcIcons.Code}" />
        <arc:MixtureOfExpertsExpert Name="Names" Handles="Variables, functions and types."
                                    Icon="{x:Static arc:ArcIcons.Hash}" />
        <!-- … -->
    </arc:MixtureOfExperts.Experts>
    <arc:MixtureOfExpertsTokenItem Text="for" Scores="62, 12, 3, 4, 6" />
    <arc:MixtureOfExpertsTokenItem Text=" total" />
</arc:MixtureOfExperts>
```

`Text` 中的空格会被保留，就像分词器保留空格一样。少于两位专家时回退为默认值，超过第十二位的专家会被省略。修改任一列表都会让故事重新开始。

### 查看 token 或专家

指向某个 token，或用键盘使其获得焦点，会让故事停留在当前位置，并一次显示该 token 的完整路由：它的分数、两条连线、亮起的方块，以及它之后的负载情况，即使该 token 尚未播放也是如此。指向某位专家时，舞台保持不变，并高亮该专家迄今为止接收的 token，按它是其第一还是第二选择着色；页脚显示它的负载和它的 `Handles` 句子。移开指针后，故事从同一时刻继续。

点击、轻触、Enter 或 Space 会固定该 token 或专家：故事停在该处，播放按钮提供恢复播放的选项。按下 Escape、再次点击或调用 `Unpin()` 会解除固定，故事继续播放。`PinToken(index)` 和 `PinExpert(index)` 可在代码中完成相同的操作；`InspectedTokenIndex` 和 `InspectedExpertIndex` 报告当前显示的内容。

### 播放、事件与绑定

每个 token 的数据包离开路由器时会触发 `Routed`，事件参数包括该 token 的 `Index`、`Token`、归一化的 `Scores`、按最优先排列的被选 `Experts`、它们的 `Weights`，以及已满而被跳过的 `Dropped` 专家。`Routes` 保存当前设置下的完整规划，而 `ActiveParameters`、`Capacity`、`CurrentTokenIndex` 和 `LoadBalance` 报告显示时的状态。下面的示例会记录路由、阻止故事循环、关闭容量限制，并为选择使用另外两种图表系列颜色。

<Demo name="RouteLog" />

```csharp
card.Routed += (_, e) =>
{
    var first = e.Experts[0];
    log.Add($"{e.Token} → expert {first} ({e.Weights[0]:P0})");
};
```

`IsPlaying` 是双向的，因此视图模型可以在对话框打开时暂停卡片。`Speed` 将故事时钟从 0（静止不动）缩放到 4；卡片本身没有速度控件。`FirstChoiceBrush` 和 `SecondChoiceBrush` 用于替换选择颜色，默认使用图表系列 1 和 2，并跟随强调色。

### 内容指南

以专家大多处理的内容为其命名，用一个简短的词即可（窄布局只显示它们的图标）。`Handles` 则应写成一句读者可以对照其所接收 token 进行核对的平实句子。真实的专家远没有这么整齐；请在卡片周围的文字中说明这一点。选择一句混合多种类型 token（名称、动词、代码、数字、标点）的句子，使路由在不同 token 之间明显变化。

| 避免 | 改为 |
|---|---|
| 专家 3 | 数字 |
| 处理高激活度的数值 token | 整数以及日期中的数字。 |
| 一段四十个 token 的文字 | 一句十二到二十个 token 的句子 |
| 671B 参数（某个真实模型的数字） | 你自己的示意数字，并说明它们仅为示意 |
| 没有主题的专家 | 名称与其接收的 token 相匹配的专家 |

### 最佳实践

**建议**

- 为承载故事重点的 token 提供分数（找到已满专家的那个、直接穿过的那个），其余 token 的分数让它们自行推导。
- 当故事关于容量时，保留默认的容量系数：15 个 token 配 8 位专家会产生一到两次跳过，足以让读者注意到。
- 在周围的文字中解释摘要句；它是读者最常引用的部分。
- 让读者可以自行检视：悬停停留正是读者按自己的节奏检查路由的方式。

**避免**

- 将负载、均衡度或参数量当作真实模型的测量结果来展示。
- 在标签或参数中使用厂商的模型名称或标志。
- 超过十二位专家，或使用很长的 token 文本；方块和标签块不会为容纳内容而变大。
- 每隔一段时间重建 token 列表：每次变化都会让故事重新开始。

### 常见问题

**为什么被跳过的专家仍保留其权重？** 真实的层中容量限制就是这样运作的：token 的输出由实际处理它的专家按路由器给出的权重混合而成。卡片如实展示这一点，以便让损失可见，而不是悄悄地把另一位专家提升到 100%。

**没有分数的 token，分数由什么决定？** 卡片对 token 的文本进行哈希，并以此为种子生成一位最受青睐的专家、一位次优专家，以及其余专家的小分数。相同的文本总是得到相同的分数，因此截图和测试保持稳定。

**故事可以从暂停状态开始吗？** 设置 `AutoPlay="False"`；卡片会停在第一个 token 处，直到 `Play()` 或播放按钮被触发。设置 `IsLooping="False"` 则让故事停在摘要处。

**悬停会暂停卡片吗？** 悬停只是保持故事停留，而不会改变 `IsPlaying`，因此绑定的视图模型不会察觉到暂停。固定则会暂停卡片，此时播放按钮会提供恢复播放的选项。

## 无障碍

- 卡片是一个分组，由 `Title` 命名（默认为 "Mixture of experts routing"）。
- 专家方块和序列中的 token 都是真正的按钮。每个专家分组和序列各占用一个 Tab 停靠点，方向键在其内部移动。被固定的方块或 token 会报告一个已按下的切换状态。
- token 的名称包含其完整路由（"Ada: People 71%, Syntax 29%"，对于已达容量的专家会附加 "full, skipped"）。方块的名称包含其负载、是否已满，以及它在当前显示的路由中所扮演的角色（"Syntax expert, 4 tokens, at capacity, second choice for x"）。
- 读数和负载均衡会被读成句子（"30B of 480B parameters active per token"）；它们滚动的数字对屏幕阅读器隐藏。
- 即时区域只播报读者自己的操作：暂停、恢复、重新开始、固定与解除固定，以及 top k 的变化。自动播放的路由不会被播报。
- 颜色从不是唯一的信号：第一选择在路由行中排在最前，被跳过的专家带有警告标志、虚线边框和 "full" 字样。

### 键盘

| 按键 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 在 top-k 开关、播放按钮、专家方块和 token 序列之间移动 |
| `←` / `→` | 在 top-k 开关中选择 top 1 或 top 2 |
| `↓` / `→`、`↑` / `←` | 在方块或序列中移到下一个或上一个（不循环）；获得焦点即会检视该项 |
| `Home` / `End` | 第一个或最后一个方块或 token |
| `Enter` / `Space` | 固定或解除固定当前焦点的方块或 token；在播放按钮上，则为暂停、恢复或重新路由 |
| `Escape` | 解除固定（焦点停留在该项上时，它仍保持被检视状态，直到焦点移开） |

## 动效

| 变化 | 完整 | 减少 | 关闭 |
|---|---|---|---|
| 数据包 | 一个带柔和拖尾的圆点沿每条路径移动，缓入缓出 | 不显示 | 不显示 |
| token 节奏 | 每个 token 2.2 秒，然后 3.6 秒摘要并循环 | 每个 token 1.8 秒，停在摘要处 | 同减少 |
| 分数条、连线颜色、路由器边框 | 240 毫秒 | 立即变化 | 立即变化 |
| 方块亮起 / 恢复 | 160 毫秒 / 480 毫秒 | 立即变化 | 立即变化 |
| 计数器、读数、负载均衡 | 数字以平滑的弹簧滚动 | 立即变化 | 立即变化 |
| 容量条和负载段 | 480 毫秒内滑动 | 立即变化 | 立即变化 |
| 标签块 | 输入从 14 像素处滑入，输出从 10 像素处滑入 | 立即变化 | 立即变化 |
| 页脚行 | 旧行淡出，新行上升 2 像素 | 短暂淡入淡出 | 立即变化 |

数据包运行在故事时钟上，因此会随 `Speed` 暂停、保持和缩放；淡入淡出是会自行结束的短过渡。卡片位于可视区域之外时，时钟停止。
