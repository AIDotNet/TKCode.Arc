## 何時使用

`MixtureOfExperts` 說明稀疏混合專家層如何處理文字：路由器為每個 token 評分，將它交給最好的一或兩位專家，再由他們的輸出重組出結果。它回答讀者第一次看到「480B 參數、30B 啟用」這類描述時會問的問題：哪些參數會運作，以及為什麼對任何一個 token 而言，大部分參數都保持閒置。它是一個講解工具，而不是監控儀表：其中的分數、負載和參數數量都是示意數字，因此要在插圖周圍的文字中說明這一點。

- **模型說明文件**：介紹稀疏模型及其啟用參數數量的頁面。標題列的讀數與摘要句會顯示較小的數字是從哪裡來的。
- **課程與新人引導**：講解路由的課程，讀者可在 top 1 與 top 2 之間切換，指向某個 token 以查看其閘控分數，或指向某位專家以查看它接收了哪些 token。
- **容量與負載平衡**：說明專家為何有容量限制，以及放不下的 token 會發生什麼事的註解。被跳過的選擇與負載平衡條會讓這項取捨一目了然。
- **推論平台的產品頁面**：放在文字旁的簡短視覺圖，說明為什麼同等規模的混合專家模型比稠密模型更便宜地提供服務。
- **演講與版本說明**：一張循環播放的卡片，不需旁白，在四十秒內講完整個故事。

## 何時不用

- **顯示你的模型的真實路由統計**：使用 `BarChart` 或 `DataGrid`，搭配實際測得的專家負載。卡片會根據所給的分數規劃自己的小故事；它不是測量儀器。
- **選擇由哪個模型回答請求**：那是你產品中的模型路由器，屬於不同層級的概念。模型選擇器或一般的 `Select` 才是正確的控制項。
- **說明注意力或 tokenization**：卡片只顯示給定的 token，不說明文字如何切分，也不說明哪些 token 關注哪些 token。請使用為此製作的圖表。
- **同一個畫面上有多張卡片**：每張卡片在播放時都會產生動畫。每頁只放一張，或使用 `IsPlaying` 暫停其他卡片。
- **長序列**：故事在每個 token 上花 2.2 秒。十五到二十個 token 就能講完故事；一整段文字會讓讀者等待過久。

## 用法

卡片不需要資料：它內建一句虛構的十五個 token、八位專家的句子。它第一次大部分進入畫面時開始播放，並且循環：最後一個 token 之後，摘要停留 3.6 秒，然後路由重新開始。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:MixtureOfExperts MaxWidth="760" />
</UserControl>
```

`MixtureOfExperts` 衍生自 `Explainer`，這是 Special 套件中動畫 AI 講解工具的基底類別；而 `Explainer` 衍生自 Avalonia 的 `TemplatedControl`。此基底提供故事時鐘（`IsPlaying`、`Speed`、`IsLooping`、`Play()`、`Pause()`、`Restart()`）、進入畫面時開始播放的行為、播放按鈕和禮貌的即時區域；此控制項則負責描述這一層、規劃路由並繪製它們。

### 結構

1. **標題列**：在 top 1 與 top 2 之間切換的開關（`TopK`）、啟用參數讀數（「Active parameters 30B of 480B」，來自 `Parameters`），以及圓形播放按鈕。
2. **輸入**：正在被路由的 token，位於從左側滑入的標籤塊中。封包離開前往路由器後，標籤塊變暗。
3. **路由器**：一個圓角方框，每位專家一條分數條與百分比。分數條的長度與分數本身成比例，而不是與最高分成比例，因此 50% 的分數會填滿一半的軌道。最佳的幾個選擇分別採用第一與第二選擇的顏色；其餘的保持淡色。
4. **閘控線**：從路由器到每位專家各一條線。被選中的線以其選擇的顏色亮起；通往已滿專家的線則變為虛線警示線。
5. **專家方塊**：一個圖示、專家的名稱，以及其已接收 token 數量的計數器，底部有一條細的容量條。被選中的方塊以其選擇的顏色亮起；已滿而跳過該 token 的專家會變為虛線，並帶有警示標誌。
6. **合併曲線與光點**：被選中的專家輸出沿曲線匯聚成一個點，然後移往輸出端。
7. **輸出**：該 token 的輸出標籤塊，每位處理過它的專家都有一個圓點。曾經通過的 token 其標籤塊為虛線，且沒有圓點。
8. **序列**：每個 token 以標籤塊顯示在分隔線下方。尚未到來的 token 為淡色，目前的 token 有一個環，已路由的 token 則為實心填滿。
9. **頁尾**：路由列（token、箭頭，以及每個選擇與其權重）和一段以文字說明它的註解。右側則是負載平衡讀數，以及一條每位專家一個區段的條狀圖。

寬度小於 568 像素時，舞台會改為由上而下排列：路由器變為一排垂直條，下方是一列圖示方塊。寬度小於 640 像素時，負載平衡會移到頁尾文字下方；小於 480 像素時，內距收緊，讀數獨占一行，路由列也會省略 token 標籤塊。

### 故事

在速度 1 時，每個 token 花費 2.2 秒：

| 時間 | 發生什麼事 |
|---|---|
| 0 s | 該 token 成為目前的 token，其標籤塊滑入。路由器仍顯示先前的分數，且為淡色。頁尾說明路由器正在為專家評分。 |
| 0.16 – 0.48 s | 一個帶有短拖尾的中性封包移往路由器。 |
| 0.48 s | 路由器顯示該 token 的分數；最佳的選擇採用其顏色，頁尾顯示路由。 |
| 0.76 – 1.14 s | 每個選擇各有一個以其顏色呈現的封包移往其專家（離開時會觸發 `Routed`）。前往已滿專家的封包會在抵達前停在近處。 |
| 1.14 s | 被選中的專家亮起，其計數器滾動，容量條與負載平衡隨之移動。 |
| 1.38 – 1.66 s | 輸出沿合併曲線移動；長度不同的曲線會同時抵達。 |
| 1.66 – 1.84 s | 合併後的封包移往輸出端。 |
| 1.84 s | 輸出標籤塊變為該 token，該 token 被標記為已路由。 |

最後一個 token 之後，摘要會說明共路由了多少 token，以及每個 token 只使用了多少參數。

### 計算方式

卡片會一次規劃整個序列，因此在播放之前就能檢視任何 token。每個數字都來自 token 的分數：

- **閘控分數**會正規化為總和為 1。百分比是逐一四捨五入的，因此一對數字加起來可能是 101。
- **選擇**是分數最高的 `TopK` 位專家。分數相同時，排在前面的專家優先。
- **權重**是被選中的分數除以其總和：44% 與 22% 的分數混合比例為 67 比 33。
- **容量**為 ⌈factor × tokens × k ÷ experts⌉ 個 token 每位專家。15 個 token 配 8 位專家，在 top 2 時每位專家容量為 4，在 top 1 時為 2。
- **載入**依順序進行。已滿的被選專家會跳過該 token；它保留其權重，另一位專家不會被拉到 100%。若一個 token 的所有選擇都已滿，它會原樣通過。
- **負載平衡**為負載上的 (E − max ÷ mean) ÷ (E − 1)：所有專家負載相同時為 100%，一位專家接收全部時為 0%。
- **啟用參數**為 shared + k × 每位專家參數：以預設值計，top 1 時為 6 + 12 = 18B，top 2 時為 6 + 24 = 30B。

以預設資料計，top 2 對 15 個 token 產生 28 次指派，因為兩個第二選擇發現其專家已滿，最後的負載平衡為 98%。Top 1 則讓最後一個句號直接通過。

### Top k 與容量

`TopK` 接受 1 或 2，並且是雙向的：標題列的開關會寫入它，應用程式也可以綁定它。變更它會重新規劃每條路由，並從故事的同一個時間點繼續，因此計數器、負載平衡與頁尾會原地變化，讀數也會滾動到新的數字。`CapacityFactor` 會縮放容量；`double.PositiveInfinity` 會關閉容量限制，此時容量條會相對於最忙的專家來填滿。

```xml
<arc:MixtureOfExperts TopK="1" CapacityFactor="1.5" />
```

### 你自己的專家與 token

`Experts` 接受 2 到 12 個 `MixtureOfExpertsExpert` 項目，每個都有 `Name`，可選的 `Handles` 句子（在檢視該專家時顯示），以及可選的 24×24 `Icon` 幾何圖形（若沒有圖示，則以名稱的第一個字母代替）。`Tokens` 接受 `MixtureOfExpertsTokenItem` 項目，包含其 `Text`，以及可選的 `Scores`（每位專家一個原始分數）。沒有分數的 token 會得到由其文字衍生的穩定示例分數：相同的文字永遠以相同的方式路由。`Parameters` 接受總數、shared 與每位專家的數量，單位為十億（B）。

<Demo name="CodeModel" />

```xml
<arc:MixtureOfExperts TopK="1" Parameters="96, 4, 7.5" CapacityFactor="1.25">
    <arc:MixtureOfExperts.Experts>
        <arc:MixtureOfExpertsExpert Name="Keywords" Handles="Reserved words such as if, for and return."
                                    Icon="{x:Static arc:ArcIcons.Code}" />
        <arc:MixtureOfExpertsExpert Name="Names" Handles="Variables, functions and types."
                                    Icon="{x:Static arc:ArcIcons.Hash}" />
        <!-- … -->
    </arc:MixtureOfExperts.Experts>
    <arc:MixtureOfExpertsTokenItem Text="for" Scores="62, 12, 3, 4, 6" />
    <arc:MixtureOfExpertsTokenItem Text=" total" />
</arc:MixtureOfExperts>
```

`Text` 中的空白會被保留，就像 tokenizer 會保留它們一樣。少於兩位專家時會退回預設值，超過第十二位的專家會被省略。變更任一列表都會讓故事重新開始。

### 檢視 token 或專家

將指標停在 token 上，或以鍵盤使其取得焦點，會讓故事停留在目前位置，並一次顯示該 token 的完整路由：它的分數、兩條線、亮起的方塊，以及在它之後的負載。即使該 token 尚未播放也一樣。將指標停在專家上會讓舞台保持原狀，並突顯該專家目前為止接收的 token，依其是第一或第二選擇而著色；頁尾顯示其負載與 `Handles` 句子。移開指標後，故事會從同一個時刻繼續。

單擊、點按、Enter 或 Space 會釘選該 token 或專家：故事會在它上面暫停，播放按鈕則提供繼續的選項。Escape、再次單擊或 `Unpin()` 會釋放釘選，故事繼續播放。`PinToken(index)` 與 `PinExpert(index)` 從程式碼中執行相同的操作；`InspectedTokenIndex` 與 `InspectedExpertIndex` 則回報目前顯示的是哪一個。

### 播放、事件與綁定

每當一個 token 的封包離開路由器時，就會引發 `Routed`，其中包含該 token 的 `Index`、`Token`、正規化的 `Scores`、依最佳排序的被選 `Experts`、它們的 `Weights`，以及已滿而被跳過的 `Dropped` 專家。`Routes` 保存目前設定下的完整計畫；`ActiveParameters`、`Capacity`、`CurrentTokenIndex` 與 `LoadBalance` 則回報顯示時的狀態。以下範例會記錄路由、阻止故事循環、關閉容量限制，並為各選擇使用另外兩個系列色。

<Demo name="RouteLog" />

```csharp
card.Routed += (_, e) =>
{
    var first = e.Experts[0];
    log.Add($"{e.Token} → expert {first} ({e.Weights[0]:P0})");
};
```

`IsPlaying` 是雙向的，因此檢視模型可以在對話方塊開啟時暫停卡片。`Speed` 會縮放故事時鐘，範圍從 0（保持靜止）到 4；卡片本身沒有速度控制項。`FirstChoiceBrush` 與 `SecondChoiceBrush` 會取代選擇的顏色，預設為圖表系列 1 與 2，並隨強調色變化。

### 減少動態效果

在減少動態效果下，卡片會直接顯示摘要，包括最終的負載與平衡。再次按下重新路由，會以每個 token 1.8 秒逐步進行，且沒有任何移動：分數與路由立即出現，專家在 0.6 秒後亮起並計數，輸出在 1.1 秒時變化，故事則停在摘要上，而不是循環。

### 內容指南

以專家通常處理的內容為其命名，名稱為一個簡短的詞（窄版面只顯示其圖示）。`Handles` 則寫成讀者可以對照其所接收 token 來核對的一句平實敘述。真實的專家不會如此整齊；請在卡片周圍的文字中說明這一點。選擇一個混合了各類 token 的句子（名詞、動詞、程式碼、數字、標點），讓路由能明顯地隨 token 而變化。

| 不要寫 | 改寫為 |
|---|---|
| 專家 3 | 數字 |
| 處理高激活度的數字 token | 整數與日期中的數字。 |
| 一段四十個 token 的文字 | 一句十二到二十個 token 的句子 |
| 671B 參數（真實模型的數字） | 你自己的示意數字，並說明它們只是示意 |
| 沒有主題的專家 | 名稱與其所接收 token 相符的專家 |

### 最佳實務

**建議**

- 為承載故事重點的 token 提供分數（那個發現其專家已滿的，以及那個直接通過的），其餘的讓它們自行推導。
- 當故事是關於容量時，保留預設的容量係數：15 個 token 配 8 位專家會產生一到兩次跳過，足以讓人注意到。
- 在周圍的文字中解釋摘要句；它是讀者會引用的部分。
- 讓讀者可以檢視：懸停停留正是他們以自己的步調核對路由的方式。

**避免**

- 把負載、平衡或參數數量當成真實模型的測量值來呈現。
- 在標籤或參數中使用廠商的模型名稱或標誌。
- 超過十二位專家，或非常長的 token 文字；方塊與標籤塊不會為了容納內容而變大。
- 以計時器重建 token 列表：每次變更都會讓故事重新開始。

### 常見問題

**為什麼被跳過的專家會保留其權重？** 這正是真實的層中容量限制的運作方式：token 的輸出是由實際處理它的專家，依路由器給予的權重混合而成。卡片如實顯示這一點，好讓損失可見，而不是悄悄把另一位專家拉到 100%。

**沒有分數的 token，其分數如何決定？** 卡片會對 token 的文字進行雜湊，並從該種子繪製一位最愛、一位次之，以及其餘的小分數。相同的文字永遠得到相同的分數，因此截圖與測試保持穩定。

**故事可以從暫停開始嗎？** 設定 `AutoPlay="False"`；卡片會停在第一個 token，直到 `Play()` 或按下播放按鈕。設定 `IsLooping="False"` 則會停在摘要上。

**懸停會暫停卡片嗎？** 它會在不改變 `IsPlaying` 的情況下停住故事，因此綁定的檢視模型不會看到暫停。釘選則會暫停，播放按鈕隨之提供繼續的選項。

## 無障礙

- 卡片是一個群組，其名稱為 `Title`（預設為「Mixture of experts routing」）。
- 專家方塊與序列 token 是真正的按鈕。每個專家群組與序列各佔一個 Tab 停駐點，方向鍵在其中移動。已釘選的方塊或 token 會回報為已按下的切換狀態。
- Token 的名稱包含其完整路由（「Ada: People 71%, Syntax 29%」，對於已達容量的專家會加上「full, skipped」）。方塊的名稱包含其負載、是否已滿，以及它在目前顯示的路由中所扮演的角色（「Syntax expert, 4 tokens, at capacity, second choice for x」）。
- 讀數與負載平衡會以句子朗讀（「30B of 480B parameters active per token」）；其滾動數字會對螢幕閱讀器隱藏。
- 即時區域只會為讀者自己的操作發出聲音：暫停、繼續、重新開始、釘選與取消釘選，以及 top k 的變更。自動播放的路由不會被宣告。
- 顏色從來不是唯一的訊號：第一選擇會先出現在路由列中，被跳過的專家則有警示標誌、虛線框，以及「full」一詞。

### 鍵盤

| 按鍵 | 動作 |
|---|---|
| `Tab` / `Shift+Tab` | 在 top-k 開關、播放按鈕、專家方塊與 token 序列之間移動 |
| `←` / `→` | 在 top-k 開關中：選擇 top 1 或 top 2 |
| `↓` / `→`、`↑` / `←` | 在方塊或序列中：下一個或上一個（不循環）；使其取得焦點即會檢視 |
| `Home` / `End` | 第一個或最後一個方塊或 token |
| `Enter` / `Space` | 釘選或釋放已取得焦點的方塊或 token；在播放按鈕上：暫停、繼續或重新路由 |
| `Escape` | 釋放釘選（已取得焦點的項目保持檢視，直到焦點移動） |
