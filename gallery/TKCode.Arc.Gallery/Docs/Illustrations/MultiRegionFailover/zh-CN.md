## 何时使用

`MultiRegionFailover` 展示当某个区域发生故障时，服务如何保持可用。它绘制全局流量路径、每个区域及其应用和数据库，以及数据库之间的复制链路，然后播放故障、流量切换、数据库提升和恢复的全过程。它适合放在架构与可靠性页面、运维手册和培训材料中，让读者知道在任何时刻由哪个区域提供流量、哪个数据库接受写入。

- **支付或账单 API 的可靠性页面**：解释为什么在 `us-east-1` 故障时结账仍能继续。主区域提供流量，`eu-west-1` 持有一个被提升的副本，说明文字描述处理中的请求会发生什么。
- **游戏日之前的运维手册演练**：团队使用手动控制项演练订单数据库的故障转移，所用的状态机与图示相同，然后才在生产环境中执行真正的流程。
- **多区域部署的架构评审**：一份设计文档比较双区域主备布局与三区域布局，并使用 `Regions` 属性展示每种方案。
- **值班工程师的入门说明**：简短解释“提升”和“副本”对团队自己的数据库意味着什么，并放在他们将要执行的运维手册步骤旁边。
- **数据驻留功能的客户文档**：说明数据在哪里复制、由哪个区域接管，并使用客户合同中的区域名称。

## 何时不用

- **通知真实服务中断**：使用 `Alert`，填写实际的状态文字和事故发生时间。图示播放的是固定的故事，绝不能替代生产环境的真实状态。
- **单个区域或单台服务器**：故事需要两到三个区域才能说明问题。只涉及一个位置时，使用带纯文字的 `Card`，或用事故的 `Timeline`。
- **真实的可用性、延迟或错误率**：使用 `LineChart` 或 `Gauge` 并填入实测值。插图展示的是故障转移的形态，而不是你的故障转移用时多久。
- **每个区域的实时健康视图**：使用 `DataGrid` 或由 `Badge` 组成的列表，展示健康检查结果。十个区域或十几项健康检查无法放进三区域的外框中。
- **需要人员逐步执行的流程**：运维手册的步骤使用 `Stepper`，并在旁边链接该图示。插图会自行循环，无法等待操作员确认某一步。

## 用法

默认情况下故事会自动播放：某个区域未通过健康检查，流量和主数据库切换到备用区域，故障区域恢复为副本，流量最终回到原定区域。该控制项无需数据，也无需代码即可运行。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:MultiRegionFailover />
</UserControl>
```

`MultiRegionFailover` 派生自 `Illustration`，而 `Illustration` 派生自 Avalonia 的 `TemplatedControl`。它可获得焦点，拥有供辅助技术使用的 `Label`，并与其他系统插图使用相同的外框、播放按钮和说明文字。控制项为每个区域保留一个小型状态机：健康、降级、故障或恢复中。图示中每一次可见的变化都是该状态机的一次转换，因此图示永远不会展示代码无法到达的状态。

### 结构

1. **用户**（`Labels.Users`、`Labels.UsersDetail`）：左上角的流量来源，150 × 52 场景单位。
2. **全局负载均衡器**（`Labels.Balancer`、`Labels.BalancerDetail`）：顶部中央较宽的卡片，170 × 52 单位，带有来自用户的流量路径。旁边的读数显示接收流量的区域（`Labels.ServedBy`），切换期间还显示故障转移用时（`Labels.FailoverTime`）。
3. **区域外框**：场景下部按区域名称排列的两到三组。每个外框都有一个健康指示点、一个标题和一个状态词（`Labels.Healthy`、`Labels.Degraded`、`Labels.Down` 或 `Labels.Recovering`），绘制在连线之上，因此线条永远不会穿过文字。
4. **应用**（`Labels.App`、`Labels.AppDetail`）：每个区域中的服务，带有来自负载均衡器的流量连线。
5. **数据库**（`Labels.Database`，以及读作 `Labels.Primary`、`Labels.Replica`、`Labels.Unavailable` 或“副本 · 正在追赶”的副标题）：每个区域中的数据存储，并通过一条连线与应用相连。
6. **复制链路**：按 `Regions` 列表顺序在相邻数据库之间绘制的虚线。变更以绿色数据包的形式沿其传输。
7. **标示**：切换期间在负载均衡器上显示“切换中”标示，在成为主库的数据库上显示“已升为主库”标示。标示文字来自 `Labels.FailingOver`、`Labels.Promoted` 和 `Labels.Primary`。
8. **说明行**（`IsCaptionVisible`）与**播放按钮**（`IsPlaybackButtonVisible`）：与其他插图相同的控件。按钮在静态画面中隐藏。

场景为 844 × 356 单位，并按控制项给定的宽度缩放。外框在两侧和顶部保留 20 px 内边距，底部保留 14 px，节点使用令牌中的 12 px 圆角。

健康状态以三种色调显示：降级的区域变为警告色，故障的区域变为危险色且其数据包被丢弃，恢复的区域则回到成功色。

### 区域

`Regions` 接受两到三个区域名称。少于两个名称的列表会回退为默认区域（`us-east-1`、`eu-west-1` 和 `ap-southeast-1`），超过三个名称的列表只取前三个。区域外框平均分配场景宽度，因此两个区域的外框比三个区域的更宽。

<Demo name="TwoRegions" />

列表中的第一个区域初始为主区域，第二个为备用区域。在双区域情况下，主区域的每次故障都会把流量和主库转移到另一个区域，故障转移是故事唯一能走的路径。在三区域情况下，故障转移会指向列表中下一个健康的区域，到达末尾时回绕，因此列表的顺序就是优先级顺序。应将应优先接管的区域放在主区域的紧后面。

### 自行驱动故障

将 `IsAutomatic` 设为 `False` 以停止脚本化的故事，然后用区域的索引调用 `FailRegion` 和 `RecoverRegion`。每次调用都会运行与自动故事相同的状态机，因此图示与读数的表现一致。

- `FailRegion(index)` 使某个区域故障。若索引超出范围，或该区域已处于降级或故障状态，则忽略该调用。
- `RecoverRegion(index)` 使某个区域恢复。若索引超出范围，或该区域已处于健康或恢复中状态，则忽略该调用。
- `PrimaryRegion` 是主库所在区域的索引，`TrafficRegion` 是接收流量的区域的索引。两者均为只读。
- `PrimaryRegionChanged` 在提升完成后以新主库的索引触发。持有主库角色的区域以外的区域故障时，不会触发该事件。

<Demo name="DriveItYourself" />

```csharp
var failover = new MultiRegionFailover { IsAutomatic = false };
var regionNames = new[] { "us-east-1", "eu-west-1", "ap-southeast-1" };

failover.PrimaryRegionChanged += (_, index) =>
    primaryLabel.Text = $"主库：{regionNames[index]}";

failButton.Click += (_, _) => failover.FailRegion(0);
recoverButton.Click += (_, _) => failover.RecoverRegion(0);
```

故障是一个序列，而不是一次性的变化。发生故障的区域先显示 0.8 秒的降级状态，随后变为故障状态。如果它承载了流量或主库，负载均衡器会在 0.5 秒后切换到下一个健康的区域；如果它承载了主数据库，则下一个健康区域的数据库会在此之后 0.7 秒被提升。故障转移用时读数从故障发生开始计时，直到流量切换为止。这些时间均为场景时间，因此暂停的插图在再次播放时会继续完成整个序列。

使用这些控制项来演练故障。按照动作和区域命名，例如“让 us-east-1 故障”和“恢复 us-east-1”，这样每个按钮对屏幕阅读器和阅读页面的操作员来说都很清楚。

### 标签

`Labels` 接受一个 `MultiRegionFailoverLabels` 对象，其中包含图示中每一个可见的文字：节点名称与详细信息、健康状态、标示以及步骤说明文字。只设置需要的属性即可，但要让步骤说明文字的措辞与运维手册保持一致，因为在故事播放期间，说明文字是读者看到的唯一解释。

```csharp
failover.Labels = new MultiRegionFailoverLabels
{
    Balancer = "全局负载均衡",
    FailingOver = "切换中",
    Promoted = "已升为主库"
};
```

### 播放

`IsPlaying`、`Speed` 和 `Restart()` 与其他插图一样控制故事。`Speed` 的取值范围为 0.25 到 4。自动故事共六步，`StepChanged` 会报告每一步：

| 步骤 | 说明文字 | 发生时机（自动故事） |
|---|---|---|
| 0 | 流量由计划区域提供；数据复制到备用区域 | 开始 |
| 1 | 某个区域未通过健康检查 | 3.0 s 时，该区域故障 |
| 2 | 负载均衡器将流量切换到下一个健康区域 | 故障后约 1.3 s |
| 3 | 备用数据库被提升为主库 | 故障后约 2.0 s |
| 4 | 故障区域恢复，并以副本身份追赶数据 | 8.6 s 时，该区域恢复 |
| 5 | 计划内回切到原区域 | 11.8 s；循环长 14.4 s |

故事以计划内的回切结束，流量和主库会被移回第一个区域。手动控制项不会自行回切；请参阅下方的常见问题。

```xml
<arc:MultiRegionFailover Speed="2" />
```

### 减弱动效

在减弱动效（或关闭动效）下，插图是健康部署的静态画面。流量由第一个区域提供，备用复制链路以虚线绘制，说明文字概括整个部署。播放按钮隐藏。当读者需要了解拓扑结构而不需要了解故障序列时，请使用该静态画面。

### 由代码驱动

该控制项演示的是一个状态机，而不是基础设施的读取工具。用它来展示已经发生的故障转移，或者你想要演练的故障转移，并将真实状态保存在你的监控系统中。一个合理的做法是把插图放在解释设计的页面上，并像上面的示例那样由操作员自己的控制项驱动它。不要把健康检查数据直接接入 `FailRegion`：那样控制项就会播放一次由数据源报告的故障动画，却没有真实故障转移中的任何检查、超时和审批。

### 示例：支付平台可靠性页面

一个账单服务的可靠性页面。区域是该服务实际运行的区域，负载均衡器使用基础设施团队惯用的简称命名，数据库和应用的标签描述它们在架构中的角色。说明文字解释读者在故事播放时看到的内容，因此页面不依赖动画本身。

![三区域部署，包含全局负载均衡器，以及位于 us-east-1 的主数据库](images/PaymentsRegions.png)

```xml
<StackPanel Width="760" Spacing="16">
    <TextBlock Text="How billing stays available"
               FontSize="16"
               FontWeight="SemiBold"
               Foreground="{arc:ArcDesignTokenResource Foreground}" />
    <TextBlock Text="Requests are served from the primary region. When it fails, traffic and the primary database move to the next healthy region."
               TextWrapping="Wrap"
               Foreground="{arc:ArcDesignTokenResource TextSecondary}" />
    <arc:MultiRegionFailover Label="Billing service failover across three regions">
        <arc:MultiRegionFailover.Labels>
            <arc:MultiRegionFailoverLabels Users="Customers"
                                           UsersDetail="worldwide"

                                           Database="Ledger DB"
                                           FailingOver="Failing over" />
```

标签刻意保持简短：负载均衡器卡片比区域卡片窄，过长的标题会被省略号截断。修改标签后请检查截图。

### 文案规范

按基础设施中的名称命名区域，并使用团队运维手册中的词语命名数据库角色（主库、副本）。将负载均衡器写成组件的职责（“全局负载均衡器”“流量管理器”），而不是产品名称，除非页面本身就是关于该产品的。说明文字使用现在时，描述状态而不是团队的响应（“流量由 eu-west-1 提供”，而不是“我们已切换流量”）。

| 不要写 | 改为 |
|---|---|
| 所有区域均高可用 | us-east-1 故障期间，流量由 eu-west-1 提供 |
| 区域 1 | us-east-1 |
| 主数据库（Master DB） | 主数据库 |
| 从库（Slave） | 副本 |
| 故障转移完成 | 流量由 eu-west-1 提供 |
| 系统会自我修复 | 故障区域恢复，并以副本身份追赶数据 |

不要在标签中承诺故障转移用时。故障转移读数是图示所用的时间，面向客户的说法必须来自你自己的测量，并写在图示旁边。

### 最佳实践

**推荐**

- 展示与生产部署相同的区域。如果读数中出现服务并不运行的区域，就会传达错误的拓扑，而读者无法分辨其中的差异。
- 按优先级顺序在 `Regions` 列表中排列故障转移的顺序，并在页面上说明这一点，因为列表中下一个健康的区域会接收流量。
- 在运维手册页面上使用 `IsAutomatic="False"` 配合真实的按钮，让操作员决定每一步何时发生。
- 在图示旁边用文字提供状态。辅助技术不会朗读说明文字的变化，因此页面必须用文字说明当前的情况。

**避免**

- 把图示当作真实服务的状态。循环播放的故事会展示一个可能并不存在的故障。真实状态请使用 `Alert`。
- 用你尚未测量的数值为读数加上标签。故障转移用时是场景时间，而不是基准测试结果。
- 在解释某次具体事故的页面上保留自动故事。故事会循环播放，暗示事故仍在发生。
- 将实时健康数据源接入 `FailRegion` 或 `RecoverRegion`。这些调用只会驱动状态机的动画，不会移动任何真实流量，因此图示可能与生产环境不一致。

### 常见问题

**如何停止自动故事并自行驱动故障？** 将 `IsAutomatic` 设为 `False`。脚本化的故障、恢复和回切都会停止，状态只在你调用 `FailRegion` 或 `RecoverRegion` 时才会变化。修改 `IsAutomatic` 会重建图示，因此应在页面显示控制项之前设置它。

**为什么故障转移用时与我的监控告警时间不同？** 该读数是从调用 `FailRegion` 到流量切换之间的场景时间。它描述的是图示的序列，其中使用固定的延迟（0.8 秒和 0.5 秒），并不是对你系统的测量。

**恢复会把流量切回去吗？** 不会。`RecoverRegion` 会使该区域以副本身份恢复并追赶数据，但流量和主库角色仍停留在故障转移之后的位置。只有自动故事会执行计划内的回切。流量会一直停留在已提升的区域，直到该区域故障为止。

**如果没有其他健康的区域，会发生什么？** 故障区域保留流量和主库。故障转移不会开始，因此 `TrafficRegion` 与 `PrimaryRegion` 不会改变，`PrimaryRegionChanged` 也不会触发。

**复制遵循哪些区域之间的关系？** 复制在相邻数据库之间进行，顺序取决于 `Regions` 列表，每次只跨一跳。位于故障区域之后的备用区域在故障区域恢复之前不会收到任何数据，而恢复的区域会从主库接收一小批追赶变更。

## 无障碍

- `Label` 是插图的无障碍名称。请在其中为部署命名，例如“跨三个区域的账单服务故障转移”。
- 插图可获得焦点，获得焦点时外框周围会显示 2px 焦点环。
- 当前的说明文字会作为帮助文本提供，因此控制项获得焦点时，屏幕阅读器会朗读该步骤的含义。
- 说明文字的变化不会被播报，因为故事会循环播放，否则会无休止地重复同一条消息。
- 区域名称、健康状态和标示就是图示的文字。请让它们脱离动画也能被理解，因为看不到动画的读者仍能从标签中获得拓扑信息。
- 手动控制项必须是真正的按钮，并带有各自的名称，例如“让 us-east-1 故障”。只标为“故障”的按钮无法说明它影响的是哪个区域。
- 在减弱动效下，静态画面展示健康的拓扑结构及概要说明文字，因此在没有任何动作的情况下状态依然清晰。

### 键盘

插图可通过 Tab 键获得焦点。获得焦点后，以下按键控制自动故事：

| 按键 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 将焦点移入或移出插图 |
| `Space` 或 `Enter` | 播放或暂停故事 |
| `R` | 从健康状态重新开始故事 |

键盘本身不能使区域故障或恢复。请为此提供按钮，并以与页面其余部分相同的方式让它们可通过键盘访问。

## 动效

- 故障区域先变为琥珀色，再变为红色，发往该区域的传输中数据包会被丢弃。
- 负载均衡器带着“切换中”标示将流量切换到健康区域，读数显示切换所用的时间。
- 备用数据库以“已升为主库”标示被提升，复制从新主库开始。
- 恢复阶段显示该区域以副本身份追赶数据，随后在自动故事中进行计划内的回切。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 区域故障 | 外框先变为警告色，再变为危险色；其数据包淡出，连线变暗 | 以健康的稳定状态显示 | 以稳定状态显示 |
| 流量切换到另一个区域 | 流量连线在 0.4 s 内交叉淡化；切换期间显示故障转移标示 | 不显示 | 不显示 |
| 数据库被提升 | “已升为主库”标示弹出；复制连线从新主库开始运行 | 不显示 | 不显示 |
| 区域恢复 | 追赶变更突发之后，外框回到成功色 | 不显示 | 不显示 |
| 播放按钮 | 可见；切换播放状态 | 隐藏 | 隐藏 |

## 相关组件

- `PaymentFlow`：依赖支付服务可用的单笔请求。
- `DataFlow`：将事件存入单一数据仓库的管线。
- `Alert`：以文字说明真实服务的状态。

| 组件 | 适用场景 |
|---|---|
| `Alert` | 你要以文字说明真实服务或事故的状态 |
| `Stepper` | 运维手册的步骤是操作员依次经过的序列 |
| `Timeline` | 你要按顺序并带时间地展示真实事故中发生的事 |
| `LineChart` / `Gauge` | 你要绘制实测的可用性、延迟或错误率 |
| `DataGrid` | 你要以表格列出每个区域或每项检查的健康状况 |
| `PaymentFlow` | 故事是依赖该服务的一笔支付请求 |
| `DataFlow` | 故事是事件从来源流向数据仓库 |
