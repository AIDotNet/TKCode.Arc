## 何時使用

`PromptCache` 以一段簡短的模擬故事說明提示快取。一輪最多四個請求共用同一段穩定的前綴（工具結構描述、指示、文件、目前的對話），每個請求在結尾加上一則新訊息。第一個請求會處理整段提示並儲存前綴；之後的請求讀回前綴，只處理自己的訊息。卡片會累計這些做法對輸入成本，以及第一個輸出 token 出現前等待時間的影響。它是一個附有模擬時鐘與範例價格的教學插圖，而不是真實快取的監控工具。

- **API 與 SDK 文件**：介紹快取斷點或快取輸入計價的頁面。各列說明為何穩定的前綴很重要，讓讀者在寫任何程式碼之前就能理解。
- **計價與用量頁面**：說明快取流量背後三種價格（輸入、快取寫入、快取讀取）與存活時間的段落。傳入你自己的價格，總計會隨之更新。
- **AI 產品的導覽流程**：首次執行時解釋提示的順序為何重要，並以變更切換器展示：提示前段的修改，比末段的修改成本更高。
- **工程文章與內部培訓**：關於延遲的演講或文章，其中第一個 token 的加速倍數是聽眾最容易記住的數字。

## 何時不用

- **回報真實的快取命中率**：請使用 `LineChart` 或 `BarChart`，搭配你遙測資料中的數字。本卡片中的每個數字，都是由你提供的範例資料計算而來。
- **顯示配額用量比例**：使用 `UsageMeter`。它顯示的是某個上限的真實比例；本卡片講的是一個故事。
- **列出真實請求及其成本**：使用 `DataGrid`，並填入你日誌中的資料列。
- **說明其他推論概念**：`SpeculativeDecoding` 說明草稿與驗證，`AgentLoop` 說明代理的上下文、動作與檢查循環。

## 用法

卡片不需要資料：它內建自己的故事，講的是一家貨運公司的支援助理，其四個問題共用一段 45.5K token 的前綴。卡片第一次大部分可見時開始播放，並循環播放。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:PromptCache MaxWidth="744" />
</UserControl>
```

`PromptCache` 衍生自 `Explainer`，這是 Special 講解插圖的基底類別，提供故事時鐘、播放、單步與重新開始按鈕、即時區域與減少動態效果。卡片依自身的寬度進行版面配置，因此請給予它所在欄位的寬度；744px 能讓請求與快取並排顯示。

### 結構

1. **標題列**：標題（`Title`，預設為 "Prompt cache"）、模型列（來自 `Model` 的標記與名稱，接著是存活時間 "5-minute cache"），以及三個圓形按鈕：播放或暫停、送出下一個請求、重新開始。
2. **圖例**：每個前綴段落的顏色與 token 數，最後是新訊息。
3. **請求**：每個請求一列。列標題顯示 "Request N"、送出的模擬時間與狀態；其下是提示的長條；最右邊是三個數字：已處理的 token 數、輸入成本與第一個 token 的時間。各列上方有兩個鍵說明，分辨實心的已處理填色與淺色的快取填色。
4. **快取面板**：一個圓環，顯示剩餘的存活時間；快取狀態（Empty、Writing、Reading、"Expires in 4:22" 或 Expired）；已快取內容的長條；已快取的 token 數與三種價格。
5. **說明文字**：一到兩句，說明剛才發生了什麼。
6. **頁尾**：本輪的輸入成本，與沒有快取時相同提示的成本相比；命中時的第一個 token 加速倍數；以及變更切換器。

長條採用平方根刻度，因此 200 token 的訊息與 33,800 token 的知識庫並排時，仍清楚可見；圖例與數字則提供真實的計數。

### 故事流程

全動態下，一輪約需十秒：

1. **請求 1 寫入。** 沒有任何內容被快取，因此整段提示都要處理：每個段落依序以一致的速度填滿，然後是新訊息。前綴會從列中升起，飛入快取面板，途中由實心顏色轉為淺色的快取色調。圓環開始填滿，存活時間的倒數也隨之開始。
2. **請求 2 至 4 命中。** 模擬時鐘依請求之間的間隔前進，圓環也隨之稍微消退。前綴轉為快取色調，同時一道光帶掃過（也掃過面板上的長條）；只有訊息會被處理，圓環重新填滿：每次命中都會重設存活時間。
3. **數字從上一列滾動過來。** 每一列的三個數字都從上一列的數值開始，因此你能看到命中時成本與第一個 token 時間的下降。
4. **快取閒置並過期。** 沒有更多請求時，時鐘會加速，圓環消退，最後一分鐘轉為警告色，然後清空。循環的卡片會以已寫入的第一個請求開始下一輪；若 `IsLooping="False"`，卡片則會停在已過期的快取上。

卡片中的所有數字都是示意性的：它們依你傳入的價格、token 數與第一個 token 的估算推算而來，而非來自真實模型。

### 計算方式

以 `P` 代表前綴 token 數、`m` 代表訊息 token 數，以及每個 token 的三種價格：

| 結果 | 從快取讀取 | 寫入快取 | 處理 | 輸入成本 |
|---|---|---|---|---|
| 寫入（沒有快取，或快取已過期） | 0 | `P` | `P + m` | `P × write + m × input` |
| 命中 | `P` | 0 | `m` | `P × read + m × input` |
| 在段落 `k` 部分命中 | 段落 `k` 之前的各段 | 從 `k` 起的各段 | 寫入量 + `m` | 快取量 × read + 寫入量 × write + `m` × input |

請求的未快取成本為 `(P + m) × input`。成本統計比較的是本輪的總計：以內建故事來看，第一次寫入的成本為 $0.1712，沒有快取時為 $0.1371（高出 25%）；三次命中之後，本輪成本為 $0.2147，沒有快取時為 $0.5491（低 61%）。加速倍數只平均快取命中的第一個 token，並與沒有快取時相比：0.48s 對 1.42s，2.9x。寫入與部分命中不計入其中。

### 自己的前綴與請求

依提示順序，以 `PromptCacheSegment` 項目填入 `Segments`（一個 id、一個標籤、一個 token 數，以及選用的 `Color`），並以最多四個 `PromptCacheRequest` 項目填入 `Requests`（新訊息的 token 數、相對於前一個請求的模擬 `Gap`（秒），以及一個 `Message`，它會被朗讀出來並傳入結果）。清單為空時，卡片使用內建故事。若要改為繫結，請設定 `SegmentsSource` 與 `RequestsSource`。

<Demo name="CodeReview" />

```xml
<arc:PromptCache Title="Review bot cache" Ttl="3600" ChangeSegmentId="style">
    <arc:PromptCache.Model>
        <arc:ExplainerModel Name="Quill 2 Mini" />
    </arc:PromptCache.Model>
    <arc:PromptCache.Pricing>
        <arc:PromptCachePricing InputPrice="1.20" CacheWritePrice="2.40" CacheReadPrice="0.12" />
    </arc:PromptCache.Pricing>
    <arc:PromptCache.Segments>
        <arc:PromptCacheSegment Id="repo" Label="Repository map" Tokens="7400" />
        <arc:PromptCacheSegment Id="style" Label="Style guide" Tokens="1800" />
        <arc:PromptCacheSegment Id="diff" Label="Open diff" Tokens="21500" />
    </arc:PromptCache.Segments>
    <arc:PromptCache.Requests>
        <arc:PromptCacheRequest Message="Flag any unchecked null returns in the parser" Tokens="140" />
        <arc:PromptCacheRequest Message="Suggest a clearer name for the retry helper" Tokens="90" Gap="64" />
        <arc:PromptCacheRequest Message="Does the new migration need a rollback step?" Tokens="210" Gap="118" />
    </arc:PromptCache.Requests>
</arc:PromptCache>
```

未設定顏色的段落會依 3、2、4、1 的順序取用圖表系列色，因此會跟隨主題與強調色。變更資料會重建故事並從頭開始，所以請設定一次，而不要每次重新整理都設定。

### 價格與首個 token

`Pricing` 接受一個 `PromptCachePricing`，以每百萬 token 的美元計價。預設值是常見模式的範例價格：輸入 $3.00，快取寫入為輸入的 1.25 倍（$3.75），快取讀取為十分之一（$0.30）。若你的供應商寫入不另外收費，請將 `CacheWritePrice` 設為與 `InputPrice` 相同。`Ttl` 是以模擬秒數計的存活時間（預設 300）；它驅動圓環、倒數與標題的註記。

`FirstTokenEstimator` 依已處理與已快取的 token 數，回傳到第一個輸出 token 的秒數。預設值是一個示意模型，`0.40 + processed / 45,000 + cached / 600,000`：固定的額外開銷、新 token 的預填，以及快取 token 便宜得多的載入。若你已有自己的量測值，請傳入。

```csharp
cache.FirstTokenEstimator = (processed, cached) => 0.25 + processed / 60_000.0 + cached / 900_000.0;
```

### 變更切換

統計數字下方的切換器會編輯一個段落，即 `ChangeSegmentId`（預設為 "rules"，也就是指示）。切換器啟動（`IsChangeArmed`）時，下一個請求只會比對快取到該段落為止：前面的段落會被讀取，一行警告文字標示斷點，而該段落及其之後的內容會重新處理並寫入。該請求送出後切換器即解除，下一個請求會命中重寫後的快取。若修改的是第一個段落，比對會在任何內容之前就中斷，因此屬於單純的寫入。將 `ChangeSegmentId` 設為 null（或設為沒有任何段落使用的 id），即可隱藏切換器。

### 播放、單步與事件

`IsPlaying`、`Speed`（0 到 4；0 表示靜止）、`Play()`、`Pause()` 與 `Restart()` 來自 `Explainer`。單步按鈕（"Send the next request"，即 `StepForward()`）會暫停故事，並且只送出一個請求：之前的暫停會被略過，進行中的請求會完成；若一輪已經結束，則會開始新的一輪，其第一個請求在快取仍溫熱時會命中。重新開始會清空快取，並保留播放狀態，因此暫停中的卡片會停在起點並維持暫停。

`RequestCompleted` 會以 `PromptCacheResult` 回報每個已完成的請求：其索引、模擬時間、類型、斷點、已快取、已寫入與已處理的 token 數、有與沒有快取時的成本、有與沒有快取時的第一個 token 時間、是否被編輯或為冷寫入，以及其訊息。`Expired` 會在快取每次耗盡時觸發。`Results` 保存本輪目前的結果，`CacheState` 則說明快取目前的狀態。

<Demo name="EventLog" />

```csharp
cache.RequestCompleted += (_, e) =>
    log.Add($"{e.Result.Kind}: {e.Result.Cost:C4} instead of {e.Result.UncachedCost:C4}");
cache.Expired += (_, _) => log.Add("The cache expired.");
```

### 窄容器

版面配置依卡片的內容寬度而定，而非視窗寬度。寬度達 660px 時，快取面板與請求並排；低於此寬度時，它會變成位於請求上方的一條狀列，因此流動動畫仍能從某一列行進到快取。低於 480px 時，每個請求佔三行（標題與狀態、長條，然後是共用標題下方的三個數字），統計數字會堆疊排列，切換器則橫跨整張卡片。低於 260px 時，播放按鈕會移到標題下方。

### 減少動態效果

在減少動態效果下，卡片會以一輪已完成的狀態開啟並等待。播放與單步仍可使用，但每個變化都會立即套用：沒有掃過效果、沒有光帶、沒有飛行動畫、沒有滾動數字，也沒有加速的消退。一輪結束後快取會過期；循環的卡片則會稍後開始新的一輪。

### 文案規範

以提示中的內容為段落命名，並保持標籤簡短；它們會出現在圖例、切換器與說明文字中（"Edit the style guide"）。順序要符合實際：變動最少的內容放在最前面。將訊息寫成使用者會提出的問題，因為它們會被螢幕閱讀器朗讀。

| 不要寫 | 改為 |
|---|---|
| 段落 1 | 工具結構描述 |
| 系統 | 指示 |
| 大型上下文 | 知識庫 |
| 問題 3 | 比較試算表中的兩份貨運報價 |
| 少 $0.1 | （讓卡片自行計算成本） |

### 最佳做法

**建議**

- 使用你所描述模型的 token 數與價格，讓總計能告訴讀者關於該模型的真實資訊。
- 讓間隔短於存活時間，除非你想在一輪中間展示一次冷寫入。
- 利用變更切換器說明提示順序的重點：提示前段的修改，幾乎會改寫所有內容。
- 在卡片附近說明數字僅供示意。

**避免**

- 將即時流量餵給卡片。它一次只模擬一輪；真實的量測應放在圖表中。
- 超過四個請求：卡片只顯示一輪的前四個。
- 以計時器變更資料；每次變更都會讓故事從頭開始。

### 常見問題

**為什麼第一個請求的成本比沒有快取時還高？** 寫入快取的成本比一般輸入高（以範例價格計為 1.25 倍），因此第一次寫入較昂貴。命中會把成本賺回來；在那之前，成本統計會顯示 "higher"。

**為什麼加速倍數忽略部分命中？** 它比較的是快取命中與沒有快取的相同提示。部分命中會重新處理大部分的提示，若把它計入，就會掩蓋快取命中實際的效果。

**卡片能顯示我的真實快取嗎？** 不能。使用 `RequestCompleted` 來查看模擬計算的結果，真實數字請用圖表呈現。

## 無障礙

- 卡片以其標題命名，並標示為模擬（"Prompt cache, a simulation with sample prices"）。
- 圖例、請求與快取面板都是具名群組。每個請求列會被讀成一句完整的句子，包含時間、訊息、結果、從快取讀取的 token 數、已處理的 token 數、成本與第一個 token 的時間（執行前為 "Request 1: not sent yet."）；長條與滾動數字對輔助技術隱藏。
- 單步、切換器、暫停與重新開始會在禮貌的即時區域中播報；故事自行播放時保持靜默。
- 結果從不只依賴顏色：每個狀態都搭配圖示與文字，實心與快取的填色在色調與外框上也有所不同。
- 切換器是切換按鈕，會回報是否已啟動；圖示按鈕都有名稱與提示。

## 動態效果

所有故事動畫都在講解插圖的時鐘上執行，因此暫停會凍結全部動畫（包括進行中的掃過效果），而 `Speed` 會縮放所有動畫。

| 變化 | 完整 | 減少與關閉 |
|---|---|---|
| 處理 | 每個段落依序以一致的速度填滿（完整長條需 1.1 秒），然後是訊息，耗時 120 毫秒 | 立即填滿 |
| 快取命中 | 快取色調在 160 毫秒內淡入；光帶在 520 毫秒內掃過前綴與面板長條 | 立即顯示色調，沒有光帶 |
| 寫入 | 寫入的部分在 460 毫秒內以強烈的緩出效果飛入快取面板，實心逐漸淡為色調 | 面板立即填滿 |
| 部分命中 | 警告線在變更段落之前的間隙中升起（200 毫秒）；面板移除已變更的內容 | 立即顯示警告線 |
| 數字 | 在 420 毫秒內（緩出）從上一列滾動過來 | 立即變更 |
| 圓環 | 以短暫的延遲跟隨目標值；最後一分鐘轉為警告色 | 直接到達目標值 |
| 模擬間隔 | 以 0.55 秒的 S 型曲線經過 | 立即經過 |
| 閒置 | 存活時間在約 4.2 秒內消退，然後快取過期 | 暫停後過期 |
| 狀態與說明文字 | 交叉淡化（淡入 160 毫秒、淡出 100 毫秒） | 短暫的交叉淡化 |
