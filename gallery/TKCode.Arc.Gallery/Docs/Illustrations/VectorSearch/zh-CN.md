## 何时使用

`VectorSearch` 是语义搜索的动画插图。它逐字输入一个问题，将其转换为向量，把它放在文档向量的地图上，并把离它最近的文档作为排好名次的答案列出。将它放在解释搜索功能的文字旁边，读者就能看到：为什么一个与文档没有任何相同词语的问题，仍然能匹配到这篇答案。

- **账单产品的帮助中心首页**：访客问“为什么我被扣了两次费”，看到关于重复付款的文章排在第一，尽管措辞并不相同。这张图在访客使用真正的搜索框之前就先建立了预期。
- **AI 辅助客服控制台的新手引导**：新的客服人员看到助手如何选择推荐的文章，从而建立对排名的信任，并理解为什么换一种问法会改变答案。
- **数据分析工作区的产品导览**：介绍“用自然语言提问你的数据”的导览步骤，展示一个普通问题如何找到与之相关的已保存报表。
- **搜索功能的开发者文档**：一篇关于嵌入、余弦相似度和 top-k 结果的教程，用实时地图和排名列表作为旁边文字的参考图。
- **知识库作者培训**：排名列表及其相似度分数向作者展示哪些标题和关键词能够匹配，使他们可以改进排名靠后的文章。

## 何时不用

- **回答真实客户的问题**：内置索引使用哈希词与字符三元组，而不是经过训练的模型，因此它只是教学工具。请使用你自己的搜索服务，并用 `SearchField` 展示其结果。
- **精确查找或带筛选条件的查找**：发票号、订单 ID 或日期范围需要带筛选的精确索引。请使用 `SearchField` 进行普通查询，而不是相似度排名。
- **绘制真实测量值**：地图是文本相似度的二维投影，没有单位和坐标轴。对于人们需要比较的数值，请使用 `LineChart` 或 `BarChart`。
- **人们据此采取行动的长结果列表**：排名、分数与文档元数据以列的形式呈现时，更便于在 `SortableDataTable` 中浏览、排序和导出。
- **讲解流水线而非搜索**：当图片应展示文档如何被收集、校验和存储时，请使用 `DataFlow`，它正是为这类叙述而设计的。
- **信息密集的仪表板，或包含多个动画图片的页面**：每个插图在播放时都会每一帧重绘其画布。请改用 `Card` 配合简短的静态说明。

## 用法

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:VectorSearch />
</UserControl>
```

`VectorSearch` 派生自 `Illustration`，而 `Illustration` 派生自 `TemplatedControl`。基类在场景时钟上循环播放故事，为控件提供焦点，添加播放与暂停按钮以及说明文字行，并在故事于四个步骤之间推进时触发 `StepChanged`。当控件位于屏幕之外、被隐藏或已从视觉树中分离时，时钟会暂停，因此位于首屏以下的故事在滚动进入视野之前不会消耗任何资源。`VectorSearch` 则负责搜索本身：它为文档构建内存中的索引，嵌入每个问题，按余弦相似度对文档排序并绘制结果。默认故事会循环三个示例问题，因此一个控件就能展示从问题到答案的完整过程。

### 结构

图示绘制在一块画布上，画布会按控件所给的宽度缩放，因此下列比例在任何尺寸下都成立。外框的内边距在两侧和顶部为 20 px，底部为 14 px。

1. **查询框**（运行时为 `Query`）：左上角的问题，逐字符输入并带有光标。
2. **嵌入模型节点**（`Labels.Model`，其下方为 `Labels.ModelDetail`）：带有大脑图标的卡片。模型处理问题时，它会显示忙碌环。
3. **向量条**：16 个单元格，以整个向量的固定投影来显示问题的向量。单元格根据查询的真实嵌入填充，因此同一个问题总是以相同方式填充。
4. **文档地图**：每个文档是一个点，按其 `Topic` 分组，主题名称以淡色绘制在组内。查询是一个点，放置在其最近的文档之间，并有一个环延伸到最远的答案。
5. **结果列表**：标题（`Labels.Header`，默认为 "Top 3 · cosine similarity"），之后每个答案一行，包含排名、标题、保留两位小数的相似度分数以及一条条形图。在一行中放不下的标题会以省略号截断，保持单行显示。
6. **说明文字行**（`Caption`）：图示下方一行，使用次要文字颜色和小号字体，说明当前步骤。使用 `IsCaptionVisible="False"` 可将其隐藏。
7. **播放按钮**（`IsPlaybackButtonVisible`）：位于右下角、直径 28 px 的幽灵圆形按钮，在播放与暂停图标之间切换。静态画面下它会隐藏。
8. **外框**：Surface 卡片，带有 1 px 的边框线、表面圆角以及点状背景。当控件获得键盘焦点时，外框周围会出现焦点色的 2 px 焦点环。

节点卡片的圆角为 12 px。所有颜色都来自 ArcDesign 令牌（表面、边框、文字、强调色与状态色），因此该控件无需任何颜色设置即可跟随浅色与深色主题。

### 答案数量

`TopK` 设置列表显示的答案数量。该值被限制在 1 到 5 之间，默认为 3。列表始终是最佳答案排在最前，地图会把环画到最远的答案，并限制在 110 个场景单位内，以免一个离群值占满整张地图。

```xml
<arc:VectorSearch TopK="4" />
```

在帮助页面上使用 3。它适合阅读栏的宽度，最佳匹配会从其余答案中脱颖而出。只有当列表本身就是讲解的重点时才使用 5，因为每增加一个答案，环都会变大。更改 `TopK` 会重建场景，因此请在页面构建时一次设定，而不是在每次交互时修改。

### 你自己的文档与问题

`Documents` 接受 `VectorSearchDocument` 值。该记录有三个部分：`Title` 是结果列表显示的文字，`Topic` 将文档归入地图上的分组并为其聚类加上标签，`Keywords`（可选）为文档的嵌入增加词语，但不会显示出来。`Queries` 接受故事循环播放的问题。两者一旦设定（且至少包含一项），就会替换默认值。

<Demo name="YourDocuments" />

```csharp
search.Documents =
[
    new VectorSearchDocument("取消并退款年度套餐", "账单", "退款 退钱 取消"),
    new VectorSearchDocument("重置双因素认证", "安全", "手机 丢失 新设备"),
    new VectorSearchDocument("追踪延误的包裹", "物流", "快递 延误 包裹"),
];
search.Queries = ["怎样把钱退回来", "我的手机丢了"];
```

标题应写成读者会点击的答案，并把读者真正会输入的词语放入 `Keywords`。关键词也计入匹配，因此标题可以简短朴素。主题名称要少而宽泛（四到六个较为合适）：每个主题都会在地图上形成一个聚类，聚类过多、过小会让地图难以阅读。

### 搜索某个问题

`Search(query)` 会立即显示一个问题：它取消已排定的步骤，嵌入该问题并开始其故事。空白或仅含空白字符的字符串不会产生任何作用。在该问题的答案展示之后，故事会继续播放 `Queries` 中的问题。`Query` 是屏幕上显示的问题，`Results` 保存其答案（最佳者在前），每当某个问题的答案确定时都会触发 `ResultsChanged`，包括故事自行播放的问题。

<Demo name="AskYourOwn" />

每个 `VectorSearchResult` 都有 `Document`、`Score`（余弦相似度，范围从 −1 到 1）和 `Rank`（1 表示最佳匹配）。`Results` 是普通属性，不会发出变更通知，因此请在 `ResultsChanged` 处理程序中读取它，而不要将其绑定。

### 标签

`Labels` 接受一个 `VectorSearchLabels` 对象，用于设置可见的文字：模型名称及其详细说明行、列表标题，以及四个步骤的说明文字（`Typing`、`Embedding`、`Comparing` 与 `Answers`）。其 `Summary` 是静态画面的说明文字。请整体替换该对象来更改文字，因为标题和模型节点是在构建场景时读取的。

```csharp
search.Labels = new VectorSearchLabels { Model = "文本模型", Header = k => $"最佳 {k} 个匹配" };
```

### 播放、速度与说明文字

插图默认自动播放。`IsPlaying` 为双向绑定：可以绑定到页面上显示的开关，也可以调用 `Play()` 和 `Pause()`。`Restart()` 从第一步重新开始故事。本页顶部的预览使用了速度按钮，同样的设置在代码中也可以使用。

| 成员 | 用途 |
|---|---|
| `Speed` | 缩放故事时钟，范围从 0.25 到 4（默认 1）。讲解每个步骤的导览可以放慢，预告片则可以加快。 |
| `IsCaptionVisible` | 当页面已在正文中说明各步骤时，隐藏说明文字行。 |
| `IsPlaybackButtonVisible` | 在必须保持静止的页面上，隐藏播放与暂停按钮。 |
| `Caption` 与 `Step` | 读取当前说明文字及其步骤（0 到 3）。这些只读值同时也为无障碍帮助文字提供依据。 |
| `StepChanged` | 响应每个步骤，例如高亮图片旁文字中对应的句子。 |
| `Label` | 为辅助技术为插图命名（默认为 "Vector search illustration"）。 |

### 减弱动效

在减弱动效下，插图是第一个问题答案的静态画面。说明文字概括整个故事，播放按钮隐藏，光标也不再闪烁。请在控件上设置动效级别（如演示所示），或在持有页面动效设置的父级上设置。

### 克制地使用动效

当读者需要看清一条路径时，故事会有所帮助：问题变成向量，向量找到它的邻居，邻居成为答案。请将其放在读者有时间看完一个问题的页面上，在一倍速的完整动效下，一个问题大约需要 6.5 秒。当它位于表单、结账步骤或实时仪表板旁边时，就会分散注意力，因为视线应停留在读者正在填写的字段上。每页最多放置一两个插图，并且只在图片位于屏幕上时才让故事运行。时钟本身已经会在屏幕外暂停，因此长页面不会为读者尚未看到的插图付出代价。

### 绑定到视图模型

在 MVVM 应用中，视图模型持有文档与问题，控件只负责显示它们。下面的视图模型使用 CommunityToolkit.Mvvm。控件的 `Documents`、`Queries`、`TopK` 与 `Labels` 都是单向输入：新值会重建索引和地图。`IsPlaying` 是唯一的双向值。

```csharp
public partial class HelpCentreViewModel : ObservableObject
{
    [ObservableProperty]
    private IReadOnlyList<VectorSearchDocument> _articles = [];

    [ObservableProperty]
    private IReadOnlyList<string> _sampleQuestions = [];

    [ObservableProperty]
    private string _topMatchTitle = string.Empty;

    [ObservableProperty]
    private bool _isStoryPlaying = true;

    public void Load()
    {
        // 赋予新列表会触发 PropertyChanged，因此控件只会重建一次索引。
        Articles =
        [
            new VectorSearchDocument("取消并退款年度套餐", "账单", "退款 退钱 取消"),
            new VectorSearchDocument("重置双因素认证", "安全", "手机 丢失 新设备"),
            new VectorSearchDocument("追踪延误的包裹", "物流", "快递 延误 包裹"),
        ];
        SampleQuestions = ["怎样把钱退回来", "我的手机丢了"];
    }
}
```

```xml
<arc:VectorSearch Documents="{Binding Articles}"
                  Queries="{Binding SampleQuestions}"
                  IsPlaying="{Binding IsStoryPlaying, Mode=TwoWay}"
                  TopK="3"
                  Label="帮助中心搜索插图" />
```

`Search` 是方法，`Results` 是普通属性，因此它们留在代码后置中。在 `ResultsChanged` 处理程序中将最佳匹配转发给视图模型，并在页面搜索框的处理程序中调用 `Search`：

```csharp
// 在承载该控件的视图的代码后置中。
Search.ResultsChanged += (_, _) =>
{
    ViewModel.TopMatchTitle = Search.Results.Count > 0 ? Search.Results[0].Document.Title : string.Empty;
};

private void OnAskSubmitted(object? sender, SearchSubmittedEventArgs e)
{
    Search.Search(e.Query);
}
```

### 数据结构与性能

- **数据项模型**：`VectorSearchDocument` 是由 `Title`、`Topic` 与 `Keywords` 组成的记录。索引在构建时为每个文档嵌入一次。每个问题在被搜索时嵌入，因此一次提问只需一次嵌入和一轮对文档的排序计算。
- **规模**：默认索引包含四个主题下的 32 篇帮助中心文章。索引位于内存中，没有分页或持久化。地图会对文档集执行固定次数（300 次）的应力最小化迭代。只有在文档变化时才会重新计算，每次提问并不会重算。该插图是为教学规模的索引而设计的：拥有数千篇文章的真实帮助中心应使用你的搜索服务，而本控件用于说明其工作原理。
- **更新**：替换 `Documents`、`Queries`、`TopK` 或 `Labels` 会重建场景。原地修改列表中的项不会触发重建，因为控件并不监视列表本身。请用新的列表替换它。
- **格式**：排名与分数文字使用不变文化并保留两位小数（例如 "0.87"），因此数字在任何区域设置下都显示一致。请通过 `Labels` 翻译文字，而不是数字。

### 文案规范

- **标签**：说明图片展示的内容，采用句子式大小写：“帮助中心搜索插图”，而不是“Vector search”。屏幕阅读器会先读它，因此它应在没有图片的情况下也说得通。
- **说明与标题**：面向读者书写，而不是面向数学。默认标题使用了“余弦相似度”一词，适合开发者。面向客户的页面通常会说明这个数字的含义。
- **文档标题**：写成读者会点击的答案，采用句子式大小写，并让标题短到能放进结果列表的一行。读者使用的同义词与错别字应放入 `Keywords`。
- **主题**：一个简短的名词，采用句子式大小写，与导航所用的词语一致：“账单”“安全”“物流”。

| 不要写 | 改为 |
|---|---|
| Top 3 · cosine similarity | 最佳 3 个匹配 |
| Vector search illustration | 帮助中心搜索插图 |
| Embedding model | 文本模型 |
| Query | 问题 |
| The vector is compared with 32 document vectors | 正在比对 32 篇文章 |

### 最佳实践

**推荐**

- 将插图放在真实搜索框旁边，使读者能把图片与自己的问题联系起来。插图说明的是排名方式，它并不替页面执行搜索。
- 在帮助页和营销页上将 `TopK` 保持为 3。简短的列表能适应版面，也便于看清最佳匹配。
- 将读者会输入的词语放入 `Keywords`。它们能改善匹配，又不会让读者看到的标题变得杂乱。
- 当页面需要无障碍支持时，通过 `Results` 以文字形式提供相同的答案，放在读者可以阅读和浏览的列表中。绘制的列表本身并不是无障碍列表。

**避免**

- 将内置排名当作你的产品搜索质量。嵌入是哈希词与三元组，因此这些示例是在讲解方法，而不是衡量你的内容。
- 在同一屏幕上放置多个故事插图。每个插图在播放时都会逐帧重绘画布，页面会变得沉重，读者也无法同时跟随一个以上的故事。
- 在文档列表中原地编辑项。控件只在列表被替换时才会重建，因此地图和结果仍保留旧的文档。
- 依赖完整文字的长标题。结果列表会以省略号将长标题截断为一行，因此重要的词语必须放在前面。

### 常见问题

**故事运行时调用 `Search` 会怎样？** 已排定的步骤会被取消，问题会立即显示。随后故事会从当时的位置继续播放 `Queries` 列表，因此单次搜索不会让循环重新开始。

**为什么添加一个文档后地图会移动？** 地图是根据所有文档同时布局的，因此新增一个文档会改变其他文档的位置。排名则不会以同样的方式改变：答案的顺序只取决于问题与每个文档之间的余弦相似度。

**哪些词语会计入匹配？** 词语会被转为小写，“the”“my”“how”等常见词会被去掉，复数以及 `-ing`、`-ed` 词尾会被截去。每个词及其字符三元组都会进入向量，三元组按 0.3 个词计算，因此 "bill" 与 "billing" 会部分重合。`Keywords` 的计算方式相同，但从不显示。

**我能停止故事并仍然阅读答案吗？** 可以。设置 `IsPlaying="False"` 即可停留在当前画面，并且随时可以读取 `Results`。在减弱动效下，控件会以静态画面显示第一个问题的答案。

## 无障碍

- `Label` 是无障碍名称，当前的说明文字作为帮助文本提供。
- 插图可获得键盘焦点，并在其外框周围显示 2 px 的焦点环。
- 说明文字与绘制的结果列表在变化时不会被播报。排名后的答案也可通过 `Results` 以文字形式获取，因此请将其放在用户可以阅读和浏览的列表中。
- 在减弱动效下，控件显示其静态画面，因此没有任何内容需要依靠动效才能理解。

### 键盘

| 按键 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 将焦点移入或移出插图 |
| `Space` 或 `Enter` | 播放或暂停故事（插图本身有焦点时） |
| `R` | 从第一步重新开始故事 |

## 动效

- 问题会以带闪烁光标的方式逐字输入，然后嵌入模型开始处理。
- 向量条逐格填充，查询点飞入文档地图。
- 半径不断扩大直到触及最后一个答案，答案按排名依次点亮，其所在行向上浮入列表。
- 问题在完整动效、速度为 1 时大约需要 6.5 秒，之后故事开始下一个问题。
- 减弱动效和关闭动效时，显示第一个问题答案的静态画面，没有光标和逐字输入。播放按钮会隐藏。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 问题出现 | 带闪烁光标逐字输入 | 完整显示，没有光标 | 完整显示，没有光标 |
| 模型处理问题 | 模型节点显示忙碌环 | 没有忙碌环 | 没有忙碌环 |
| 向量条 | 单元格逐个填充 | 最终数值 | 最终数值 |
| 查询点 | 从向量条飞入地图 | 放置在最终位置 | 放置在最终位置 |
| 答案 | 半径扩大到最后一个答案，邻近的答案按排名依次点亮 | 最终的环与答案 | 最终的环与答案 |
| 结果行 | 按排名顺序向上浮入列表 | 立即列出 | 立即列出 |

## 相关组件

- `SearchField`：应用中的问题输入框，也用于展示你自己的结果。
- `DataFlow`：为搜索提供文档的内容如何被收集与存储。
- `SortableDataTable`：以分数展示长列表的结果。

| 组件 | 适用场景 |
|---|---|
| `SearchField` | 读者在你的产品中输入问题，由你自己的搜索服务作答 |
| `ExpandingSearch` | 搜索位于页头，并按需展开 |
| `SortableDataTable` | 结果是一份需要人们排序、筛选或导出的长列表 |
| `DataFlow` | 故事讲述的是文档如何被收集、校验和存储 |
| `LineChart` | 数值是人们需要按时间比较的测量值 |
| `Card` | 静态说明已经足够，插图会与页面内容争抢注意力 |
