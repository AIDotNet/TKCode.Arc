## 何时使用

`StretchRefresh` 是一张动态流卡片，向顶部拉过阈值即可刷新。顶部的页眉包含标题、一行简短状态和一个圆形刷新按钮，覆盖在一个柔和的底槽之上；行位于覆盖底槽的列表层上。向下拉动列表层时，它会跟随拉动，阻力逐渐增大，同时各行向两侧分开；间隙中的一条短线从中心向外生长，恰好在松手即可刷新的位置达到全长。在该位置松手后，线条会来回运行，直到工作完成，随后让位给一个对勾和简短结果，新的行从顶部落入。

- **动态、收件箱与时间线**：新条目总是出现在顶部，人们会不时过来查看。
- **需要通过手势在每次输入时刷新的面板**：鼠标拖动、触摸、触控笔，以及滚轮或触控板在动态流顶部向上滚动，都以同样的方式下拉。
- **刷新结果很重要的动态流**：指示器会说明本次刷新带来了什么（"3 new updates"），屏幕阅读器也会朗读。

## 何时不用

- **从不刷新的静态内容**：使用普通列表。
- **翻阅更早的条目**：使用 `Pagination`，或在列表底部加载更多。
- **带日期和标记的固定事件历史**：使用 `Timeline`。
- **自行更新的内容**（实时日志、聊天线程）：新条目到达时直接推入即可；下拉手势暗示动态流已经过时，需要用户主动请求。
- **手机上的整屏内容**：使用移动端的 `PullToRefresh` 包装器，它适用于任何可滚动内容。

## 用法

为控件设置标题、条目和刷新处理程序，并设置高度（或设置一个能决定其尺寸的父元素）：动态流在卡片内部滚动。处理程序是一个 `async` 函数，负责执行工作、将新条目放入集合，并返回一段简短结果。返回 `null` 则显示完成标签（"Up to date"）；抛出异常则显示错误标签（"Couldn’t refresh"）。

```xml
<arc:StretchRefresh x:Name="Feed" Title="Northbeam activity" Subtitle="Updated 12 min ago" Height="368" />
```

```csharp
Feed.ItemsSource = items;                       // an ObservableCollection, newest first
Feed.RefreshHandler = async ct =>
{
    var fresh = await api.FetchNewAsync(ct);
    foreach (var item in fresh.Reverse()) { items.Insert(0, item); }
    Feed.Subtitle = "Updated just now";
    return fresh.Count == 1 ? "1 new update" : $"{fresh.Count} new updates";
};
```

预览播放的是一个模拟后端 `StretchRefreshSampleFeed`：每次刷新耗时 1150 ms，将已显示的内容标记为已读，在顶部加入下一批虚构条目（依次为 3 条、1 条、2 条、0 条），并更改副标题。重置属于演示的一部分，而不属于控件本身。在应用中，请用你自己的工作替换示例动态流。

### 结构

1. **页眉**：标题、副标题（发生变化时向上浮现），以及一个 36 px 的圆形刷新按钮，其图标在工作运行时旋转，结束时变为对勾。
2. **底槽**：列表层后方的柔和区域。它的指示器包含 72 × 3 的线条和一行状态文字（"Pull to refresh"、"Release to refresh"、"Refreshing"，然后是带对勾的结果）。
3. **列表层**：位于表面颜色上的行。被下拉时，它的顶部圆角逐渐变圆，上方的底槽会投下一层柔和的阴影。
4. **行**：由 `ItemTemplate` 构建。若未设置，`StretchRefreshActivity` 条目会显示为 `StretchRefreshActivityRow`：头像或状态图标、一句话（其中的执行者与对象使用强调字重）、可选的引用和照片、一行元信息，以及条目未读时的强调色未读点。

### 状态

| 状态 | 显示内容 |
|---|---|
| `Idle` | 列表层覆盖底槽；指示器的任何部分都不可见 |
| `Pulling` | 出现间隙；线条从中心向外生长，颜色为次要色；显示 "Pull to refresh" |
| `Armed` | 下拉超过 `Threshold`：线条达到全长，再略微拉长，并变为前景色；显示 "Release to refresh" |
| `Refreshing` | 列表层停留在向下 60 px 处；一段短线沿线条运行；页眉图标旋转；显示 "Refreshing" |
| `Done` | 线条收缩消失；对勾在结果旁绘制出来；新行落入；随后列表层归位 |
| `Failed` | 与 `Done` 相同，但显示危险色的叉号和错误标签 |

`State` 和 `IsRefreshing` 为只读且可绑定；`RefreshStarted` 和 `RefreshCompleted` 会报告每个周期，包括触发原因（`Pull`、`Wheel`、`Button` 或 `Code`）及其结果或错误。

### 自定义行

任何条目类型都可以配合 `ItemTemplate` 使用。为 `ItemKeySelector` 设置稳定的键，使行在刷新后保持其视图：保留的行会从原位置滑动到新位置，键为新值的行则依次进入。此示例旁边的日志会显示每个周期的事件。

### 错误与标签

抛出异常的处理程序会使周期结束于 `Failed`：指示器显示叉号和 `Labels.Error`，页眉图标变为叉号，`RefreshCompleted` 携带该异常。控件显示或朗读的每个词都位于 `StretchRefreshLabels` 中；本示例为邮件收件箱重写了这些文字，并且除某些次数外，每次都会失败。

### 窄容器与阈值

卡片会占满所给的宽度；行会换行，照片按 4:3 的比例缩小。`Threshold` 是经过阻力计算后的下拉距离，超过它即可启动刷新；线条总是恰好在那里达到全长。在宽度为 475 px 或更窄的窗口中，卡片会去掉边框和圆角，以便贴边显示。

### 减弱动效

<Demo name="ReducedMotion" />

在减弱动效下，列表层仍然跟随下拉，行仍然分开，因此手势的感觉保持不变；线条不会过度拉伸，也不会运行（刷新时短线停在线条中央并以透明度呼吸，页眉图标随之呼吸）；列表层直接跳到其停靠位置，文字变化和新行只做淡入；列表层返回与周期结束在结果出现后 1.2 s 同时发生。

### 内容准则

- **标题**：动态流的名词短语（"Northbeam activity"、"Inbox"、"Deploy queue"）。它也为屏幕阅读器标明动态流的名称。
- **副标题**：用几个字说明动态流最后一次更新的时间。在处理程序中更新它；变化时会向上浮现。
- **结果**：简要说明发生了什么变化："3 new updates"、"1 new message"。若没有任何变化，请直接说明（"You’re all caught up"），或返回空值以显示完成标签。
- **错误标签**：说明什么失败了，而不是该怎么做；按钮和下拉手势就是重试方式。
- **刷新按钮名称**：当页面上有多个动态流时，请写明它刷新的内容（"Refresh activity"）。

### 最佳实践

- 在处理程序返回**之前**将新条目放入集合：结果、对勾和进入的行应当同时出现。
- 工作至少持续半秒，以便看清运行中的线条；立即返回的刷新看起来像故障。如果数据来自缓存，请等待差额时间。
- 为条目设置稳定的键（`StretchRefreshActivity.Id` 或 `ItemKeySelector`）；否则，发生变化的条目会被当作新条目。
- 新条目到达时，将旧条目标记为已读：`StretchRefreshActivity.IsUnread` 会让未读点在屏幕上淡出。
- 保持动态流简短（一两屏）：行不做虚拟化，因此每一行都能随下拉一起分开。

### 常见问题

**下拉的速度重要吗？** 不重要。只有距离重要：快速轻扫且未达到阈值，会像参考实现一样弹回。

**动态流滚动时，滚轮能否下拉？** 不能。只有当动态流已经位于顶部时，滚轮和触控板才会触发下拉；使其到达顶部的那一次事件只会滚动，下一次事件才会下拉。最后一次滚轮事件之后 150 ms，下拉结束。

**拖动离开卡片会怎样？** 它会继续下拉：只要按下是在动态流上开始的，控件就会跟随指针穿过整个窗口，并且只在下拉开始时才捕获指针，因此没有触发下拉的按下仍会点击其下方的行。

**能否从代码启动刷新？** 可以调用 `RefreshAsync()`。当周期正在运行时，它立即返回 `false`；否则在工作结束后返回 `true`。

## 无障碍

- 刷新按钮是键盘和开关操作的路径，与下拉执行相同的刷新。它的名称是 `Labels.RefreshButton`。周期运行期间，它仍可获得焦点，但不会执行任何操作（相当于 `aria-disabled`）。
- 动态流是一个以标题命名的可聚焦区域；方向键、Page Up 和 Page Down 可以滚动它。它的键盘焦点环绘制在列表层之内，因此底槽不会裁剪它。
- 工作运行期间，动态流会报告忙碌状态；"Refreshing" 以及随后的结果会以礼貌方式朗读。
- 未读行会先读出 "New."；每个活动行会把它的句子、引用和元信息合并为一个名称来朗读。
- 指示器仅起装饰作用；状态区域承载相同的文字。

### 键盘

| 按键 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 移动到刷新按钮，然后移动到动态流 |
| 按钮上的 `Enter` / `Space` | 不下拉，直接刷新 |
| 动态流中的方向键、`Page Up`、`Page Down`、`Home`、`End` | 滚动动态流 |

## 动效

- 列表层按阻力曲线 `280·d / (d + 400)` 与下拉一一对应地移动；每一行向下移动其索引 × 下拉距离的 5%，因此行与行之间的间隙逐渐张开。
- 线条的填充随下拉从中心向外生长。超过阈值后，整条线以快速弹簧拉伸至 1.12，其填充在 160 ms 内变为前景色。
- 松手后，列表层以临界阻尼弹簧（约 0.4 s）回弹到 60 px 处，行随之收拢；填充淡出，一段长度为 40% 的短线运行到远端再返回，每段 700 ms，采用缓入缓出曲线；页眉图标每 0.85 s 转一圈。
- 工作结束时，运行中的短线停止并淡出，线条收缩到 0.4 并淡出（180 ms）；对勾淡入并放大，其笔画在 320 ms 内绘制完成；保留的行以平滑弹簧滑动到新位置；新行在结果出现后 100 ms 开始，每行间隔 60 ms，从柔和的模糊中下落 16 px 进入原位。列表层在 1.21 s 之后弹回，指示器在 1.86 s 时重置。
- 状态文字和副标题在 240 ms 内从柔和的模糊中向上浮现，旧文字则在 120 ms 内向上飘走。

| 变化 | 完整动效 | 减弱动效 | 关闭 |
|---|---|---|---|
| 下拉与行的分开 | 跟随下拉 | 跟随下拉 | 跟随下拉 |
| 进入 Armed 时的过度拉伸 | 弹簧至 1.12 | 无 | 无 |
| 列表层的停靠与返回 | 弹簧 | 直接跳转 | 直接跳转 |
| 运行中的短线与旋转图标 | 有动画 | 停在原处，以透明度呼吸（1.8 s） | 静止 |
| 文字变化 | 向上浮现并模糊 | 淡入 | 直接替换 |
| 新行 | 下落、放大并去除模糊 | 淡入 | 直接出现 |
| 保留的行 | 滑动 | 直接跳转 | 直接跳转 |

## 响应式行为

- 卡片的宽度与其父元素允许的宽度相同；请为它设置高度，或设置一个能决定其尺寸的父元素。行会换行，照片附件会按其宽高比缩小。
- 在宽度为 475 px 或更窄的窗口中，卡片会去掉边框、圆角和背景（页眉和列表层保留其表面），以便贴边运行。
- 触摸下拉只有在手指按下时动态流已位于顶部才会开始；否则手指将滚动动态流。
- 悬停只会改变刷新按钮，且仅对鼠标和触控笔生效。

## 相关组件

- `PullToRefresh`（Mobile）用下拉刷新包装任何可滚动内容。
- `Timeline` 用于固定的事件历史。
- `Pagination` 用于翻阅更早的条目。
- `Skeleton` 用于首次加载时的占位。

| 组件 | 选择它的情况 |
|---|---|
| `StretchRefresh` | 动态流卡片应通过下拉、滚轮或按钮刷新，并说明刷新带来了什么 |
| `PullToRefresh` | 手机屏幕自身的可滚动内容应通过下拉刷新 |
| `Timeline` | 事件是固定的历史 |
| `Pagination` | 更早的条目分页呈现 |
