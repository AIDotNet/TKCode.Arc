## 何時使用

`StretchRefresh` 是一張動態串流卡片，當使用者把它拉過頂端時就會重新整理。標頭包含標題、簡短狀態與一個圓形的重新整理按鈕，位於柔和的底槽之上；列則排在覆蓋底槽的列表層上。把列表層往下拉時，它會以逐漸增加的阻力跟隨，同時列向外散開；列之間的空隙中有一條短線，從中心開始生長，恰好在放手即可重新整理的那一點達到全長。在該處放手後，線條會來回運行，同時進行工作，接著在新的列從頂端落下時，讓位給一個勾號與簡短的結果。

- **活動動態、收件匣與時間軸**：新項目會從頂端進來，人們會不時來查看是否有新內容。
- **應該以手勢重新整理的面板**：滑鼠拖曳、觸控、觸控筆，以及在動態串流頂端向上滾動的滾輪或觸控板，都以相同方式下拉。
- **結果很重要的動態串流**：指示器會說明這次重新整理帶來了什麼（"3 new updates"），螢幕閱讀器也會播報。

## 何時不用

- **永不重新整理的靜態內容**：請使用一般清單。
- **翻閱較舊的項目**：請使用 `Pagination`，或在清單底部載入更多。
- **帶有日期與標記的固定事件歷史**：請使用 `Timeline`。
- **會自行更新的內容**（即時記錄、聊天串）：有新項目時直接推入；下拉手勢會暗示動態串流在被要求之前都是過時的。
- **手機上的整個畫面**：請使用行動版的 `PullToRefresh` 包裝器，它適用於任何可捲動的內容。

## 用法

為控制項提供標題、項目、重新整理處理常式，以及高度（或會替它決定大小的父層）：動態串流會在卡片內捲動。處理常式是一個 `async` 函式，負責執行工作、把新項目放入集合，並傳回一個簡短的結果。若要顯示完成標籤（"Up to date"），請傳回 `null`；若要顯示錯誤標籤（"Couldn’t refresh"），請擲出例外。

```xml
<arc:StretchRefresh x:Name="Feed" Title="Northbeam activity" Subtitle="Updated 12 min ago" Height="368" />
```

```csharp
Feed.ItemsSource = items;                       // an ObservableCollection, newest first
Feed.RefreshHandler = async ct =>
{
    var fresh = await api.FetchNewAsync(ct);
    foreach (var item in fresh.Reverse()) { items.Insert(0, item); }
    Feed.Subtitle = "Updated just now";
    return fresh.Count == 1 ? "1 new update" : $"{fresh.Count} new updates";
};
```

預覽會重播一個模擬後端 `StretchRefreshSampleFeed`：每次重新整理需要 1150 ms，會把已顯示的項目標記為已讀，在最上方加入下一批虛構的項目（依序為 3、1、2，然後不再加入任何項目），並更改副標題。重設屬於示範的一部分，而非控制項的一部分。在應用程式中，請以你自己的工作取代範例動態串流。

### 結構

1. **標頭**：標題、副標題（變更時會升起），以及一個 36 px 的圓形重新整理按鈕，其圖示在工作執行時旋轉，結束時轉為勾號。
2. **底槽**：列表層後方的柔和區域。其指示器包含 72 × 3 的線與一行狀態文字（"Pull to refresh"、"Release to refresh"、"Refreshing"，然後是附勾號的結果）。
3. **列表層**：以表面色呈現的列。被下拉時，其頂端圓角會逐漸變圓，且一道柔和陰影會落在上方的底槽上。
4. **列**：由 `ItemTemplate` 建立。若沒有指定，`StretchRefreshActivity` 項目會以 `StretchRefreshActivityRow` 呈現：頭像或狀態圖示、一個以強調字重顯示行為者與目標的句子、可選的引述與照片、一行中繼資料，以及項目未讀時的強調色點。

### 狀態

| 狀態 | 顯示內容 |
|---|---|
| `Idle` | 列表層覆蓋底槽；指示器的任何部分都不可見 |
| `Pulling` | 出現一道空隙；線條以柔和色從中心生長；"Pull to refresh" |
| `Armed` | 下拉超過 `Threshold`：線條呈全長，再稍微多伸展一些，並轉為前景色；"Release to refresh" |
| `Refreshing` | 列表層停在向下 60 px 處；一段短線段沿線條運行；標頭圖示旋轉；"Refreshing" |
| `Done` | 線條縮回；勾號在結果旁繪製出來；新列落入；然後列表層回位 |
| `Failed` | 與 done 相同，但以危險色呈現叉號與錯誤標籤 |

`State` 與 `IsRefreshing` 為唯讀且可繫結；`RefreshStarted` 與 `RefreshCompleted` 會回報每個週期，包括觸發它的原因（`Pull`、`Wheel`、`Button` 或 `Code`）及其結果或錯誤。

### 你自己的列

任何項目型別都可搭配 `ItemTemplate` 使用。為 `ItemKeySelector` 提供穩定的鍵，讓列在重新整理後保留其檢視：保留下來的列會從原位滑到新位置，新鍵的列則會一個接一個進入。此動態串流旁的記錄會顯示每個週期的事件。

### 錯誤與標籤

拋出例外的處理常式會讓這個週期以 `Failed` 結束：指示器顯示叉號與 `Labels.Error`，標頭圖示變成叉號，而 `RefreshCompleted` 會帶著例外。控制項顯示或播報的每個文字都位於 `StretchRefreshLabels` 中；此示範為郵件收件匣改寫了這些文字，並且每隔一次重新整理就會失敗。

### 窄容器與門檻

卡片會填滿所給的寬度；列會換行，照片則依其 4:3 的比例縮小。`Threshold` 是經過阻力後能觸發重新整理的下拉距離；線條總是恰好在該處達到全長。在寬度為 475 px 或以下的視窗中，卡片會移除邊框與圓角，以便貼齊邊緣。

在減少動態效果下，列表層仍會跟隨下拉，列也仍會散開，因此手勢依然保有其手感；線條不會過度伸展或運行（重新整理時線段停在線條中央並以透明度呼吸，標頭圖示也隨之呼吸），列表層會直接跳到其停留位置，文字變化與新列僅淡入，而列表層回位與週期結束會在結果出現 1.2 s 後同時發生。

### 內容指引

- **標題**：動態串流的名詞片語（"Northbeam activity"、"Inbox"、"Deploy queue"）。它也為螢幕閱讀器指出這個動態串流的名稱。
- **副標題**：簡短說明動態串流上次更新的時間。在處理常式中更新它；變更時會升起。
- **結果**：簡要說明改變了什麼："3 new updates"、"1 new message"。若沒有任何改變，請直接說明（"You’re all caught up"），或傳回空值以顯示完成標籤。
- **錯誤標籤**：說明失敗的內容，而非該如何處理；按鈕與下拉本身就是重試。
- **重新整理按鈕名稱**：當頁面上有多個動態串流時，請寫出它重新整理的對象（"Refresh activity"）。

### 最佳做法

- 在處理常式傳回**之前**先把新項目放入集合：結果、勾號與進入的列應該一起出現。
- 讓工作至少持續半秒，以便看見運行中的線條；若立即傳回，重新整理看起來就像故障。若資料已快取，請等待其差額時間。
- 為項目提供穩定的鍵（`StretchRefreshActivity.Id` 或 `ItemKeySelector`）；沒有鍵的話，已變更的項目會被視為新項目。
- 新項目到達時，將舊項目標為已讀：`StretchRefreshActivity.IsUnread` 會在螢幕上淡出未讀點。
- 讓動態串流保持簡短（一到兩個螢幕）：列不會虛擬化，因此每一列都能隨下拉散開。

### 常見問題

**下拉的速度重要嗎？** 不重要。只有距離重要：快速輕彈但未超過門檻的手勢，會如同參考實作一樣以彈簧回彈。

**動態串流已捲動時，滾輪能下拉嗎？** 不能。滾輪與觸控板只有在動態串流已位於頂端時才會下拉；把它帶到頂端的那個事件只會捲動，下一個事件才會下拉。最後一次滾輪事件之後 150 ms，下拉即結束。

**拖曳離開卡片會怎樣？** 它會繼續下拉：只要按下是從動態串流開始，控制項就會跟隨指標穿過整個視窗；只有在下拉開始時才會擷取指標，因此不下拉的按壓仍會點擊其下方的列。

**我能從程式碼啟動重新整理嗎？** 可以，呼叫 `RefreshAsync()`。若週期仍在執行，它會立即傳回 `false`；否則在工作結束時傳回 `true`。

## 無障礙

- 重新整理按鈕是鍵盤與開關的路徑，可執行與下拉相同的重新整理。其名稱為 `Labels.RefreshButton`。週期執行期間它仍可取得焦點，但不會有任何動作（相當於 `aria-disabled`）。
- 動態串流是一個以標題命名的可取得焦點區域；方向鍵、Page Up 與 Page Down 可捲動它。它的鍵盤焦點環繪製於列表層之內，因此底槽不會裁切它。
- 工作執行時，動態串流會回報忙碌狀態；"Refreshing" 與之後的結果會以禮貌方式播報。
- 未讀的列會先朗讀 "New."；每個活動列會把它的句子、引述與中繼資料朗讀為一個名稱。
- 指示器僅供裝飾：狀態區域會帶有相同的文字。

### 鍵盤

| 按鍵 | 操作 |
|---|---|
| `Tab` / `Shift+Tab` | 移到重新整理按鈕，然後移到動態串流 |
| `Enter` / `Space` 於按鈕上 | 不需下拉即可重新整理 |
| 動態串流中的方向鍵、`Page Up`、`Page Down`、`Home`、`End` | 捲動動態串流 |

## 動態效果

- 列表層依 `280·d / (d + 400)` 的阻力曲線一對一地跟隨下拉；每一列會依其索引 × 下拉距離的 5% 向下移動，因此列之間的間隙會張開。
- 線條的填滿會隨下拉從中心生長。超過門檻後，整條線以快速彈簧伸展到 1.12，其填色在 160 ms 內轉為前景色。
- 放手時，列表層以彈簧回到 60 px（臨界阻尼，約 0.4 s），列則收攏；填色淡出，一段長度為 40% 的線段運行到遠端再返回，每段 700 ms，採用進出緩和曲線；標頭圖示每 0.85 s 轉一圈。
- 工作結束時，線段停止並淡出，線條縮至 0.4 並淡出（180 ms）；勾號淡入並放大，其筆畫在 320 ms 內繪製；保留的列會以平滑彈簧滑到新位置；新列在結果出現後 100 ms 起，以 60 ms 的間隔，從柔和模糊中向下落入 16 px 的位置。列表層在 1.21 s 後以彈簧彈回，指示器在 1.86 s 時重設。
- 狀態文字與副標題會在 240 ms 內從柔和模糊中升起，舊文字則在 120 ms 內向上淡離。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| 下拉與列的散開 | 跟隨下拉 | 跟隨下拉 | 跟隨下拉 |
| 超過門檻的過度伸展 | 以彈簧伸展至 1.12 | 無 | 無 |
| 列表層移到停留位置與回位 | 以彈簧移動 | 直接跳動 | 直接跳動 |
| 運行中的線段與旋轉圖示 | 有動畫 | 停在原處，以透明度呼吸（1.8 s） | 靜止 |
| 文字變化 | 升起並模糊 | 淡入 | 直接取代 |
| 新列 | 落入、放大並去除模糊 | 淡入 | 直接出現 |
| 保留的列 | 滑動 | 直接跳動 | 直接跳動 |

## 響應式

- 卡片的寬度與其父層允許的一樣寬；請為它提供高度，或提供會決定大小的父層。列會換行，照片附件則依其比例縮小。
- 在寬度為 475 px 或以下的視窗中，卡片會移除邊框、圓角與背景（標頭與列表層仍保留其表面），以便貼齊邊緣執行。
- 觸控下拉只有在手指按下時動態串流已位於頂端時才會開始；否則手指會捲動動態串流。
- 懸停只會改變重新整理按鈕，而且僅限滑鼠與觸控筆。

## 相關元件

- `PullToRefresh`（Mobile）以下拉重新整理包裝任何可捲動的內容。
- `Timeline` 用於固定的事件歷史。
- `Pagination` 用於翻閱較舊的項目。
- `Skeleton` 用於第一次載入執行期間的佔位。

| 元件 | 適用時機 |
|---|---|
| `StretchRefresh` | 動態串流卡片應能透過下拉、滾輪或按鈕重新整理，並說明它帶來了什麼 |
| `PullToRefresh` | 手機畫面中自身可捲動的內容應能以下拉重新整理 |
| `Timeline` | 事件是固定的歷史 |
