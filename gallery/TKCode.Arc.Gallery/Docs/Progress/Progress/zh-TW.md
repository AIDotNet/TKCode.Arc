## 何時使用

`Progress` 顯示一項總量已知的任務完成了多少：檔案上傳、資料匯入、批次作業或月底結帳。它位於頁面的內容流中，放在所描述的內容之上或旁邊，並給使用者一個明確的答案，回答「還剩多少」。可選的計數與完成標記讓進度條同時傳達數字和形狀，因此使用者無需解讀填滿的長度就能讀出狀態。

- **檔案上傳與匯出**：帳務或 CRM 頁面中的發票匯出或文件上傳，`Label` 寫明任務（「正在上傳 4 個檔案」），`IsValueVisible` 顯示百分比。每個區塊完成時，進度條隨之填滿。
- **列數已知的資料匯入**：CRM 中匯入 2,400 筆聯絡人。將 `Maximum` 設為列數，`Value` 設為已處理的列數，這樣進度條和計數使用使用者所計算的單位。
- **批次作業與對帳**：財務主控台中的月底總帳結帳或每晚對帳，多個作業並行執行。每個作業都有自己的進度條，已完成的作業顯示勾號。
- **總量可度量的設定與引導清單**：工作區設定已匯入 5 個資料來源中的 3 個。進度條顯示設定已完成的比例，步驟清單說明還剩哪些。
- **開發者工具中的長時間操作**：有可度量步驟數的建置、套件同步或日誌封存。

## 何時不用

- **無法度量進度的載入**：用 `Skeleton` 預留正在載入內容的空間。
- **相對於額度測量的配額**：相對儲存空間、席位或 API 呼叫上限的用量用 `UsageMeter`。進度條到 100% 表示任務已完成，而配額到 100% 表示額度已用盡，需要警示。
- **儀表板上的單一指標**：可用性或準時交付率等核心數字用 `Gauge`。
- **多步驟流程中的位置**：用 `Stepper` 顯示目前處於哪一步。進度條暗示存在一個總工作量，而步驟並沒有。
- **截止時間而非工作占比**：距離某個時刻還剩多久用 `Countdown`。倒數的進度條會被讀成已完成的工作，這與截止時間所表達的意義正好相反。

## 用法

設定 `Value`，若總量不是 100，還需設定 `Maximum`。進度條為唯讀，無法取得焦點。

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:Progress Label="正在上傳 4 個檔案"
                  IsValueVisible="True"
                  Value="35" />
</UserControl>
```

`Progress` 衍生自 Avalonia 的 `RangeBase`，因此 `Value` 與 `Maximum` 和你在滑桿與捲軸中已熟悉的範圍屬性相同。`Minimum` 會當作 0 處理，值為零或負數的 `Maximum` 會當作 100 處理。計算百分比時控制項會將 `Value` 限制在範圍內，因此超過最大值的數值顯示為 100%，低於零的數值顯示為 0%。控制項從不寫入 `Value`：它只顯示所給的值，因此可以安全地從擁有該作業的檢視模型繫結。

### 結構

1. **標籤**（`Label`）：作業的可見名稱，使用小字級和次要文字顏色。它位於進度條上方那一列的左側，同時也是無障礙名稱。沒有標籤時，該列隱藏。
2. **讀數**（`IsValueVisible`）：計數的百分比，靠右對齊，使用弱化文字顏色和等寬數字。它位於標籤之後 12 px。其占位寬度與「100%」相同，因此數字增加一位時，勾號和數字不會移位。達到 100% 時，計數旁出現成功色的勾號。
3. **軌道**：高 7 px（含 1 px 邊框）的膠囊，使用邊框顏色、表面弱化背景和完全圓角的兩端。軌道會裁切填滿的部分，因此圓形末端在任何數值下都保持形狀。
4. **填滿**：從軌道左邊緣開始的強調色，寬度與百分比對應。達到 100% 時變為成功色。

中繼資訊列（標籤和讀數）僅在 `Label` 有文字或 `IsValueVisible` 開啟時出現。中繼資訊列與軌道之間的間距為 8 px。兩者都沒有的進度條只顯示 7 px 高的軌道，適合表格列或卡片底部。

### 僅進度條

不設定標籤和數值時，進度條單獨使用。其無障礙名稱為「進度」。

<Demo name="BarOnly" />

當周圍的版面已經為任務命名時，單獨使用進度條即可，例如第一欄是任務名稱的表格列，或標題為「匯出」的卡片。這種情況下再加一個標籤只會重複相同的字。

### 自訂最大值

`Percentage` 為 `round(Value / Maximum × 100)`，因此 2,400 中的 1,392 顯示為 58%。

<Demo name="CustomMaximum" />

當總量是人們習慣計數的單位時使用 `Maximum`：列、檔案、位元組或步驟。相比需要使用者自行計算的百分比，計數更加直觀；而且總量變化時，百分比會根據兩個數字重新計算，因此始終正確。`Value` 與 `Maximum` 應使用相同的單位，不要在同一個進度條中混用位元組和百萬位元組。

### 切換標籤

切換 `Label` 時，新文字會從柔和的模糊中升起，舊文字同時淡出。

<Demo name="ChangingLabel" />

當任務依序經歷幾個有名稱的階段時，使用會變化的標籤，例如「正在準備匯出」、「正在壓縮封存」和「正在上傳封存」。各階段保持同一個進度條；只有當某個階段有自己的總量時，才為該階段重設 `Value`。如果每個階段都從零開始，使用者會以為整個任務重新開始了。

```xml
<arc:Progress Label="{Binding PhaseName}"
              Value="{Binding PhaseProgress}" />
```

### 完成

達到 100% 時，填滿變為成功色，計數旁出現勾號。使用 `:complete` 偽類為該狀態設定樣式。

```csharp
upload.Value = 100;
// upload.IsComplete 現在為 true；開啟 IsValueVisible 時會顯示勾號。
```

`IsComplete` 為唯讀。百分比達到 100 時它變為 true，`:complete` 偽類隨之變化。計數停在 99/100 的作業並未完成，因此工作完成時應將 `Value` 設為完整總量。進度條本身不會播報完成狀態。任務結束時，請顯示通知，例如使用 Toast。

### 繫結到檢視模型

在 MVVM 應用程式中，作業歸檢視模型所有，進度條只顯示其狀態。使用 CommunityToolkit.Mvvm 時，一個 `ObservableObject` 保存計數和計算出的百分比，進度條以單向方式繫結到它們。

```csharp
public partial class ImportViewModel : ObservableObject
{
    [ObservableProperty]
    private int _rowsImported;

    [ObservableProperty]
    private int _rowsTotal = 2400;

    [ObservableProperty]
    private string _phaseName = "正在匯入聯絡人";
}
```

```xml
<arc:Progress Label="{Binding PhaseName}"
              IsValueVisible="True"
              Maximum="{Binding RowsTotal}"
              Value="{Binding RowsImported, Mode=OneWay}" />
```

`Value` 與 `Maximum` 應使用單向繫結。匯入服務在每批次提交時設定 `RowsImported`，繫結會把變化傳遞給進度條，因此頁面無需輪詢作業。將 `Label` 繫結到階段名稱，階段變化時新文字會升起顯示。若需要「取消」按鈕之類的命令（例如連接到 `[RelayCommand]` 的按鈕），應放在進度條旁邊而不是其內部，因為進度條不接收輸入。

### 回報進度

當一個工作單位完成時（例如一批列或一個檔案）更新 `Value`，而不是每個位元組或每一影格都更新。每次變化都會啟動填滿彈簧，因此持續不斷的微小更新會讓進度條保持移動，卻不增加任何資訊。以幾百列為一批，或以一個檔案為單位，都是不錯的單位。當作業有較長的停頓（例如伺服器端步驟沒有任何回饋）時，應改變 `Label` 說明作業正在等待什麼，而不是讓進度條靜止不動卻沒有解釋。

### 範例：CRM 中的資料匯入

匯入畫面展示三個並行執行的作業：發票歷史匯出、聯絡人匯入和總帳對帳。每個作業都有自己的進度條和標籤，因此使用者無需查看日誌就能看出哪個已完成。已完成的作業顯示勾號，執行中的作業顯示其計數與總量，剛開始的作業則位於軌道起點附近。文案寫明了作業名稱，因此即使不看頁面標題，進度條也能讀懂。

![資料遷移面板，一個作業已完成，一個匯入進行到 58%，一個作業剛剛開始](images/MigrationJobs.png)

```xml
<Border Width="640"
        Padding="28"
        CornerRadius="12"
        Background="{arc:ArcDesignTokenResource Surface}"
        BorderBrush="{arc:ArcDesignTokenResource Border}"
        BorderThickness="1">
    <StackPanel Spacing="22">

                       FontSize="18"

                       Foreground="{arc:ArcDesignTokenResource Foreground}" />
            <TextBlock Text="Three jobs for the Northwind workspace"
                       FontSize="13"
                       Foreground="{arc:ArcDesignTokenResource TextMuted}" />
        </StackPanel>
        <arc:Progress Label="Invoice history export"
                      IsValueVisible="True"
                      Value="100" />
        <arc:Progress Label="Contacts import"
                      IsValueVisible="True"
                      Maximum="2400"
                      Value="1392" />
        <arc:Progress Label="Ledger reconciliation"
                      IsValueVisible="True"
                      Value="4" />
    </StackPanel>

```

每個進度條使用相同的寬度和相同的讀數，因此這一欄讀起來像一個清單。聯絡人匯入使用 `Maximum`，因為團隊以列數計算；另外兩個使用預設的 100，因為它們的總量天然就是百分比。已完成的作業會以勾號保留在清單中，因此使用者能看出它已完成，而不會疑惑它是否消失了。

### 文案規範

標籤說明作業和計數，因此兩者都應能獨立讀懂。寫明工作的對象，使用句首大寫，並讓標籤短到能與讀數並排放在同一列。作業執行時使用現在分詞，完成後使用普通名詞，讓標籤告訴使用者作業處於什麼狀態。

| 不要寫 | 改為 |
|---|---|
| `Progress` | `Uploading 4 files` |
| `Done` | `Invoice history export`（勾號和 100% 已經表明它已完成） |
| `Importing... please wait` | `Importing contacts` |
| `Step 2 of 5 (40%)` | `Ledger reconciliation`，並將 `Value` 設為 40 |
| `Error: upload failed` | 在進度條旁的訊息中寫 `Upload failed. Retry`，進度條停在出錯的位置 |

讀數中的數字使用阿拉伯數字，由進度條顯示百分比。不要把百分比也寫進標籤，否則使用者會讀到兩次同一個數字。

### 最佳做法

**建議**

- 在使用者需要等待的任何作業上顯示 `IsValueVisible`，因為數字能告訴他作業是否在推進。
- 當總量是使用者習慣計數的數字時使用 `Maximum`，這樣總量變化時百分比仍然正確。
- 作業失敗時讓進度條停在失敗的位置，並在旁邊的訊息中說明原因，因為重設的進度條會掩蓋已經完成的工作。
- 清單中每個作業各一個進度條，讓每個作業都有自己的狀態、標籤和勾號。

**避免**

- 為沒有可度量總量的工作顯示進度條，因為隨機移動的進度條會讓使用者學會忽略它。內容載入時使用 `Skeleton`。
- 在同一作業的各階段之間把 `Value` 重設為零，因為使用者會把它理解為整個作業重新開始。
- 每個位元組或每一影格都更新 `Value`，因為每次變化都會重新啟動填滿彈簧，卻不增加任何資訊。
- 在清單中把勾號當作唯一的完成標誌。作業結果重要時，應加上狀態詞或訊息，例如「匯出已就緒」。

### 常見問題

**`Value` 大於 `Maximum` 時會怎樣？** 百分比會限制在 100，`IsComplete` 變為 true。控制項本身不會修改 `Value`，因此如果該作業不應視為已完成，請在檢視模型中重設它。

**進度條能顯示未知總量嗎？** 不能。控制項沒有不確定狀態，因此沒有總量的進度條是錯誤的做法。內容載入時使用 `Skeleton`，或在標籤中顯示作業目前的階段，而不使用進度條。

**如何隱藏標籤並保留讀數？** 保持 `IsValueVisible` 開啟，並將 `Label` 留空。中繼資訊列隨即只顯示讀數，靠右對齊於軌道上方，無障礙名稱變為「進度」。當名稱重要時，請在周圍版面為進度條提供標題。

**如何知道作業何時完成？** 訂閱檢視模型中的作業狀態，或在設定 `Value` 之後檢查 `IsComplete`。控制項沒有完成事件，因此由頁面負責播報：作業結束時顯示 Toast 或訊息。

## 無障礙

- `Label` 是無障礙名稱。沒有標籤時，名稱為「進度」。
- 控制項以百分比的形式公開數值，因此螢幕閱讀器會朗讀目前百分比，例如 30%。
- 對輔助技術而言它是唯讀的進度條，不會要求焦點。
- 它不是即時區域。任務結束時請單獨播報完成狀態。
- 無法取得焦點，也沒有鍵盤互動。用於啟動、暫停或取消作業的控制項應保留在 Tab 順序中，緊挨進度條放置，使使用者能用鍵盤操作。
- 朗讀的是百分比，因此應為作業取一個說明計數對象的名稱，例如「聯絡人匯入」，這樣數字本身就有意義。

## 動態效果

- 同一條平滑彈簧同時驅動填滿與計數的百分比，因此數字始終與進度條一致。
- 達到 100% 時，填滿在短暫延遲後變為成功色，勾號以輕微縮放和模糊的方式落定。
- 標籤變化時，新標籤從柔和的模糊中升起，舊標籤淡出。
- 減少動態效果時，填滿與計數直接跳到新值，標籤以短暫淡入切換。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| `Value` 變化 | 填滿與計數沿同一條平滑彈簧一起移動 | 填滿與計數直接跳到新值 | 立即 |
| 達到 100% | 填滿在 200 ms 後淡入成功色；勾號在 0.24 s 後從 0.6 縮放出現 | 勾號淡入 | 立即 |
| `Label` 變化 | 新標籤從 0.3 em 處帶柔和模糊升起；舊標籤淡出 | 短暫淡入 | 立即 |

### 節制地使用動態效果

在進度條中，真正需要移動的只有填滿與計數，而且它們應當只在作業推進時才移動。不要在執行中的進度條上循環播放脈衝或閃爍效果，因為這種動效會暗示作業有活動，而事實並非如此。暫停或等待中的進度條應停止變化，並由標籤說明原因。減少動態效果無需額外處理：控制項會直接跳到新值，並讓勾號淡入。

## 相關元件

- `Skeleton`：工作量未知且內容仍在載入時使用。
- `UsageMeter`：數值占滿帶上限的額度時使用。
- `Gauge`：儀表板上的單一指標。
- `Stepper`：任務由一連串命名步驟組成時使用。
- `Countdown`：剩餘時間比工作完成占比更重要時使用。

| 元件 | 適用情境 |
|---|---|
| `Skeleton` | 內容正在載入，無法度量進度 |
| `UsageMeter` | 數值相對於使用者需要管理的上限進行測量 |
| `Gauge` | 儀表板上展示一個核心指標 |
| `Stepper` | 任務是一連串帶有目前步驟的命名步驟 |
| `Countdown` | 距離某個固定時刻的剩餘時間才是要傳達的訊息 |
