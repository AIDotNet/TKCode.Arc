## 何时使用

`LinkUnfurl` 是一个消息输入区域，适用于人们分享链接的地方：聊天频道、评论框、笔记收件箱。粘贴的地址，或者输入后跟一个空格的地址，会变成一个行内链接。在获取其预览期间，链接会在柔和的扫光下显示地址；预览到达后，网站图标和页面标题滚入链接，链接本身则在消息下方展开为一张卡片，其中有网站、标题、简短描述和分享图片。卡片随时可以收起回链接中，也可以连同链接一起移除。

- **聊天与评论的消息输入框**：人们在发送之前就能看到链接指向什么，并可以去掉只会增加干扰的预览。
- **笔记与收件箱收集**：粘贴的地址会立即变成可读的内容。
- **展示应用如何处理链接的产品页**：借助内置的示例和自动播放，消息输入框会自行演示整个过程。

## 何时不用

- **显示他人写下的链接**：使用 `HoverCard`，在悬停或获得焦点时预览它；此控件用于书写。
- **代表人员、频道或记录的标记**：使用 `MentionInput`，它会在输入时给出建议。
- **较长的格式化文档**：使用 `RichTextEditor`。
- **单个地址字段**：带验证的普通 `TextField` 比消息输入框更清晰。

## 用法

`LinkUnfurl` 派生自 Avalonia 的 `TemplatedControl`，位于 Special 包中：请在 `UseArc()` 旁调用`UseArcSpecial()` 进行注册。未设置任何内容时，它是一个空的消息输入框，会把任何地址展开为一张仅由地址本身构建的普通卡片。上方的预览增加了三个虚构的示例、一条初始消息和自动播放：消息输入框首次进入视野 1.1 秒后，会粘贴第一个示例，除非有人已经使用过它。

```xml
<arc:LinkUnfurl Label="Message #trail-club"
                Placeholder="Message #trail-club"
                Samples="{x:Static arc:LinkUnfurlSamples.Previews}" />
```

### 你自己的解析器与发送处理程序

在应用中，请在你的服务器上展开链接（Open Graph、oEmbed），并从 `Resolver` 返回一个 `LinkUnfurlPreview`。没有可显示的内容时返回 null：链接随后会留在文字中而不带卡片，并在被点击时重新获取。链接被移除或消息被发送时，取消令牌会触发，因此请遵循它。

```csharp
composer.Resolver = FetchPreview;
composer.SendHandler = message => http.PostAsync("/api/messages", new StringContent(message.Text));

async Task<LinkUnfurlPreview?> FetchPreview(string url, CancellationToken cancellationToken)
{
    var response = await http.GetAsync($"/api/unfurl?url={Uri.EscapeDataString(url)}", cancellationToken);
    if (!response.IsSuccessStatusCode)
    {
        return null;
    }
    // Read site, title, description and image from your own response format here.
    return new LinkUnfurlPreview(url, "Site name", "Page title") { Description = "One or two sentences." };
}
```

按 Enter 或发送按钮会引发 `SendRequested`，然后调用 `SendHandler`。消息包含文字（其中每个链接都写成当初粘贴的地址）以及已解析的预览。返回的任务运行期间，消息输入框保持等待：消息为只读，发送按钮显示一个加载指示器。任务完成后，内容向上移走，消息输入框缩回原来的高度，按钮显示一个对勾，持续 1.6 秒；任务失败时，其消息以警告的形式出现在消息输入框下方，文字保留不变。下方的演示会记录每一个事件；包含 "missing" 的地址不会得到预览，包含 "fail" 的消息会被拒绝。

### 结构

1. **消息输入框**：最宽 576px，带 1px 边框（焦点位于其中时边框变深），圆角半径 26。
2. **消息**：Inter 16/26，至少两行高。链接作为单个整体位于文字中。
3. **链接**：高 26px，最宽 224px。加载中：一个地球图标和去掉协议部分的地址，位于扫光之下。已解析：网站图标和标题，过长时以省略号截断。已展开：强调色色调和环。
4. **卡片栏**：卡片，每个链接一张，按链接的顺序排列，间距 10px。
5. **卡片**：最宽 440px，包含页眉（网站图标、网站、一个收起按钮和一个移除按钮）、作为真实链接的标题、最多两行描述，以及按 Open Graph 比例 1.91 : 1 显示的图片。没有图片的预览会得到一张纯文字卡片；没有网站图标的预览会在一个小方块上显示网站的首字母。
6. **工具栏**：左侧是 "Try" 和示例按钮，右侧是圆形的发送按钮。

### 状态

| 部件 | 状态 | 外观 |
|---|---|---|
| 链接 | 加载中 | 柔和的填充、一圈细环、次要文字、一个呼吸的地球图标，以及每 1.15 s 一次的扫光 |
| 链接 | 已解析，收起 | 柔和的填充，网站图标和标题使用文字颜色 |
| 链接 | 已展开 | 11% 的强调色（深色模式下为 20%）以及 34%（48%）的强调色环 |
| 链接 | 无预览 | 地址加一个静止的地球图标；点击会重新获取 |
| 卡片 | 打开 / 收起 | 收起的卡片被隐藏，并移出 Tab 顺序 |
| 示例按钮 | 不在消息中 / 在消息中 | 一圈细环 / 柔和的填充 |
| 发送按钮 | 空闲 / 等待中 / 已发送 | 文字颜色 / 一个加载指示器 / 成功色加一个对勾 |

### 手势

- **点击链接**可收起或打开其卡片；没有预览的链接会重新获取。
- **向上拖动卡片**可将其收起。卡片跟随指针移动（拖动其高度的 80% 即完全收起）；超过 40% 时松开，或向上快速轻扫，卡片会收起，否则它会以松开时的速度弹回打开状态。使用鼠标或笔时可以拖动整张卡片；触摸时只能拖动页眉，因此在卡片主体上仍可滚动页面。
- **示例按钮**会粘贴其链接，然后收起或打开其卡片。

### 窄容器

消息输入框根据自身宽度调整尺寸：宽度低于 560px 时内边距会减小，低于 360px 时 "Try" 会隐藏，使示例按钮和发送按钮保持在一行（如果仍放不下，示例会横向滚动）。卡片会填满较窄的卡片栏，其图片保持 1.91 : 1 的比例。

### 减少动效

在减少动效下，以及设置了 `IsPaused` 时，卡片会立即打开和收起，加载中的链接显示静止的色调，而不是扫光。每种状态、名称和播报都保持不变。

### 内容准则

- 让网站图标保持方形；它们位于一个 16px 的槽位中，在链接和卡片之间对齐。
- 按页面自身的写法返回标题；链接会在 224px 处截断过长的标题，卡片则显示完整标题。
- 让描述保持在一两句话以内；卡片显示两行。
- 当图片承载含义时，请提供 `ImageAlt`；没有它时，图片对辅助技术而言是装饰性的。
- 按消息的去向为字段命名（`Label`，"Message #trail-club"），并将其复用为占位文字。

### 最佳实践

- 在你的服务器上获取预览，使用较短的超时，并返回 null，而不是空的预览。
- 在返回预览之前先解码图片，这样卡片就永远不会以空白画面打开。
- 让人们可以移除不想要的预览；移除按钮也会把链接从消息中移除。
- 只在营销页面和演示中使用 `AutoPlay`；在真实的消息输入框中请将其关闭（它只在存在示例时才起作用）。

### 常见问题

**文字会保留地址吗？** 会。`Text` 和发送的消息完全按粘贴或输入时的样子保存地址；链接只是它的绘制方式。

**什么算作地址？** 以 `http://`、`https://` 或 `www.` 开头，且主机名包含一个点、顶级域名至少有两个字母的文字。`https://x` 和 `localhost:3000` 仍保持为文字。

**可以在代码中打开卡片吗？** 使用 `ExpandPreview`、`CollapsePreview`、`TogglePreview`、`RemoveLink` 和 `Retry`，并传入`Links` 中某个链接的 `Id`；`Paste` 会在光标处添加一个链接，`Send` 则发送消息。

## 无障碍

- 消息是一个多行文本字段，由 `Label` 命名，由 `LinkUnfurlLabels.KeyHint` 描述，后者列出了它的按键。它的状态按名称列出各个链接：加载中时为地址加 "preview on its way"，解析完成后为 "Link to site: title"。
- 链接是一个整体：光标会跳过它，在其旁边按一次 Backspace 或 Delete 即可将其整个移除。
- 每张卡片都有一个带名称的收起按钮和一个带名称的移除按钮，其标题是一个打开该地址的真实链接。收起的卡片被隐藏，并移出 Tab 顺序；当卡片收起时，位于卡片内的键盘焦点会回到消息。
- 礼貌级别的实时区域会播报链接的添加、卡片的打开、收起与移除、缺失的预览以及已发送的消息。发送错误会以强制级别的警告出现在消息输入框下方。
- 加载状态通过扫光、柔和的文字和代替网站图标的地球图标来呈现，并且会被播报：从不只依赖颜色。
- 键盘焦点显示 2px 的焦点环，并在按钮上显示柔和的填充；指针焦点不显示任何内容。

### 键盘

| 按键 | 操作 |
|---|---|
| Enter | 发送消息 |
| Shift+Enter | 开始新的一行 |
| Alt+Enter | 打开或收起光标之前最近的链接的卡片 |
| Backspace / Delete | 在链接旁边时，移除整个链接 |
| 地址后的 Space | 将地址变成链接 |
| Tab | 从消息依次移到每张打开的卡片的收起按钮、移除按钮和标题，然后移到示例和发送按钮 |

## 动效

- 一个弹簧进度驱动一张卡片：卡片被剪裁为其链接的精确矩形，两个网站图标对齐，并移动到链接上；随着弹簧运行，剪裁区域先变宽、后变深（宽度遵循1 − (1 − p)^1.6，高度遵循 p^1.35），圆角半径从 13 增大到 18，卡片下方的底板只在运动中途借助阴影抬起。主体在页眉之后淡入，图片则从轻微放大的状态落定。打开时使用一个略微过阻尼的弹簧，约一秒后稳定；收起时沿同一路径反向运行，使用一个更快的弹簧。
- 卡片栏按同一进度随卡片一起增高，因此工具栏会平滑滑动，而不是跳动。
- 预览到达时，链接的宽度在 340 ms 内平滑变化以适应标题，同时标题向上滚入，网站图标弹出。
- 被移除的链接会在其卡片收起到它里面之后淡出并缩小消失。
- 发送时内容向上移走（180 ms），消息输入框平滑变化到新的高度（480 ms），空的输入区域随后淡入回来。
- `Speed` 缩放形变动画和模拟的获取过程。减少动效与 `IsPaused` 会立即打开和收起卡片，并让加载色调保持静止。当消息输入框离开可视树时，卡片会立即落定。

## 响应式

- `LinkUnfurl` 按自身宽度变化，最宽 576 px：低于 560 px（`:compact`）时，编辑区、预览区和工具栏的内边距变小；低于 360 px（`:tight`）时隐藏示例链接前的提示文字。
- 预览卡最宽 440 px，随输入框一起缩小；过长的标题和描述以省略号结尾。
- 卡片上的按钮是 30 px 的圆形，但点击区域为 44 px，触控时也容易点中。拖动卡片即可把它折回，也可以用卡片的折叠和移除按钮；没有功能依赖悬停。
