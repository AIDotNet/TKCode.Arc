## 何时使用

`TextReveal` 是标题或短段落，出现在屏幕上时播放一次入场动效。每个词从自己的裁剪区中升起，同时逐渐清晰、淡入，因此人看到的第一句话是以确定的节奏落定的句子。它应放在屏幕顶部，此时读者的注意力在标题上，还没有转到控件。

- **设置页的欢迎标题**：“用 3 步完成账单设置。”放在账单开通流程的顶部。标题在页面打开时播放一次，下方的表单从第一帧起就可以使用。
- **定价页或产品页的首屏区域**：发票产品落地页上的大标题，其下的一段简短文字逐词呈现。
- **更新日志顶部的发布公告**：标题说明本次发布了什么，换行经过刻意安排，使文案在任何宽度下都成立。
- **工作区首页的问候语**：“早上好，Priya”之类的标题，仪表板打开时播放，之后在下方表格中工作时保持不动。

## 何时不用

- **需要随滚动呈现的分节标题，位于页面更靠下的位置**：用 `InViewTitle`。挂载在首屏以下的 `TextReveal` 会等到可见时才播放，但它只播放一次，并且是为屏幕顶部设计的。
- **持续进行的状态文字，例如“正在生成账单摘要”**：用 `TextShimmer`。它在工作进行时循环播放，而 `TextReveal` 播放一次后就停住。
- **长正文**：用普通的 `TextBlock`。逐词效果只适用于标题和短段落，长段落会让读者一直等待每个词。
- **会切换状态的标签，例如从“草稿”变为“已发送”**：用 `TextMorph`。修改 `TextReveal` 的 `Text` 会重新播放整个入场动效，对于一个状态词来说动效过多。
- **必须立即读到的警告或错误**：用 `Alert`。逐词呈现的标题会延迟人需要马上知道的信息。

## 用法

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AIDotNet/TKCode.Arc">
    <arc:TextReveal Text="从第一帧起就显得周到的界面"
                    Level="H1" />
</UserControl>
```

`TextReveal` 派生自 Avalonia 的 `Control`，整段文字由它自己绘制。它不会为每个词创建子控件，因此一个二十个词的标题是一个控件，内部包含二十个裁剪后的词。它按行测量尺寸，因此可以像任何文字一样放进 `StackPanel` 或 `Grid`。它以自身的文字命名，标题级别会在大纲中设定标题角色。

控件只播放一次入场效果。文本中的 `\n` 会刻意换行；各行经过平衡处理，且宽度不超过 24 个字符。

### 结构

1. **标题或段落**（`Text`）：逐行绘制的词。文本中的 `\n` 会强制换行。
2. **级别**（`Level`）：`H1`、`H2`、`H3` 或 `Paragraph`。级别决定字号、字体与行高：`H1` 使用 4XL 展示字号，`H2` 使用 3XL，`H3` 使用 2XL，均为展示字体、中等字重。`Paragraph` 使用大号正文字号、正文字体与常规字重。
3. **行框**（`Leading`）：标题为字号的 1.1 倍，段落为 1.4 倍，取自主题。
4. **测量宽度**（`MaxWidthInChars`）：文字最宽为 24 个 "0" 字形宽度。各行经过平衡，因此较长的标题会分成长度相近的几行，而不是一行很长、一行很短。
5. **词裁剪**：每个词在到达的过程中，从底边柔和的裁剪区中升起。入场结束后，词以普通文字绘制，因此不会残留遮罩。

### 标题级别与段落

`Level` 设置标题级别（`H1`、`H2`、`H3`）或 `Paragraph`。标题使用展示字体与更紧的行距；段落使用正文字体、常规字重与更柔和的模糊。级别还会为标题设置 `AutomationProperties.HeadingLevel`：`H1` 设为 1，`H2` 设为 2，`H3` 设为 3。段落不设置标题级别。

### 换行与宽度

`\n` 位于 `Text` 中会强制换行，强制换行在任何宽度下都保留。各行在宽度限制内取得平衡，因此带换行的标题在宽屏上读起来是两行长度相近的文字，在窄屏上也能放得下。

`MaxWidthInChars` 以 "0" 字形宽度为单位设置宽度上限。主题默认为 24，使标题保持在舒适的行长附近。设为 `0` 可取消限制，让标题使用父级的全部宽度。段落应保留上限，因为在 1440 px 宽的屏幕上铺满全宽的段落很难阅读。

```xml
<arc:TextReveal Text="在月结当天开出发票"
                Level="H2"
                MaxWidthInChars="30" />
```

### 延迟与错落

`Delay` 会在第一个词升起前等待。之后的错落间隔保持在半秒以内，因此长文字不会拉长入场时间。每个词在前一个词之后开始，强制换行会再增加一步，因此第二行会在第一行开始之后才开始。

较短的延迟可以让相关控件先稳定下来，例如位于标题上方的 logo 或表单。延迟应保持在半秒以内；更长的等待会让页面显得迟缓。

```xml
<arc:TextReveal Text="欢迎回来" Level="H2" Delay="0:0:0.4" />
```

### 重播

`Replay()` 会再次播放入场效果，可在代码中调用，例如在按钮点击时。若控件未挂载到窗口，它什么也不做。运行入场效果期间 `IsRevealing` 为 `true`，适合在入场结束后再显示其下方的内容。

```csharp
var hero = new TextReveal { Text = "从第一帧起就显得周到的界面", Level = TextLevel.H1 };
var replay = new Button { Content = "重播", Variant = ButtonVariant.Secondary };
replay.Click += (_, _) => hero.Replay();
```

在屏幕上的控件中修改 `Text` 会重新播放入场效果，因此变化是可见的。修改 `Level` 不会重播，新字号立即生效。

### 首次布局前的入场

挂载在首屏以下的控件会先保持隐藏，直到第一次进入可视区域。挂载时已在屏幕上的控件则从第一帧开始播放。运行入场效果期间 `IsRevealing` 为 `true`。

### 字距、行距与模糊

`Tracking` 以 em 为单位设置字间距，`Leading` 以字号的倍数设置行高，`BlurRadius` 设置每个词的起始模糊半径。级别主题已设定这些值；只有标题需要不同的节奏时才覆盖它们。

```xml
<arc:TextReveal Text="默认保持安静" Level="H2" Tracking="-0.02" Leading="1.2" />
```

### 由数据驱动

文字可以来自视图模型。绑定 `Text`，级别保留在 XAML 中。由于文字变化会重播入场效果，应只在页面状态变化时修改该属性，例如用户选择了另一个工作区时。

```csharp
public partial class WelcomeViewModel : ObservableObject
{
    [ObservableProperty]
    private string _greeting = "早上好，Priya";
}
```

```xml
<arc:TextReveal Text="{Binding Greeting}" Level="H2" />
```

### 克制地使用动效

入场效果在每个屏幕上只起一次作用：它告诉读者页面从哪里开始，并给人平静的第一印象。以下情况会分散注意力：一个屏幕上有好几个各自播放的标题，标题紧挨着需要人快速填写的表单，或者文字经常变化。这些屏幕只在顶部使用一个 `TextReveal`，其下使用普通文字。

减弱动效会保留词的顺序，去掉上升与裁剪，词只会快速淡入。动效级别设为 `Off` 时，最终文字立即显示。可以在窗口或容器上用 `arc:ArcMotion.Level` 设置级别，控件会继承该设置。

### 示例：账单产品的设置页

账单产品的设置页以一个标题开始，标题写明三个步骤，段落说明需要多长时间。标题是该屏幕上唯一的 `TextReveal`，因此入场效果标志着流程的开始。段落使用 `Paragraph` 级别，读起来像正文，其较柔和的模糊让它保持平静。按钮是操作，位于段落之下，正是读者视线读完段落后停留的位置。

### 文案规范

标题应以句子式大小写陈述结果，末尾不加句号或感叹号。将它控制在十个词左右，以保持两行的平衡。标题下方的段落说明人接下来要做什么，以及需要多长时间。数字用阿拉伯数字书写，包括标题中的步骤数（“3 步”）。

| 不要写 | 改为 |
|---|---|
| 欢迎来到超棒的账单设置！ | 用 3 步完成账单设置。 |
| 点击这里开始！ | “开始设置”（写在按钮上） |
| 我们革命性的平台让开票轻而易举。 | 今天就发出第一张发票。 |
| 我们非常高兴你能来到这里。 | 早上好，Priya |
| 第 1 步，共 3 步：连接银行账户 | 连接银行账户 |

### 最佳实践

**推荐**

- 每个屏幕顶部只用一个 `TextReveal`。入场效果告诉读者屏幕从哪里开始，第二个会与之争夺注意力。
- 保持文字简短，使标题在一秒左右稳定下来，读者可以开始阅读下方的内容。
- 在文案需要的地方用 `\n` 换行，并在 360 px 宽的屏幕上检查换行效果。
- 级别与大纲保持一致：屏幕标题用 `H1` 或 `H2`，其下的引导文字用 `Paragraph`。
- 把读者需要的控件放在标题下方，让动效引向操作。

**避免**

- 为正文或长段落加入动效。逐词的节奏读长文很慢，读者要等待每个词。
- 每次更新都修改 `Text`，例如计数器或时钟。每次修改都会重播入场效果，标题永远无法稳定。
- 将效果用于状态或警告。需要人立即处理的消息应立即可见。
- 设置过长的延迟。`Delay` 超过半秒会让页面显得停滞，而不是周到。
- 期望屏幕阅读器会播报变化。控件本身不播报其文字，因此当变化必须被读到时，请在父元素上使用实时区域。

### 常见问题

**为什么标题没有动画就直接出现？** 动效级别为 `Off`，或文字为空。在 `Off` 下最终文字立即显示；空的 `Text` 没有可呈现的词。

**为什么标题要等我滚动到它才出现？** 控件挂载在首屏以下。它会等到第一次进入可视区域才播放。如果希望页面打开时就播放，请把它移到屏幕顶部。

**返回该页面时，标题会再播放一次吗？** 会，前提是控件从可视树中移除后又重新挂载：每次挂载都会重新开始入场检查。一直留在树中的控件只播放一次。若不移除控件也想再播放，请调用 `Replay()`。

**能否播放入场效果并等它结束后再显示按钮？** 检查 `IsRevealing`。入场期间它为 `true`，结束后为 `false`。在 `Reduced` 与 `Off` 下入场会立即或很快结束，因此三种级别下按钮都可以用同一个检查来等待。

**如何把标题拆成指定的行？** 在 `Text` 中使用 `\n`。每段之间的文字会相互平衡，强制换行在任何宽度下都保留。请确认每一段在屏幕支持的最窄宽度下都能放得下。

## 无障碍

- 标题以完整文字作为名称，并将 `HeadingLevel` 设为 1 至 3。段落是纯文字。
- 强制换行会被读作空格。
- 控件本身不播报其变化。若文字必须被播报，请在父元素上使用实时区域。
- 控件不可获得焦点，也没有键盘交互，因此不会在页面上增加 Tab 停靠点。
- 请根据页面大纲选择级别，而不是根据想要的字号。

## 动效

- 每个词从各自的裁剪区中升起，同时从柔和的模糊中逐渐清晰。词按顺序开始。
- 整个入场效果在控件出现于屏幕上时播放一次。只有调用 `Replay()`，或在控件位于屏幕上时修改 `Text`，才会重播。
- 减弱动效保留词的顺序，但去掉上升与裁剪；词快速淡入。
- 关闭动效时立即显示最终文字。

| 变化 | 完整 | 减弱 | 关闭 |
|---|---|---|---|
| 控件出现在屏幕上 | 词逐个上升 0.62em，逐渐清晰并淡入 | 词按顺序快速淡入 | 立即显示最终文字 |
| 控件挂载在首屏以下 | 先保持隐藏，进入视口后播放 | 先等待，然后快速淡入 | 立即显示最终文字 |
| 屏幕上的 `Text` 变化 | 重新播放入场效果 | 重新播放快速淡入 | 立即显示最终文字 |
| `Replay()` | 重新播放入场效果 | 重新播放快速淡入 | 立即显示最终文字 |
| `Level` 或 `Delay` 变化 | 不重播；新字号或延迟作用于下一次入场 | 不重播 | 不重播 |

## 相关组件

- `InViewTitle`：随滚动进入视口时呈现的分节标题。
- `TextShimmer`：表示持续工作的状态行。
- `TextMorph`：简短标签逐字母切换状态。

| 组件 | 适用场景 |
|---|---|
| `InViewTitle` | 分节标题随读者滚动到它时呈现 |
| `TextShimmer` | 状态行显示仍在进行的工作 |
| `TextMorph` | 短标签切换状态，字母应移动到新文字的位置 |
| `Alert` | 警告或消息必须立即被读到 |
| `Card` | 标题位于一张卡片上，卡片自身承载内容 |
