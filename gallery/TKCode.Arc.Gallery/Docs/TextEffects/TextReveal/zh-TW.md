## 何時使用

`TextReveal` 是標題或短段落，出現在螢幕上時播放一次進場動態效果。每個詞從自己的裁剪區中升起，同時逐漸清晰、淡入，因此使用者看到的第一句話是以確定的節奏落定的句子。它應放在螢幕頂部，此時讀者的注意力在標題上，還沒有轉到控制項。

- **設定頁的歡迎標題**：「用 3 步完成帳單設定。」放在帳單開通流程的頂部。標題在頁面開啟時播放一次，下方的表單從第一個畫格起就可以使用。
- **定價頁或產品頁的首屏區域**：發票產品落地頁上的大標題，其下的一段簡短文字逐詞呈現。
- **更新日誌頂部的發布公告**：標題說明本次發布了什麼，換行經過刻意安排，使文案在任何寬度下都成立。
- **工作區首頁的問候語**：「早安，Priya」之類的標題，儀表板開啟時播放，之後在下方表格中工作時保持不動。

## 何時不用

- **需要隨捲動呈現的分節標題，位於頁面更下方的位置**：用 `InViewTitle`。掛載在首屏以下的 `TextReveal` 會等到可見時才播放，但它只播放一次，並且是為螢幕頂部設計的。
- **持續進行的狀態文字，例如「正在產生帳單摘要」**：用 `TextShimmer`。它在工作進行時循環播放，而 `TextReveal` 播放一次後就停住。
- **長篇內文**：用一般的 `TextBlock`。逐詞效果只適用於標題和短段落，長段落會讓讀者一直等待每個詞。
- **會切換狀態的標籤，例如從「草稿」變為「已寄出」**：用 `TextMorph`。修改 `TextReveal` 的 `Text` 會重新播放整個進場動態效果，對於一個狀態詞來說動態效果過多。
- **必須立即讀到的警告或錯誤**：用 `Alert`。逐詞呈現的標題會延遲使用者需要馬上知道的訊息。

## 用法

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:arc="https://github.com/AtomUICommunity/TKCode.Arc">
    <arc:TextReveal Text="從第一個畫格起就顯得周到的介面"
                    Level="H1" />
</UserControl>
```

`TextReveal` 衍生自 Avalonia 的 `Control`，整段文字由它自己繪製。它不會為每個詞建立子控制項，因此一個二十個詞的標題是一個控制項，內部包含二十個裁剪後的詞。它依行測量尺寸，因此可以像任何文字一樣放進 `StackPanel` 或 `Grid`。它以自身的文字命名，標題層級會在大綱中設定標題角色。

控制項只播放一次進場效果。文字中的 `\n` 會刻意換行；各行經過平衡處理，且寬度不超過 24 個字元。

### 結構

1. **標題或段落**（`Text`）：逐行繪製的詞。文字中的 `\n` 會強制換行。
2. **層級**（`Level`）：`H1`、`H2`、`H3` 或 `Paragraph`。層級決定字級、字型與行高：`H1` 使用 4XL 展示字級，`H2` 使用 3XL，`H3` 使用 2XL，均為展示字型、中等字重。`Paragraph` 使用大號內文字級、內文字型與一般字重。
3. **行框**（`Leading`）：標題為字級的 1.1 倍，段落為 1.4 倍，取自主題。
4. **測量寬度**（`MaxWidthInChars`）：文字最寬為 24 個 "0" 字形寬度。各行經過平衡，因此較長的標題會分成長度相近的幾行，而不是一行很長、一行很短。
5. **詞裁剪**：每個詞在抵達的過程中，從底邊柔和的裁剪區中升起。進場結束後，詞以一般文字繪製，因此不會殘留遮罩。

### 標題層級與段落

`Level` 設定標題層級（`H1`、`H2`、`H3`）或 `Paragraph`。標題使用展示字型與更緊的行距；段落使用內文字型、一般字重與更柔和的模糊。層級還會為標題設定 `AutomationProperties.HeadingLevel`：`H1` 設為 1，`H2` 設為 2，`H3` 設為 3。段落不設定標題層級。

### 換行與寬度

`\n` 位於 `Text` 中會強制換行，強制換行在任何寬度下都會保留。各行在寬度限制內取得平衡，因此帶換行的標題在寬螢幕上讀起來是兩行長度相近的文字，在窄螢幕上也放得下。

`MaxWidthInChars` 以 "0" 字形寬度為單位設定寬度上限。主題預設為 24，使標題保持在舒適的行長附近。設為 `0` 可取消限制，讓標題使用父層的全部寬度。段落應保留上限，因為在 1440 px 寬的螢幕上鋪滿全寬的段落很難閱讀。

```xml
<arc:TextReveal Text="在月結當天開出發票"
                Level="H2"
                MaxWidthInChars="30" />
```

### 延遲與錯落

`Delay` 會在第一個詞升起前等待。之後的錯落間隔維持在半秒以內，因此長文字不會拉長進場時間。每個詞在前一個詞之後開始，強制換行會再增加一步，因此第二行會在第一行開始之後才開始。

較短的延遲可以讓相關控制項先穩定下來，例如位於標題上方的 logo 或表單。延遲應保持在半秒以內；更長的等待會讓頁面顯得遲緩。

```xml
<arc:TextReveal Text="歡迎回來" Level="H2" Delay="0:0:0.4" />
```

### 重播

`Replay()` 會再次播放進場效果，可在程式碼中呼叫，例如在按鈕點按時。若控制項未掛載到視窗，它什麼也不做。執行進場效果期間 `IsRevealing` 為 `true`，適合在進場結束後再顯示其下方的內容。

```csharp
var hero = new TextReveal { Text = "從第一個畫格起就顯得周到的介面", Level = TextLevel.H1 };
var replay = new Button { Content = "重播", Variant = ButtonVariant.Secondary };
replay.Click += (_, _) => hero.Replay();
```

在螢幕上的控制項中修改 `Text` 會重新播放進場效果，因此變化是可見的。修改 `Level` 不會重播，新字級立即生效。

### 首次配置前的進場

掛載在首屏以下的控制項會先保持隱藏，直到第一次進入可視範圍。掛載時已在螢幕上的控制項則從第一個畫格開始播放。執行進場效果期間 `IsRevealing` 為 `true`。

### 字距、行距與模糊

`Tracking` 以 em 為單位設定字元間距，`Leading` 以字級的倍數設定行高，`BlurRadius` 設定每個詞的起始模糊半徑。層級主題已設定這些值；只有標題需要不同的節奏時才覆寫它們。

```xml
<arc:TextReveal Text="預設保持安靜" Level="H2" Tracking="-0.02" Leading="1.2" />
```

### 由資料驅動

文字可以來自檢視模型。繫結 `Text`，層級保留在 XAML 中。由於文字變化會重播進場效果，應只在頁面狀態變化時修改該屬性，例如使用者選擇了另一個工作區時。

```csharp
public partial class WelcomeViewModel : ObservableObject
{
    [ObservableProperty]
    private string _greeting = "早安，Priya";
}
```

```xml
<arc:TextReveal Text="{Binding Greeting}" Level="H2" />
```

### 節制地使用動態效果

進場效果在每個螢幕上只起一次作用：它告訴讀者頁面從哪裡開始，並給人平靜的第一印象。以下情況會分散注意力：一個螢幕上有好幾個各自播放的標題，標題緊挨著需要人快速填寫的表單，或者文字經常變化。這些螢幕只在頂部使用一個 `TextReveal`，其下使用一般文字。

減少動態效果會保留詞的順序，去掉上升與裁剪，詞只會快速淡入。動態效果層級設為 `Off` 時，最終文字立即顯示。可以在視窗或容器上用 `arc:ArcMotion.Level` 設定層級，控制項會繼承該設定。

### 範例：帳單產品的設定頁

帳單產品的設定頁以一個標題開始，標題寫明三個步驟，段落說明需要多長時間。標題是該畫面上唯一的 `TextReveal`，因此進場效果標示流程的開始。段落使用 `Paragraph` 層級，讀起來像正文，其較柔和的模糊讓它保持平靜。按鈕是操作，位於段落之下，正是讀者視線讀完段落後停留的位置。

![帳單設定頁，包含標題、簡短段落與主要按鈕](images/TextRevealSetup.png)

```xml
<StackPanel Width="640" Spacing="16">
    <TextBlock Text="Northwind Billing / Setup"
               FontSize="13"
               FontWeight="SemiBold"
               Foreground="{arc:ArcDesignTokenResource TextSecondary}" />
    <arc:TextReveal Text="Set up billing in 3 steps.&#10;Then send your first invoice."
                    Level="H2" />
    <arc:TextReveal Text="Connect a bank account, confirm your tax details and choose the day invoices are issued. Setup takes about ten minutes."
                    Level="Paragraph"
                    MaxWidthInChars="44" />
    <WrapPanel ItemSpacing="12" LineSpacing="12">
        <arc:Button Content="Start setup" Variant="Primary" />
        <arc:Button Content="Read the guide" Variant="Ghost" />
    </WrapPanel>
</StackPanel>
```

### 文案規範

標題應以句首大寫的方式陳述結果，結尾不加句號或驚嘆號。將它控制在十個詞左右，以維持兩行的平衡。標題下方的段落說明使用者接下來要做什麼，以及需要多長時間。數字用阿拉伯數字書寫，包括標題中的步驟數（「3 步」）。

| 不要寫 | 改為 |
|---|---|
| 歡迎來到超棒的帳單設定！ | 用 3 步完成帳單設定。 |
| 點這裡開始！ | 「開始設定」（寫在按鈕上） |
| 我們革命性的平台讓開立發票輕而易舉。 | 今天就寄出第一張發票。 |
| 我們非常高興你能來到這裡。 | 早安，Priya |
| 第 1 步，共 3 步：連接銀行帳戶 | 連接銀行帳戶 |

### 最佳做法

**建議**

- 每個螢幕頂部只用一個 `TextReveal`。進場效果告訴讀者螢幕從哪裡開始，第二個會與之爭奪注意力。
- 保持文字簡短，使標題在一秒左右穩定下來，讀者可以開始閱讀下方的內容。
- 在文案需要的地方用 `\n` 換行，並在 360 px 寬的螢幕上檢查換行效果。
- 層級與大綱保持一致：螢幕標題用 `H1` 或 `H2`，其下的引導文字用 `Paragraph`。
- 把讀者需要的控制項放在標題下方，讓動態效果引向操作。

**避免**

- 為內文或長段落加入動態效果。逐詞的節奏讀長文很慢，讀者要等待每個詞。
- 每次更新都修改 `Text`，例如計數器或時鐘。每次修改都會重播進場效果，標題永遠無法穩定。
- 將效果用於狀態或警告。需要使用者立即處理的訊息應立即可見。
- 設定過長的延遲。`Delay` 超過半秒會讓頁面顯得停滯，而不是周到。
- 期望螢幕閱讀器會播報變化。控制項本身不播報其文字，因此當變化必須被讀到時，請在父元素上使用即時區域。

### 常見問題

**為什麼標題沒有動畫就直接出現？** 動態效果層級為 `Off`，或文字為空。在 `Off` 下最終文字立即顯示；空的 `Text` 沒有可呈現的詞。

**為什麼標題要等我捲動到它才出現？** 控制項掛載在首屏以下。它會等到第一次進入可視範圍才播放。如果希望頁面開啟時就播放，請把它移到螢幕頂部。

**返回該頁面時，標題會再播放一次嗎？** 會，前提是控制項從視覺樹中移除後又重新掛載：每次掛載都會重新開始進場檢查。一直留在樹中的控制項只播放一次。若不移除控制項也想再播放，請呼叫 `Replay()`。

**能否播放進場效果並等它結束後再顯示按鈕？** 檢查 `IsRevealing`。進場期間它為 `true`，結束後為 `false`。在 `Reduced` 與 `Off` 下進場會立即或很快結束，因此三種層級下按鈕都可以用同一個檢查來等待。

**如何把標題拆成指定的行？** 在 `Text` 中使用 `\n`。每段之間的文字會彼此平衡，強制換行在任何寬度下都會保留。請確認每一段在螢幕支援的最窄寬度下都放得下。

## 無障礙

- 標題以完整文字作為名稱，並將 `HeadingLevel` 設為 1 至 3。段落是純文字。
- 強制換行會被讀作空格。
- 控制項本身不播報其變化。若文字必須被播報，請在父元素上使用即時區域。
- 控制項無法取得焦點，也沒有鍵盤互動，因此不會在頁面上增加 Tab 停留點。
- 請依頁面大綱選擇層級，而不是依想要的字級。

## 動態效果

- 每個詞從各自的裁剪區中升起，同時從柔和的模糊中逐漸清晰。詞依序開始。
- 整個進場效果在控制項出現於螢幕上時播放一次。只有呼叫 `Replay()`，或在控制項位於螢幕上時修改 `Text`，才會重播。
- 減少動態效果會保留詞的順序，但去掉上升與裁剪；詞快速淡入。
- 關閉動態效果時立即顯示最終文字。

| 變化 | 完整 | 減少 | 關閉 |
|---|---|---|---|
| 控制項出現在螢幕上 | 詞逐個上升 0.62em，逐漸清晰並淡入 | 詞依序快速淡入 | 立即顯示最終文字 |
| 控制項掛載在首屏以下 | 先保持隱藏，進入可視範圍後播放 | 先等待，然後快速淡入 | 立即顯示最終文字 |
| 螢幕上的 `Text` 變化 | 重新播放進場效果 | 重新播放快速淡入 | 立即顯示最終文字 |
| `Replay()` | 重新播放進場效果 | 重新播放快速淡入 | 立即顯示最終文字 |
| `Level` 或 `Delay` 變化 | 不重播；新字級或延遲作用於下一次進場 | 不重播 | 不重播 |

## 相關元件

- `InViewTitle`：隨捲動進入可視範圍時呈現的分節標題。
- `TextShimmer`：表示持續工作的狀態列。
- `TextMorph`：簡短標籤逐字母切換狀態。

| 元件 | 適用情境 |
|---|---|
| `InViewTitle` | 分節標題隨讀者捲動到它時呈現 |
| `TextShimmer` | 狀態列顯示仍在進行的工作 |
| `TextMorph` | 短標籤切換狀態，字母應移動到新文字的位置 |
| `Alert` | 警告或訊息必須立即被讀到 |
| `Card` | 標題位於一張卡片上，卡片本身承載內容 |
